> **이 문서는 작업 중에 쓴다.** 끝나고 쓰는 것이 아니다 ([`../CLAUDE.md`](../CLAUDE.md) 개발 원칙 1).

## 1. 착수 시점의 상태 — **main 이 현실보다 한참 뒤에 있다**

`main` 은 녹색이다(GUT 623/623). 그런데 **진짜 작업의 대부분이 main 에 없다.**

| 레인 | 커밋 | 삽입 | main 에 없는 것 |
| --- | --- | --- | --- |
| `ui-kit-2` | 66 | 28,732 | UI 층 넷 · 노이즈 축 · 인물 상세 · 원형 스쿼드 |
| `combat` | 31 | 15,127 | 전투 · 백팩 격자 · 자세 쌍 · 체이닝 |
| `char-anim` | 34 | 14,045 | **레이맨 절차 애니메이션 전부** (파츠 여섯 · 클립 아홉) |
| `sound` | 8 | 10,107 | 효과음 65개 · 사건 배치 층 |
| `npc-relations` | 19 | 9,017 | 사건 15종 · 유명세 · 사회적 거리 |
| `portraits` | 19 | 7,895 | 초상 파이프라인 |
| `dungeon-gen` | 31 | 6,588 | 구역 · 등급 · 민첩 절벽 |
| `lighting-2d` | 23 | 6,187 | 2D 조명 조사 · 노멀 굽기 |
| `hideout` | 9 | 5,482 | 아지트 아이소 격자 · 배회 |
| **합** | **240** | **~103k** | |

**아홉 레인 전부 main 과 단독으로는 깨끗하게 붙는다.** `git merge-tree` 로 확인했다.

### 1.1 그런데 순서대로 붙이면 깨진다 — 실제로 깨졌다

시험 워크트리에서 아홉을 차례로 붙여 봤다. **git 이 보는 충돌은 사소했고,
git 이 못 보는 충돌이 진짜였다.**

| 종류 | 내용 | git 이 보나 |
| --- | --- | --- |
| 파일 충돌 | `docs/HANDOFF.md` (레인마다 자기 인계서를 같은 이름으로 썼다) · `tools/make_gif.py` | ✅ 본다 |
| **의미 충돌 ①** | `PersonSheet.build()` 의 **여섯째 인자를 두 레인이 각각 다른 것으로 채웠다** — `npc-relations` 는 `RelationLedger`, `ui-kit-2` 는 `PersonNorms` | ❌ **못 본다** |
| **의미 충돌 ②** | `NpcWorld` 인구 생성에서 **SIGSEGV** (`person_seed.gd:57`) | ❌ **못 본다** |

> **이것이 `CLAUDE.md` 「통합은 넘기지 않는다」가 가리키는 자리다.**
> 두 레인이 같은 함수의 **같은 자리**에 서로 다른 인자를 밀어 넣었는데,
> 두 diff 가 겹치지 않아 git 은 깨끗하다고 답했다. **테스트만이 잡았다.**

## 2. 무엇을 먼저 하는가 — **헤드라인 기능의 전제부터**

사용자가 지정한 헤드라인은 **레이맨 절차 애니메이션에 물리와 모핑을 얹는 것**이다.
그 코드는 `char-anim` 에만 있다. 그래서 순서가 정해진다.

```
① char-anim 만 먼저 main 에 접는다  (신규 파일뿐 · 삭제 0줄 · 단독 병합 깨끗)
        ↓
② 물리·모핑 레인을 새 main 에서 띄운다   ← 여기서 대화권이 돌아온다
        ↓
③ 그 사이에 통합자가 나머지 여덟을 접는다 (의미 충돌 둘을 손으로 해소)
        ↓
④ 연출·내러티브 레인 · 최종 검증
```

`char_anim` 파일들은 **다른 어느 레인도 안 건드린다.** 그래서 ③ 이 ② 를 밀어내지 않고,
② 는 나중에 `git merge main` 한 번으로 따라잡는다 (`CLAUDE.md` 「워크트리는 나중 커밋을 못 본다」).

## 3. 헤드라인 — 물리와 모핑을 **어떻게** 얹는가

명세 본문은 [`design/31-soft-body.md`](design/31-soft-body.md) 에 쓴다. 여기에는 **왜 그 길인가**만 남긴다.

### 3.1 정면으로 부딪히는 것 — **물리는 상태를 갖고, 이 구조는 상태가 없다**

[`design/25-character-animation.md`](design/25-character-animation.md) §25.3 이 이 레인의 뼈대다.

> 궤도가 시각의 함수이면, 지연 = `orbit(t − d)` 그것뿐이다.
> `func sample(t: float, f: AnimFeatures) -> CharPose` — **순수 함수다.**
> 노드도, 이전 프레임도, 난수도 안 본다.

그 대가로 얻은 것이 셋이다 — 링 버퍼 없음 · **프레임률이 튀어도 지연이 안 변함**(웹에서 중요) ·
**GIF 캡처가 결정적**. 셋 다 이 프로젝트가 실제로 쓰고 있는 값이다.

**그런데 물리는 정의상 상태다.** `v += a·dt; x += v·dt` 는 이전 프레임을 본다.
스프링을 순진하게 넣으면 위 셋이 **전부** 날아간다.

### 3.2 빠져나가는 길 — **감쇠진동은 해석해가 있다**

스프링-댐퍼는 미분방정식이고, **우리가 쓸 두 경우 모두 닫힌 해가 있다.**

| 구동 | 해 | 쓰는 곳 |
| --- | --- | --- |
| **주기 구동** (idle · walk · run 은 §25.3.2 대로 주기가 정수다) | 정상상태 응답 — 같은 주파수, **진폭과 위상만 이동** | 걸을 때 흔들림 |
| **충격** (타격 · 착지 · 방향 전환) | 충격 응답 — `e^(−ζωt)·sin(ω_d·t)`, **「사건 이후 흐른 시간」의 함수** | 맞을 때 흔들림 |

두 번째는 §25.3 이 이미 쓰고 있는 형태 그대로다 —
> 전부 「사건 이후 흐른 시간」의 함수로 두면 오버슛은 그냥 진폭이 1 을 넘는 감쇠 진동이다.

**즉 물리를 넣는 것이 구조를 깨는 것이 아니라, 이 구조가 처음부터 물리의 형태였다.**
`char_reaction.gd`(§25.27 「맞는 것을 클립이 아니라 힘으로」)가 이미 그 절반이다.
남은 절반은 **구동 응답**과 **그것을 받을 몸**이다.

> **이 판단이 이 레인 전체를 정한다.** 적분기를 넣었으면 §25.3 의 셋을 잃고,
> GIF 이음매가 끊기고, 웹에서 프레임이 튈 때 흔들림이 같이 튀었을 것이다.

### 3.3 모핑 — **두 부위가 서로 다른 답을 요구한다**

§25.1 이 **메시 변형과 `Polygon2D` 가중치를 금지**한다. 관절이 없는 것이 이 스타일이라서다.
그런데 사용자가 요청한 것은 모핑이다. 그래서 부위별로 갈랐다.

| 부위 | 길 | §25.1 을 깨나 |
| --- | --- | --- |
| **머리카락** | **일곱째 파츠로 분리.** 머리의 자식, 제 피벗, 제 지연 | ❌ **안 깬다.** 트랜스폼만 쓴다 |
| **가슴** | 몸통 스프라이트에 **셰이더 UV 워프** (프래그먼트, 방사형 감쇠) | ⚠️ 렌더링에만 갇힌다 — 파츠 여섯은 그대로 트랜스폼 |

**머리카락 분리는 새 결정이 아니다.** §25.1.1 이 이미 후보로 올렸고 보류했다 —

> 떼면 예뻐진다 — 머리보다 더 늦게 따라오는 파츠가 하나 생기니까. 그런데
> **도형 단계에서는 머리와 머리카락의 실루엣이 같아서 지연이 안 보인다.**
> **스프라이트가 들어온 뒤에 판단한다.**

**스프라이트는 왔다** (§25.41.7). 그러니 그 보류의 조건이 풀렸고, 지금이 판정 시점이다.

가슴은 파츠로 뗄 수 없다 — 몸통 실루엣 **안**에 있어서 떼면 원피스가 갈라진다.
그래서 **모핑이 실제로 필요한 유일한 자리**이고, 요청의 「모핑」은 여기에 걸린다.

#### 왜 프래그먼트 셰이더인가 — 버텍스로는 안 된다

`Sprite2D` 는 **사각형 네 점**이다. 버텍스 셰이더로는 네 모서리밖에 못 움직인다 —
국소 부풀림이 원천적으로 안 나온다. 격자를 잘게 나눈 `MeshInstance2D` 로 바꾸면 되지만
파츠 수와 드로우 비용 표(§25.32)를 전부 다시 재야 한다.

**UV 영역을 프래그먼트에서 휘면** 노드가 안 늘고, `gl_compatibility`(WebGL2)에서 그대로 돌고,
§25.32 의 실측표가 안 낡는다.

### 3.4 그래서 배선은 이렇다

```
        AnimFeatures (t)
              │
     ┌────────┴────────┐
     │                 │
  CharPose         SoftBody          ← 둘 다 t 의 순수 함수
  (파츠 6+1)       (해석적 감쇠진동)
     │                 │
     │            MorphState { chest: 오프셋·눌림, hair: 각도·늘어남 }
     │                 │
     ├── 머리카락 ◄────┤   트랜스폼으로 받는다 (파츠)
     │                 │
     └── 몸통 ◄────────┘   셰이더 uniform 으로 받는다 (렌더링)
```

`MorphState` 가 **순수 자료**라서 셰이더 없이 단위 테스트가 된다 —
§25.13.1 「그림과 자가 다른 것을 본다」가 이 저장소에서 네 번 났다. 그 다섯 번째를 막는 자리다.

### 3.5 미리 박아 두는 판단 — 레인이 물어볼 수 없으므로

`CLAUDE.md` 「브리핑에 반드시 넣을 것」 7번. 갈릴 자리를 비워 두면 추측이 들어온다.

| 물음 | 답 | 근거 |
| --- | --- | --- |
| 흔들림의 세기 | **작게.** 정지 시 최대 변위는 해당 파츠 반크기의 **12 % 이하** | §25.29 「과장은 각도로, 거리로 하면 몸이 분해된다」 |
| 켜고 끄기 | **인물마다 자료값.** 0 이면 완전히 꺼진다(= 지금 화면과 동일) | §25.40 인물이 여럿이다 |
| 웹 예산 | 셰이더 **한 벌**, 파츠 **하나만** 증가. §25.31.3 의 웹 표를 다시 재지 않아도 되는 선 | §25.32.3 |
| 좌표계 | 코어는 `+y` 가 위. 변환은 `CharPose.canvas_transform()` **한 곳만** | §25.2.1 |
| 미학 | 흔들림이 **동작을 읽는 데 방해가 되면 진 것이다.** 실루엣 자(§25.22)가 판정한다 | §25.22 |

## 4. 검증 — 이번 통합에서 특별히 볼 것

평소 4줄에 **둘을 더한다.**

```bash
godot --headless --path . --import                          # 임포트 오류 없음
godot --headless --path . --quit-after 60                   # 런타임 오류 없음
godot --headless --path . -s res://addons/gut/gut_cmdln.gd  # 테스트 통과
gdlint src test && gdformat --check src test                # 컨벤션 통과
```

| 더 보는 것 | 왜 |
| --- | --- |
| **테스트 수가 623 에서 얼마나 늘었나** | 레인의 테스트가 조용히 안 실린 것을 잡는다. §25.13.6 「통과가 안 돌았다를 뜻한다」 |
| **`gut` 이 SIGSEGV 없이 끝까지 갔나** | 의미 충돌 ② 가 여기서만 드러났다. 「통과」줄만 보면 못 본다 |
