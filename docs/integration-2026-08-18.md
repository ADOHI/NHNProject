## 1. 착수 시점의 상태 — **main 이 현실보다 한참 뒤에 있다**

`main` 은 녹색이다(GUT 623/623). 그런데 **진짜 작업의 대부분이 main 에 없다.**

| 레인 | 커밋 | 삽입 | main 에 없는 것 |
| --- | --- | --- | --- |
| `ui-kit-2` | 66 | 28,732 | UI 층 넷 · 노이즈 축 · 인물 상세 · 원형 스쿼드 |
| `combat` | 31 | 15,127 | 전투 · 백팩 격자 · 자세 쌍 · 체이닝 |
| `char-anim` | 34 | 14,045 | **레이맨 절차 애니메이션 전부** (파츠 여섯 · 클립 아홉) |
| `sound` | 8 | 10,107 | 효과음 65개 · 사건 배치 층 |
| `npc-relations` | 19 | 9,017 | 사건 15종 · 유명세 · 사회적 거리 |
| `portraits` | 19 | 7,895 | 초상 파이프라인 |
| `dungeon-gen` | 31 | 6,588 | 구역 · 등급 · 민첩 절벽 |
| `lighting-2d` | 23 | 6,187 | 2D 조명 조사 · 노멀 굽기 |
| `hideout` | 9 | 5,482 | 아지트 아이소 격자 · 배회 |
| **합** | **240** | **~103k** | |

**아홉 레인 전부 main 과 단독으로는 깨끗하게 붙는다.** `git merge-tree` 로 확인했다.

### 1.1 그런데 순서대로 붙이면 깨진다 — 실제로 깨졌다

시험 워크트리에서 아홉을 차례로 붙여 봤다. **git 이 보는 충돌은 사소했고,
git 이 못 보는 충돌이 진짜였다.**

| 종류 | 내용 | git 이 보나 |
| --- | --- | --- |
| 파일 충돌 | `docs/HANDOFF.md` (레인마다 자기 인계서를 같은 이름으로 썼다) · `tools/make_gif.py` | ✅ 본다 |
| **의미 충돌 ①** | `PersonSheet.build()` 의 **여섯째 인자를 두 레인이 각각 다른 것으로 채웠다** — `npc-relations` 는 `RelationLedger`, `ui-kit-2` 는 `PersonNorms` | ❌ **못 본다** |
| ~~의미 충돌 ②~~ | ~~`NpcWorld` 인구 생성에서 SIGSEGV~~ → **통합 문제가 아니었다. §1.2 를 보라** | — |

> **이것이 `CLAUDE.md` 「통합은 넘기지 않는다」가 가리키는 자리다.**
> 두 레인이 같은 함수의 **같은 자리**에 서로 다른 인자를 밀어 넣었는데,
> 두 diff 가 겹치지 않아 git 은 깨끗하다고 답했다. **테스트만이 잡았다.**

### 1.2 ★ 「의미 충돌 ②」는 우리 코드가 아니었다 — **기계가 무작위로 죽는다**

SIGSEGV 를 통합 사고로 적었다가 **틀린 것을 확인했다.** 자국을 남긴다.

**이상하다고 느낀 지점:** 죽는 자리가 매번 달랐다 — `person_seed.gd:57` · `base_screen.gd:65` ·
`front_idle_clip.gd:74` · `dungeon_blueprint.gd`. 넷 다 **평범한 산술과 대입**이고
단정 실패는 한 건도 없었다. 그리고 **같은 명령이 어떤 때는 811/811 로 통과했다.**

그래서 코드가 아니라 기계를 쟀다.

| 잰 것 | 결과 |
| --- | --- |
| `gdformat`(Godot 과 무관한 **Python** 프로세스)도 죽나 | **죽는다.** 같은 파일 · 같은 명령 12회 중 2회 |
| 셸 탓인가 (MSYS 계층) | **아니다.** Git Bash 2/12 · PowerShell 2/12 — 같다 |
| 종료 코드 | **`0xC0000005`** (ACCESS_VIOLATION). Bash 에는 139 로 보인다 |
| 메모리 압박인가 | **아니다.** 여유 RAM 14.3 / 31.6 GB · VRAM 848 / 16376 MiB · ComfyUI 안 떠 있음 |
| CPU 가 뭐라 하나 | **`WHEA-Logger` 19 (2026-08-15)** — *"Corrected Machine Check. Error Type: **Translation Lookaside Buffer Error**. Reported by component: **Processor Core**"* |
| 커널은 | **최근 3주 버그체크 5회** — `0x1E`(첫 인자 `0xC0000005`) · `0x50` ×3 · `0x3B`(첫 인자 `0xC0000005`). 전부 메모리 오염 계열 |
| 기계 | **13th Gen Intel Core i9-13900H** · RAM 은 삼성 DDR5-4800 정격(오버클럭 아님) |

**서로 무관한 두 런타임(네이티브 C++ · Python)이 같은 예외 코드로 무작위로 죽고,
CPU 자신이 정정된 기계 검사 오류를 보고했다.** GDScript 버그로는 설명이 안 된다.

> #### 이 발견이 `CLAUDE.md` 의 한 줄을 뒤집는다
>
> `CLAUDE.md` 「GPU 를 나눠 쓴다」는 2026-08-07 세션이 끊긴 원인을 **VRAM 고갈**로 적었다.
> **이번엔 VRAM 이 깨끗한데 같은 증상이 난다.** 그때 표에 적힌 것도
> *"서로 무관한 프로세스가 서로 다른 모듈에서 전부 `0xc0000005` 로 죽었다"* 였다 —
> **지금과 같은 증상이고, 그때는 마침 VRAM 이 차 있어서 그것을 원인으로 읽은 것이다.**
> 상관을 인과로 읽었다.
>
> **이미지 모델을 하나만 올리는 규칙 자체는 남긴다** — 그건 그것대로 옳다.
> 바꾸는 것은 **원인 설명**뿐이다.

**그래서 무엇이 달라지나.** 이 저장소의 검증 규칙은 「테스트가 통과하면 좋다」에 기대는데,
**실패의 일부가 기계다.** 실패를 볼 때마다 코드를 의심하면 없는 버그를 쫓는다.
증거와 처방은 `test-stability` 레인이 [`test-stability.md`](test-stability.md) 에 쌓는다.

## 2. 무엇을 먼저 하는가 — **헤드라인 기능의 전제부터**

사용자가 지정한 헤드라인은 **레이맨 절차 애니메이션에 물리와 모핑을 얹는 것**이다.
그 코드는 `char-anim` 에만 있다. 그래서 순서가 정해진다.

```
① char-anim 만 먼저 main 에 접는다  (신규 파일뿐 · 삭제 0줄 · 단독 병합 깨끗)
        ↓
② 물리·모핑 레인을 새 main 에서 띄운다   ← 여기서 대화권이 돌아온다
        ↓
③ 그 사이에 통합자가 나머지 여덟을 접는다 (의미 충돌 둘을 손으로 해소)
        ↓
④ 연출·내러티브 레인 · 최종 검증
```

`char_anim` 파일들은 **다른 어느 레인도 안 건드린다.** 그래서 ③ 이 ② 를 밀어내지 않고,
② 는 나중에 `git merge main` 한 번으로 따라잡는다 (`CLAUDE.md` 「워크트리는 나중 커밋을 못 본다」).

## 3. 헤드라인 — 물리와 모핑을 **어떻게** 얹는가

명세 본문은 [`design/31-soft-body.md`](design/31-soft-body.md) 에 쓴다. 여기에는 **왜 그 길인가**만 남긴다.

### 3.1 정면으로 부딪히는 것 — **물리는 상태를 갖고, 이 구조는 상태가 없다**

[`design/25-character-animation.md`](design/25-character-animation.md) §25.3 이 이 레인의 뼈대다.

> 궤도가 시각의 함수이면, 지연 = `orbit(t − d)` 그것뿐이다.
> `func sample(t: float, f: AnimFeatures) -> CharPose` — **순수 함수다.**
> 노드도, 이전 프레임도, 난수도 안 본다.

그 대가로 얻은 것이 셋이다 — 링 버퍼 없음 · **프레임률이 튀어도 지연이 안 변함**(웹에서 중요) ·
**GIF 캡처가 결정적**. 셋 다 이 프로젝트가 실제로 쓰고 있는 값이다.

**그런데 물리는 정의상 상태다.** `v += a·dt; x += v·dt` 는 이전 프레임을 본다.
스프링을 순진하게 넣으면 위 셋이 **전부** 날아간다.

### 3.2 빠져나가는 길 — **감쇠진동은 해석해가 있다**

스프링-댐퍼는 미분방정식이고, **우리가 쓸 두 경우 모두 닫힌 해가 있다.**

| 구동 | 해 | 쓰는 곳 |
| --- | --- | --- |
| **주기 구동** (idle · walk · run 은 §25.3.2 대로 주기가 정수다) | 정상상태 응답 — 같은 주파수, **진폭과 위상만 이동** | 걸을 때 흔들림 |
| **충격** (타격 · 착지 · 방향 전환) | 충격 응답 — `e^(−ζωt)·sin(ω_d·t)`, **「사건 이후 흐른 시간」의 함수** | 맞을 때 흔들림 |

두 번째는 §25.3 이 이미 쓰고 있는 형태 그대로다 —
> 전부 「사건 이후 흐른 시간」의 함수로 두면 오버슛은 그냥 진폭이 1 을 넘는 감쇠 진동이다.

**즉 물리를 넣는 것이 구조를 깨는 것이 아니라, 이 구조가 처음부터 물리의 형태였다.**
`char_reaction.gd`(§25.27 「맞는 것을 클립이 아니라 힘으로」)가 이미 그 절반이다.
남은 절반은 **구동 응답**과 **그것을 받을 몸**이다.

> **이 판단이 이 레인 전체를 정한다.** 적분기를 넣었으면 §25.3 의 셋을 잃고,
> GIF 이음매가 끊기고, 웹에서 프레임이 튈 때 흔들림이 같이 튀었을 것이다.

### 3.3 모핑 — **두 부위가 서로 다른 답을 요구한다**

§25.1 이 **메시 변형과 `Polygon2D` 가중치를 금지**한다. 관절이 없는 것이 이 스타일이라서다.
그런데 사용자가 요청한 것은 모핑이다. 그래서 부위별로 갈랐다.

> ### ⚠ 아래 표의 머리카락 줄은 **착수 뒤에 뒤집혔다**
>
> 이 절을 쓸 때는 머리카락을 **일곱째 파츠로 뗀다**고 적었다.
> **실물 그림에 `hair.png` 가 없다** — `head.png` 에 머리카락이 그려져 들어 있다.
> 그래서 브리핑 표에서 「지금은 안 뗀다」로 뒤집었고, 레인이 그것을 따랐다.
>
> **지금 참인 것:** 머리카락과 가슴이 **둘 다 셰이더 UV 워프**다.
> 그림이 오면 **앵커의 `part` 만 바꾸면** 파츠 분리로 갈아탄다 —
> 그 자국은 `design/31-soft-body.md` §31.2.1 에 있다.

| 부위 | 길 (착수 시점 계획) | §25.1 을 깨나 |
| --- | --- | --- |
| ~~머리카락~~ | ~~일곱째 파츠로 분리~~ → **가슴과 같은 셰이더 워프** | ❌ 안 깬다 |
| **가슴** | 몸통 스프라이트에 **셰이더 UV 워프** (프래그먼트, 방사형 감쇠) | ⚠️ 렌더링에만 갇힌다 — 파츠 여섯은 그대로 트랜스폼 |

**머리카락 분리는 새 결정이 아니다.** §25.1.1 이 이미 후보로 올렸고 보류했다 —

> 떼면 예뻐진다 — 머리보다 더 늦게 따라오는 파츠가 하나 생기니까. 그런데
> **도형 단계에서는 머리와 머리카락의 실루엣이 같아서 지연이 안 보인다.**
> **스프라이트가 들어온 뒤에 판단한다.**

**스프라이트는 왔다** (§25.41.7). 그러니 그 보류의 조건이 풀렸고, 지금이 판정 시점이다.

가슴은 파츠로 뗄 수 없다 — 몸통 실루엣 **안**에 있어서 떼면 원피스가 갈라진다.
그래서 **모핑이 실제로 필요한 유일한 자리**이고, 요청의 「모핑」은 여기에 걸린다.

#### 왜 프래그먼트 셰이더인가 — 버텍스로는 안 된다

`Sprite2D` 는 **사각형 네 점**이다. 버텍스 셰이더로는 네 모서리밖에 못 움직인다 —
국소 부풀림이 원천적으로 안 나온다. 격자를 잘게 나눈 `MeshInstance2D` 로 바꾸면 되지만
파츠 수와 드로우 비용 표(§25.32)를 전부 다시 재야 한다.

**UV 영역을 프래그먼트에서 휘면** 노드가 안 늘고, `gl_compatibility`(WebGL2)에서 그대로 돌고,
§25.32 의 실측표가 안 낡는다.

### 3.4 그래서 배선은 이렇다

```
        AnimFeatures (t)
              │
     ┌────────┴────────┐
     │                 │
  CharPose         SoftBody          ← 둘 다 t 의 순수 함수
  (파츠 6+1)       (해석적 감쇠진동)
     │                 │
     │            MorphState { chest: 오프셋·눌림, hair: 각도·늘어남 }
     │                 │
     ├── 머리카락 ◄────┤   트랜스폼으로 받는다 (파츠)
     │                 │
     └── 몸통 ◄────────┘   셰이더 uniform 으로 받는다 (렌더링)
```

`MorphState` 가 **순수 자료**라서 셰이더 없이 단위 테스트가 된다 —
§25.13.1 「그림과 자가 다른 것을 본다」가 이 저장소에서 네 번 났다. 그 다섯 번째를 막는 자리다.

### 3.5 미리 박아 두는 판단 — 레인이 물어볼 수 없으므로

`CLAUDE.md` 「브리핑에 반드시 넣을 것」 7번. 갈릴 자리를 비워 두면 추측이 들어온다.

| 물음 | 답 | 근거 |
| --- | --- | --- |
| 흔들림의 세기 | **작게.** 정지 시 최대 변위는 해당 파츠 반크기의 **12 % 이하** | §25.29 「과장은 각도로, 거리로 하면 몸이 분해된다」 |
| 켜고 끄기 | **인물마다 자료값.** 0 이면 완전히 꺼진다(= 지금 화면과 동일) | §25.40 인물이 여럿이다 |
| 웹 예산 | 셰이더 **한 벌**, 파츠 **하나만** 증가. §25.31.3 의 웹 표를 다시 재지 않아도 되는 선 | §25.32.3 |
| 좌표계 | 코어는 `+y` 가 위. 변환은 `CharPose.canvas_transform()` **한 곳만** | §25.2.1 |
| 미학 | 흔들림이 **동작을 읽는 데 방해가 되면 진 것이다.** 실루엣 자(§25.22)가 판정한다 | §25.22 |

```bash
godot --headless --path . -s res://addons/gut/gut_cmdln.gd  # 테스트 통과
gdlint src test && gdformat --check src test                # 컨벤션 통과
```

| 더 보는 것 | 왜 |
| --- | --- |
| **테스트 수가 623 에서 얼마나 늘었나** | 레인의 테스트가 조용히 안 실린 것을 잡는다. §25.13.6 「통과가 안 돌았다를 뜻한다」 |

## 8. 본판이 PC 로 바뀌었다 (2026-08-19)

작업 도중 사용자가 방향을 바꿨다.

> "나 이젠 웹빌드 안하고 pc 스탠드얼론 빌드로 뽑을거야.
> 웹빌드 사양을 남겨둬도 괜찮은데(디버깅용이나 사람들한테 데모 배포용)
> **실제 게임은 pc로 출시할거야**"

**웹을 버리지 않는다 — 등급이 내려간다.** 그래서 §7 의 용량 걱정(§7.1)이
**본판에서는 사라졌고**, 웹 데모에만 남는다.

| 바뀐 것 | 어디에 |
| --- | --- |
| 제약표를 본판/부판으로 가름 | `design/01-constraints.md` §1.1 |
| **무엇이 풀리고 무엇이 안 풀렸나** | 〃 §1.2.1 |
| 렌더러를 아직 안 바꾼 이유 | 〃 §1.1.1 |
| 「절대 바꾸지 말 것」의 **이유**가 바뀜 | `CLAUDE.md` |
| PC 빌드 방법 | `web-build.md` 머리 |
| 결정 기록 D-42 ~ D-46 | `design/11-decisions.md` |

**가장 크게 바뀌는 것은 「아끼지 마라」다.** 이 저장소는 웹 용량을 걱정해서
UI 를 도형과 셰이더 노이즈로 몰아넣었다가 한 번 갈아엎었다.
**그 걱정의 근거가 이제 없다.**

### 렌더러는 레버만 만들어 뒀다

Vulkan/Forward+ 로 **구동은 확인했다** (RTX 4090 Laptop, 오류 0).
Godot 이 `rendering_method.web` 로 플랫폼을 가를 수 있으므로
*"PC 는 Forward+, 웹은 GL"* 이 설정으로는 된다.

**그런데 안 켰다.** 셰이더 전부 — 타이틀 · UI 킷 · 스케치 · 모핑 — 가
`gl_compatibility` 에서만 그려 보고 판정받았다.
**켜는 값은 성능이 아니라 「화면 검수 두 벌」이고, 그 비용은 통합자가 임의로 낼 것이 아니다.**

## 6. 린트가 이 기계에서 안 끝난다 — 러너를 세웠다

`gdlint src test tools` 를 **12회 돌려 12회 전부 실패**했다. 폭사(`139`)와
lark 파서 내부의 엉뚱한 `AttributeError`(오염이 파이썬 쪽에 나타난 얼굴)가 섞였다.

**파일 하나의 폭사율은 1/10 인데 530 파일을 한 프로세스로 돌리면 사실상 100 % 다.**
그래서 `tools/run_lint_retry.py` 가 **파일 하나씩 돌리고 폭사한 것만 다시 돌린다.**
그러니 판정이 나왔다 — **폭사 62회를 흡수하고 지적 3건을 정확히 집어냈다.**

> **통째로 돌릴 때의 「지적 0건」은 깨끗하다는 뜻이 아니라 검사를 못 했다는 뜻이었다.**

고친 지적 넷 중 **둘이 `tools/` 에 있었다.** `CLAUDE.md` 의 검증 4줄은
`gdlint src test` 인데 **CI 는 `src test tools` 를 검사한다** — 그 틈으로 들어왔다.
검증 규칙을 CI 와 맞췄다.

## 7. 웹 빌드 — **내보내고 브라우저에서 실제로 띄웠다**

이 저장소는 *"헤드리스 테스트를 통과하고도 화면에서 파싱 에러로 터진 전례"*를 갖고 있다.
그래서 내보내기만으로 끝내지 않고 **실제로 로드했다.**

```
Godot Engine v4.7.1.stable
OpenGL API OpenGL ES 3.0 (WebGL 2.0) - Compatibility
Build configuration: Emscripten 4.0.20, single-threaded, no GDExtension support
[NHNProject] v0.1.0 / platform=Web
```

**스크립트 오류 0 · 파싱 에러 0.** `gl_compatibility` 와 단일 스레드 설정이
의도대로 붙어 있는 것도 로그가 확인해 준다.

### 7.1 다만 용량이 무겁다 — **판단이 필요한 자리라 손대지 않았다**

| 조각 | 원본 | gzip |
| --- | --- | --- |
| `index.wasm` | 37 MB | **9 MB** |
| `index.pck` | 30 MB | **29 MB** |

**`pck` 가 거의 안 줄어드는 것이 핵심이다.** 안에 든 것이 이미 압축된
텍스처(`.ctex`)라 gzip 이 더 짜낼 것이 없다. 첫 로딩이 **약 38 MB** 다.

무엇이 차지하나 — `src/ui/title/art/` **11 MB**(원본 PNG) · `assets/ui/` 2.5 MB ·
폰트 1.1 MB · 구운 소리 **0.98 MB**.

**타이틀 그림이 가장 크고, 그 열 장이 전부 실제로 쓰인다.**
(`demon_a`·`demon_c` 는 폐기안이 아니라 화면에 같이 서는 다른 개체다 —
`title_layers.gd` 가 셋을 다 배치한다. 지우면 타이틀이 빈다.)

> **줄이려면 임포트 설정을 손대야 하고 그것은 화질 판단이다.**
> 타이틀 레인이 정한 것을 통합자가 임의로 낮추지 않는다. **재서 남기고 사용자에게 넘긴다.**

### 7.2 확인하고 지나간 것 — 소리는 제대로 실린다

`export_presets.cfg` 가 `assets/audio/sfx/*` 를 **제외**하고 있어 한 번 놀랐는데,
**의도한 것이 맞다.** 그 폴더는 CC0 원본 녹음이고 **굽는 재료**다.
게임이 싣는 것은 `assets/audio/sfx_baked/` 이고, `pck` 안에 **166 개가 들어 있다.**
(제외 규칙 `assets/audio/sfx/*` 는 `sfx_baked` 를 안 건드린다.)

> **처음에 `strings` 로 확인했다가 「소리가 하나도 안 실렸다」는 오판을 할 뻔했다.**
> 그 도구가 `pck` 에서 **아무 경로도** 못 찾고 있었다 — 확실히 들어 있는 것까지.
> **도구가 0 을 답할 때는 도구부터 검사해라.** 이 저장소에서 이 실패는 이번이 처음이 아니다.
