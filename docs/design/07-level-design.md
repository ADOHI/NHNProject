# 07. 던전 · 공간 · 위험도

> **상태: 확정(구조) / 미정(수치).**
> 공간 표현은 **방 단위 노드**로 확정. 그 위에 **위험도 추리 시스템**이 얹힌다.

---

## 7.1 공간 표현 — 방 단위 노드 (확정)

던전은 **방(노드)의 연결 그래프**다. 타일 그리드가 아니다.

| 항목 | 값 |
| --- | --- |
| 이동 단위 | 방 → 인접 방 |
| 관리 대상 | "누가 어느 방에 있는가" |
| 없는 것 | 칸 단위 좌표, 사거리, 시야각, 경로탐색 |

**결정 근거** — 조우·협상·경쟁이라는 핵심([`02-overview.md`](02-overview.md) §2.3)은
방 단위로 전부 성립하는 반면, 타일 그리드는 경로탐색·시야·타일맵 UI 를 전부 요구한다.
1인 90시간([`01-constraints.md`](01-constraints.md) §1.3)에서 그 비용은
NPC AI 와 성향 시스템에 쓸 시간을 그대로 잡아먹는다.

---

## 7.2 위험도 추리 시스템 (핵심)

**이 게임의 공간은 이동 경로가 아니라 추리판이다.**

### 7.2.0 위험도 = 전투력의 합 (확정)

방의 위험도는 그 방에 있는 존재들의 **전투력 합**이다.
몬스터든 NPC 탐험가든 플레이어 스쿼드든 **같은 단위**를 쓴다.

**그래서 플레이어는 자기 스쿼드 전투력과 방의 숫자를 직접 비교한다.**
"인접 합 6, 내 스쿼드 8" 은 계산 없이 읽히는 판단이다.

그리고 같은 수치가 반대 방향으로도 작동한다 —
**내 전투력은 곧 남에게 보이는 내 크기다** ([`14`](14-squad.md) §14.3).
강해지는 것과 눈에 띄는 것이 분리되지 않는다.

### 7.2.1 규칙

지뢰찾기와 같은 구조다.

- 플레이어가 있는 방은 **인접한 방들의 위험도 총합**을 보여 준다.
- 총합은 보이지만, **그 합이 어떻게 구성되어 있는지는 보이지 않는다.**

```
        [ ? ]        [ ? ]
           \          /
            \        /
   [ ? ] ─── [ 나 : 6 ] ─── [ ? ]
                 |
              [ ? ]
```

인접 4개 방의 위험도 합이 **6**. 그런데 이 6 은—

| 실제 구성 | 플레이어에게 미치는 위협 |
| --- | --- |
| 한 방에 위험도 6 짜리 보스 하나 | 그 방만 피하면 안전. 나머지 3방은 무료 |
| 네 방에 위험도 1~2 짜리가 분산 | 어디로 가도 싸운다. 소모전 |

**같은 숫자 6 이지만 최적 행동이 정반대다.** 이 모호함이 곧 게임이다.

### 7.2.2 왜 이 설계가 옳은가

한 시스템이 세 가지를 동시에 해결한다. 90시간 안에서 이건 결정적이다.

| 해결하는 문제 | 방식 |
| --- | --- |
| **"언제 나갈까"** ([`02`](02-overview.md) §2.3-A) | 앞쪽 숫자가 커지면 물러설 이유가 생긴다. 별도 장치 불필요 |
| **불완전 정보** | 숫자는 주지만 구성은 안 준다 — "단서는 있고 확신은 없다" |
| **개발 비용** | 그래프 + 정수 합산. 시야·경로탐색·애니메이션 없이 성립 |

### 7.2.3 모호함을 걷어내는 수단

**정보 자체가 이 게임의 자원이다.** 숫자의 내부 구성을 알아내는 수단을 유료화한다.

| 수단 | 알려 주는 것 | 조달 |
| --- | --- | --- |
| 정찰 아이템 | 미정 — 특정 방 1개의 정확한 내용 | 아웃게임 구매 · 던전 습득 (소모) |
| 직업 스킬 | 미정 — 예: 최댓값만 안다 / 개체 수만 안다 | 캐릭터 고유 (쿨다운) |
| 렉카 기사 | 다른 방에서 **실제로 벌어진 일** → §7.4 | 무료 · 매 턴 |
| 주둔지 강화 | 입장 시점의 정보량 | 영구 ([`06`](06-progression.md) §6.2) |

**"개체 수만 알려 주는" 스킬과 "최댓값만 알려 주는" 스킬은 서로 다른 정보다.**
합이 6, 개체 수가 1 이면 보스 확정. 합이 6, 최댓값이 2 면 분산 확정.
**단서를 조합해 좁혀 나가는 것**이 직업 설계의 축이 된다.

### 7.2.4 미정 수치

| 항목 | 값 |
| --- | --- |
| **위험도의 의미** | **전투력의 합** (확정) |
| 위험도 범위 | 미정 |
| 보이는 범위 | 미정 — 인접 방만 / 2칸 / 방문한 방 전부 |
| 방문한 방의 정보 유지 | 미정 — 기억되는가, 갱신되는가 |
| NPC 탐험가가 위험도에 포함되는가 | **포함된다 (확정)** — §7.2.5 |

### 7.2.5 NPC 도 위험도에 포함된다 (확정)

몬스터는 대체로 고정이고 **NPC 는 움직인다.** 따라서:

> **숫자의 절대값은 위험을 알려 주고, 숫자의 변화량은 사람을 알려 준다.**

3이던 방이 7이 됐다면 몬스터가 아니라 **누가 들어간 것**이다.
이 추론 하나로 핵심 재미 A(언제 나갈까)와 B(누구를 상대할까)가
**같은 숫자 하나**에서 나온다.

상세 — [`13-information-design.md`](13-information-design.md) §13.5

## 7.2.6 고도 (확정)

**방마다 고도(정수)를 갖는다.** 두 방 사이의 이동 가능 여부는 고도차로 결정된다.

| 이동 | 조건 |
| --- | --- |
| 내려가기 · 같은 높이 | **언제나 가능** |
| 올라가기 | **상승폭 ≤ 민첩** 이어야 가능 |

연결 자체는 여전히 양방향이다(§7.1). 바뀐 것은 **통과 조건이 주체마다 다르다**는 점이다.

### 7.2.6.1 고도가 세 가지를 동시에 해결한다

| 문제 | 고도가 주는 답 |
| --- | --- |
| 메트로배니아식 관문 | 능력이 오르면 갈 수 있는 곳이 늘어난다 |
| **화면 배치** | **Y축을 고도로 쓴다.** 좌표를 손으로 찍을 필요가 없다 |
| 난이도 계층 | 입구에서의 "필요 민첩"이 곧 방의 등급 (§7.2.8) |

절차 생성의 숨은 비용이 자동 레이아웃인데, 고도를 넣는 순간 그 문제가 사라진다.
그리고 플레이어는 **"위로 갈수록 어렵다"** 를 설명 없이 읽는다.

### 7.2.6.2 하강이 자유라는 것의 의미

> **들어가긴 쉽고 나오긴 어렵다.**

익스트랙션의 근본 긴장이 **지형에서 저절로 나온다.**
깊이 내려갈수록 돌아 나올 길이 막히므로, "언제 돌아설까"가 매 턴 발생한다.
턴 제한 같은 장치 없이 압박이 생긴다는 점에서
주목도 루프([`13`](13-information-design.md) §13.2)와 같은 성질이다.

판을 읽는 방식도 여기서 나온다.

| 방향 | 의미 |
| --- | --- |
| 위 | **위협의 출처.** 저기 있는 것들은 언제든 내려올 수 있다 |
| 아래 | **도주로.** 나는 언제든 내려갈 수 있다 |

고도가 Y축이므로 이 구도가 화면에서 바로 읽힌다.

### 7.2.7 못 가는 방도 위험도 합에 포함된다 (확정)

인접 위험도 합은 **갈 수 있든 없든 인접한 모든 방**을 더한다.

몬스터와 NPC 탐험가도 각자 민첩을 가지므로,
**내가 못 올라가는 방에서 그들은 내려올 수 있다.**

> 나는 손도 못 대는데 쟤는 올 수 있다.

이 비대칭이 고도의 공포다. 그리고 민첩을 올리면 같은 위협이 **기회로 바뀐다** —
못 가던 고가치 방에 손이 닿기 시작한다.

**즉 민첩은 이동 능력이면서 동시에 위험도 숫자의 의미를 바꾸는 값이다.**

### 7.2.8 필요 민첩 — 방의 등급

어떤 방에 도달하려면 **경로 상 최대 상승폭**을 넘을 수 있어야 한다.
여러 경로가 있으면 그중 **최대 상승폭이 가장 작은 경로**가 기준이다.

```
필요 민첩(방) = min over 경로 ( max over 간선 ( 상승폭 ) )
```

이 값이 곧 방의 등급이고, 생성기가 가치·탈출구를 배치하는 기준이 된다
([`17-dungeon-generation.md`](17-dungeon-generation.md)).

## 7.2.9 방 종류 (확정)

| 종류 | 내용 |
| --- | --- |
| 입구 | 스쿼드가 시작하는 방. 하나 |
| 빈방 | 통로 역할 |
| 귀중품 | 전리품이 있다. 접근 비용이 높을수록 가치가 높다 |
| 위험 | 함정 · 고위험 몬스터 |
| 보스 | 고위험 고보상. NPC 탐험가도 노린다 |
| 탈출 | 탈출 지점. **최소 하나는 민첩 0 으로 도달 가능해야 한다** |

세부 규칙(함정 효과, 귀중품 가치 산정)은 **보류 — 구현하며 결정**
([`05`](05-rules.md) §5.6 E5 와 함께).

## 7.3 던전 목록

던전은 여러 개이고 아웃게임에서 **선택**해 입장한다. 선택이 곧 난이도 선택이다.

| # | 이름 | 방 개수 | 위험 성격 | 보상 성격 | NPC 수 | 해금 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

**던전끼리 "강함"만 다르면 선택이 아니라 순서다.** 성격이 달라야 한다 —
예: 방이 적어 숫자 추리가 쉽지만 NPC 가 몰리는 곳 /
넓어서 정보가 부족하지만 경쟁이 적은 곳 / 보스 하나에 보상이 집중된 곳.

## 7.4 렉카 기사와 공간

플레이어가 보지 못하는 방에서 벌어지는 일은 **렉카 기사**를 통해 새어 나온다.
→ 상세는 [`08-ui-ux.md`](08-ui-ux.md) §8.3

즉 플레이어는 두 종류의 정보를 겹쳐 읽는다.

| 정보원 | 성질 |
| --- | --- |
| 위험도 숫자 | **정확하지만 모호하다** (합만 알려 준다) |
| 렉카 기사 | **구체적이지만 못 믿는다** (과장·왜곡 가능) |

**두 정보의 성질이 정반대라서 서로를 보완한다.** 이게 이 게임의 정보 설계다.

## 7.5 구성 방식

**미정.** 최소 절충안: 방 연결 구조는 소수의 고정 레이아웃,
**배치(위험도·귀중품·NPC 시작 위치)만 무작위**.
매 판이 달라지면서 생성기 제작 비용은 들지 않는다.

## 7.6 배치 규칙

| 대상 | 규칙 |
| --- | --- |
| 플레이어 | 미정 — 입구 방 고정 |
| NPC 탐험가 | 미정 — **플레이어와 떨어진 곳**에서 시작해야 조우가 사건이 된다 |
| 몬스터 · 보스 | 미정 |
| 귀중품 | 미정 — **유한해야 NPC 와의 경쟁이 성립한다** |
| 탈출 지점 | 미정 — 개수와 위치가 "언제 나갈까"의 무게를 결정한다 |

### 배치 원칙

- 진입 직후 즉사 배치 금지.
- **탈출 지점 위치는 알 수 있어야 한다.** 모르면 탈출이 판단이 아니라 운이 된다.
- 귀중품과 위험을 같은 곳에 둔다. 안전한 곳에 보상이 있으면 결정이 사라진다.
- **위험도 숫자만으로 정답이 나오는 배치를 피한다.** 항상 해석의 여지가 남아야 한다.

## 7.7 연출 이벤트 — 방송의 개입 (검토 중)

던전이 방송용 시설이라면([`02`](02-overview.md) §2.6.1),
**판이 지루해질 때 제작진이 개입하는 것**이 자연스럽다.

| 이벤트 | 효과 | 세계관 |
| --- | --- | --- |
| 수면가스 | 전원이 **다른 방으로 재배치**된다 | 판을 리셋하고 새 그림을 만든다 |
| 셔터 폐쇄 | 특정 통로가 막힌다 | 동선을 강제한다 |
| 조명 차단 | 위험도 정보가 안 보인다 | 정보를 끊는다 |
| 보급 투하 | 특정 방에 고가치 물품 | 사람을 한곳으로 모은다 |

### 수면가스 재배치 — 주의

**매 턴 재배치는 안 된다.**
[`13-information-design.md`](13-information-design.md) §13.5 의 핵심 추론
("숫자의 변화량은 사람을 알려 준다")이 **완전히 무너진다.**
매 턴 전원이 순간이동하면 변화량은 아무 의미도 없는 잡음이 되고,
이 게임의 엔진이 꺼진다.

**대신 가끔 쓰면 최고의 장치다.**

| 쓰임 | 효과 |
| --- | --- |
| 정체된 판 흔들기 | 서로 피하기만 하는 교착을 깬다 |
| 후반 압박 | 안전한 구석에 숨는 전략을 무력화한다 |
| 극적 반전 | 탈출 직전에 터지면 최악의 사건이 된다 |

**조건: 예고되어야 한다.** 아무 예고 없이 터지면 플레이어 탓이 아니게 되고,
[`03`](03-core-loop.md) §3.4 원칙이 깨진다.
렉카 기사가 예고 수단으로 딱 맞는다 — *"곧 뭐 터진다는데요 ㅋㅋ"*

→ [`12-open-questions.md`](12-open-questions.md) Q25

## 7.8 카메라 · 화면

방 그래프를 **한 화면에 전부** 보여 준다. 스크롤·카메라 이동 없음.
플레이어는 판 전체를 보며 숫자를 읽어야 하므로, 화면 밖에 판이 있으면 안 된다.
