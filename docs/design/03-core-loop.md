# 03. 코어 루프

> **상태: 확정.** 이중 루프 · 페이즈 구조 · **동시 해결** 확정. 세부 판정은 미정.

---

## 3.0 전체 구조

루프가 **두 겹**이다. 바깥이 아웃게임, 안이 인게임이다.

```
        ┌──────────────── 아웃게임 (주둔지) ─────────────────┐
        │  정산 → 주둔지 강화 → 장비 세팅 → 던전 선택        │
        └───────┬────────────────────────────────▲──────────┘
                │ 입장                            │ 탈출 / 사망
        ┌───────▼────────── 인게임 (던전) ────────┴──────────┐
        │  배치 → [ 계획 페이즈 → 행동 페이즈 ] 반복          │
        └────────────────────────────────────────────────────┘
```

**두 루프는 서로를 필요로 한다.**
아웃게임이 없으면 잃을 것이 없어 익스트랙션이 성립하지 않고,
인게임이 없으면 강화할 이유가 없다.

## 3.1 초 단위 루프 — 턴

인게임의 최소 반복 단위. **1턴 = 계획 페이즈 1회 + 행동 페이즈 1회.**

| 페이즈 | 하는 일 |
| --- | --- |
| **계획** | ① 위험도 숫자를 읽는다 ② **렉카 기사를 읽는다** ③ 이번 턴 행동을 지시한다 |
| **행동** | 모두의 지시가 **동시에** 실행된다. 결과가 드러나고, 새 기사가 올라온다 |

**계획과 행동을 나눈 것이 이 게임의 정체성이다.**
계획 시점에는 정보가 불완전하고, 행동 시점에는 되돌릴 수 없다.

계획 페이즈는 "명령 입력 대기"가 아니라 **읽고 추리하는 시간**이다.
플레이어가 여기서 실제로 하는 일은 두 정보를 겹치는 것이다.

| 정보원 | 성질 | 출처 |
| --- | --- | --- |
| 인접 방 위험도 합 | **정확하지만 모호** | [`07`](07-level-design.md) §7.2 |
| 렉카 기사 | **구체적이지만 못 믿음** | [`08`](08-ui-ux.md) §8.3 |

**둘의 성질이 정반대라서 서로를 보완한다.** 숫자는 못 속이고 기사는 부풀린다.

## 3.2 판 단위 루프 — 잠입 1회

```
던전 입장
  → 배치 (플레이어 · NPC 탐험가 · 몬스터가 던전에 놓인다)
  → 턴 반복 { 계획 → 행동 }
      · 탐색해서 귀중품을 얻는다
      · 몬스터와 싸운다 (보스 = 고위험 고보상)
      · NPC 탐험가와 마주친다 → 전투 / 협상 / 회피
  → 종료
      · 탈출  : 가지고 있던 것을 확정 획득
      · 사망  : 대부분 상실
```

**매 턴 플레이어가 사실상 하나의 질문에 답한다: "더 벌 것인가, 지금 나갈 것인가."**

## 3.3 판 사이 루프 — 아웃게임

```
정산 (가져온 전리품)
  → 주둔지 강화 (영구 · 누적)
  → 다음 잠입 장비 세팅 (소모 · 잃을 수 있음)
  → 던전 선택 (위험도 ↔ 보상 트레이드오프)
  → 입장
```

**영구적으로 남는 것(주둔지)과 잃을 수 있는 것(장비)을 분리한다.**
전부 잃으면 재기 불능이라 다시 안 하고, 아무것도 안 잃으면 긴장이 없다.
그 경계선을 어디에 긋는지가 이 게임의 밸런스 축이다. → [`05-rules.md`](05-rules.md)

## 3.4 다시 하게 만드는 것

- **손실이 내 판단의 결과여야 한다.** "한 턴만 더" 를 선택한 것도, 협상을 믿은 것도 플레이어다.
  운으로 죽으면 다시 안 한다.
- **주둔지는 남는다.** 전부 잃어도 다음 판의 출발점이 지난 판보다 낫다.
- **안 가본 던전이 남아 있다.**

## 3.5 결정 지점 정리

플레이어가 실제로 고민하게 되는 지점. 이 목록이 곧 게임의 내용이다.

| 시점 | 결정 |
| --- | --- |
| 아웃게임 | 강화에 쓸까, 장비에 쓸까 |
| 아웃게임 | 어느 던전에 들어갈까 (위험 ↔ 보상) |
| 인게임 매 턴 | 더 깊이 갈까, 탈출로 향할까 |
| 인게임 조우 | 죽일까 · 협상할까 · 피할까 |
| 인게임 | 보스를 노릴까, 안전한 것만 챙길까 |

## 3.6 턴 해결 방식 — 동시 해결 (확정)

플레이어와 모든 NPC 탐험가·몬스터가 계획을 정한 뒤, 행동 페이즈에 **동시에** 실행된다.

**근거** — 순차 해결이면 계획 페이즈를 나눌 이유가 사라진다.
"상대도 지금 나를 노리고 있을지 모른다"가 성립해야 조우가 심리전이 되고,
그러려면 서로의 수를 모른 채 동시에 확정해야 한다.
배신이 극적으로 드러나는 것도 동시 해결이라야 가능하다.

**대가** — 경계 상황을 전부 정의해야 한다. 이건 코드 문제가 아니라 **기획 문제**이고,
미리 정하지 않으면 구현 중에 막힌다. → [`05-rules.md`](05-rules.md) §5.6

### 해결 순서

동시 해결이라도 코드는 순서대로 처리한다. 그 순서가 곧 규칙이다.

**미정.** 최소한 아래는 순서를 정해야 한다.

1. 이동 — 누가 어디로 갔는가 (충돌 판정)
2. 조우 — 같은 방에 둘 이상이 모였는가
3. 상호작용 — 전투 / 협상 / 탐색
4. 결과 — 사망 · 획득 · 탈출
5. 기사 생성 — 이번 턴 사건을 렉카 피드에 올린다 ([`08`](08-ui-ux.md) §8.3)
