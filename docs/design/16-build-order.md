# 16. 구현 순서

> **상태: 계획.** [`10-content-scope.md`](10-content-scope.md) 의 MVP 13항목을
> 의존 관계와 위험도에 따라 재배열한 것이다.
> 시간은 **실시간 기준 누적**이며 추정이다. 어긋나면 §16.8 로 대응한다.

---

## 16.1 배열 원칙

| 원칙 | 이유 |
| --- | --- |
| **위험한 것을 먼저** | 동시 해결 턴 루프와 NPC 가 가장 어렵다. 늦게 손대면 손쓸 시간이 없다 |
| **매 구간 끝에 돌아가는 것이 있다** | 세로로 얇게 완성하고 살을 붙인다. 시스템별로 완성하면 통합 시점에 전부 터진다 |
| **브라우저 확인을 앞으로 당긴다** | 배포 자체는 자동이지만, **내용이 생긴 뒤에만 드러나는 문제**가 있다 (§16.4) |
| **자를 수 있는 것을 뒤로** | 시간이 밀리면 뒤에서부터 잘린다 (§16.8) |

## 16.2 0단계 — 기반 (0 ~ 5h) ✅ 완료

코드가 아니라 **뼈대**를 정하는 구간. 여기서 잘못 잡으면 전부 다시 짠다.

| 할 일 | 상태 |
| --- | --- |
| 프로젝트 구조 · 씬 구성 | ✅ 기존 골격 사용 ([`../conventions.md`](../conventions.md)) |
| 로직을 `src/core/` 순수 클래스로 분리 | ✅ `RefCounted` 기반, 노드 비의존 |
| 데이터 구조 — `Actor` · `Room` · `DungeonGraph` | ✅ 인접 위험도 · 개체 수 · 최댓값 조회 포함 |
| **이벤트 로그 구조** — `GameEvent` · `EventLog` | ✅ 누가 · 어디서 · 무엇을 · 얼마나 |
| 단위 테스트 | ✅ 41/41 통과 (gdlint · gdformat 통과) |

구조는 [`../architecture.md`](../architecture.md) 참고.
**스쿼드는 여기서 만들지 않았다** — `Actor` 하나로 스쿼드를 표현하고(전투력 합 = 스쿼드 합),
편성·영입이 필요해지는 5단계에서 분리한다.

### 이벤트 로그를 지금 정하는 이유

렉카 기사(M6)와 세계 갱신(M13)은 **둘 다 "무슨 일이 있었는가"를 입력으로 받는다.**

```
행동 페이즈 → 이벤트 로그 ─┬→ 렉카 기사 생성 (인게임)
                            └→ 세계 갱신 · 뉴스 (아웃게임)
```

**로그 구조를 나중에 만들면 턴 처리 코드를 다시 짜야 한다.**
지금 `누가 · 어디서 · 무엇을 · 얼마나` 네 칸만 정해 두면 그 재작업이 없다.
([`08`](08-ui-ux.md) §8.3.6 의 기사 요소와 같은 칸이다.)

## 16.3 1단계 — 판이 보인다 (5 ~ 15h) 〔M1〕 ✅ 완료

| 할 일 | 상태 |
| --- | --- |
| 방 그래프 렌더링 (한 화면에 전부) | ✅ 스크롤·카메라 없음 ([`07`](07-level-design.md) §7.8) |
| 인접 방 위험도 **합** 표시 | ✅ 선 방에만 표시, 나머지는 `?` |
| 클릭으로 방 선택 · 이동 | ✅ 인접한 방만 활성 ([`04`](04-controls.md) §4.1) |
| 표본 던전 | ✅ 8방. **금고(6짜리 하나) vs 사육장(2짜리 셋)** 대비를 눈으로 보여 준다 |

**✅ +15h 마일스톤 — 조작 가능한 말이 판 위에 있다.**

검증: GUT 60/60 · gdlint · gdformat · 렌더링 캡처 확인
(`tools/capture_scene.gd` — 실제 버튼을 눌러 화면 경로까지 검증한다).

**아직 없는 것:** 턴 페이즈, NPC 이동, 위험도 변화량 표시.
변화량 표시는 4단계 항목이다 (§16.6) — 판이 아직 정적이라 표시할 변화가 없다.

⚠ **한글 폰트가 `SystemFont` 라 웹에서 깨질 수 있다** → [`09`](09-art-sound.md) §9.3.1

## 16.4 2단계 — 턴이 돈다 (15 ~ 25h) 〔M2, M10 일부〕

**이 구간이 이 프로젝트에서 가장 어렵다.** 동시 해결의 골격을 세운다.

| 할 일 | 비고 |
| --- | --- |
| 계획 페이즈 / 행동 페이즈 분리 | [`03`](03-core-loop.md) §3.1 |
| 동시 해결 처리 순서 구현 | [`03`](03-core-loop.md) §3.6 — 이동 → 조우 → 상호작용 → 결과 → 로그 |
| 확정 전 계획 변경 가능 | [`04`](04-controls.md) §4.3 |
| 타이틀 화면 (첫 입력 확보) | [`08`](08-ui-ux.md) §8.7 |

### +25h — 배포본을 브라우저에서 열어 본다

**배포는 할 일이 아니다.** `deploy-web.yml` 이 push 마다 자동 실행되고,
2026-08-07 기준 최근 5회 전부 성공했으며 https://adohi.github.io/NHNProject/ 가 살아 있다.
파이프라인 리스크는 이미 해소돼 있다.

**남은 위험은 "빈 프로젝트가 배포되는 것"과 "게임이 브라우저에서 도는 것"의 차이다.**
아래 셋은 전부 **내용이 생긴 뒤에야** 드러난다.

| 확인할 것 | 왜 |
| --- | --- |
| 한글 폰트 로딩 · 용량 | 이 게임 최대 에셋 ([`09`](09-art-sound.md) §9.3). 서브셋 없으면 초기 로딩이 무겁다 |
| 단일 스레드 정지 | 무거운 루프가 한 프레임에 몰리면 화면이 멈춘다 ([`01`](01-constraints.md) §1.2) |
| `gl_compatibility` 렌더링 | UI·텍스트가 데스크톱과 다르게 나올 수 있다 |
| 화면 비율 · 모바일 | 포인터 단독 조작이 실제로 되는가 ([`04`](04-controls.md) §4.1) |

**이 확인은 이후에도 계속한다.** 특히 세계 갱신(5단계)은
NPC 전원을 한 프레임에 돌리면 단일 스레드에서 멈출 수 있으므로,
구현 직후 브라우저에서 다시 본다.

## 16.5 3단계 — 한 판이 끝난다 (25 ~ 45h) 〔M3, M4, M7, M8 최소〕

**루프를 닫는 구간.** 인게임만 돌면 반쪽이므로 아웃게임 껍데기까지 얇게 넣는다.

| 순서 | 할 일 | 비고 |
| --- | --- | --- |
| 1 | 행동 — 이동 · 탐색 · 탈출 | 전투는 최소 형태로 |
| 2 | **NPC 탐험가** — 이동 · 획득 · 탈출 | [`05`](05-rules.md) §5.2.2. **두 번째로 위험한 항목** |
| 3 | NPC 가 위험도 숫자에 반영 | [`13`](13-information-design.md) §13.5 |
| 4 | 사망 / 탈출 정산 | [`05`](05-rules.md) §5.3 — 빈손 귀환 |
| 5 | 아웃게임 **최소** 껍데기 | 입장 → 정산 → 재입장. 강화·편성 없음 |

**✅ +45h 마일스톤 — 한 판이 시작되고 끝나고 다시 시작된다.**

이 시점의 게임은 재미없다. **그래도 돌아가는 것이 중요하다.**
여기까지 못 오면 이후 계획을 전부 재검토한다 ([`10`](10-content-scope.md) §10.0).

---

## 16.6 4단계 — 게임의 정체성 (45 ~ 60h) 〔M5, M6〕

**여기서 이 게임이 다른 게임과 구분된다.** 앞 구간까지는 흔한 턴제 이동 게임이다.

| 순서 | 할 일 | 비고 |
| --- | --- | --- |
| 1 | **조우 절차** — 전투 / 협상 / 도주 분기 | [`05`](05-rules.md) §5.8 |
| 2 | **렉카 피드** — 이벤트 로그 → 기사 | [`08`](08-ui-ux.md) §8.3 |
| 3 | 기사 ↔ 판 연결 (방 이름 클릭 → 강조) | [`13`](13-information-design.md) §13.7 |
| 4 | 위험도 증감 표시 (▲2) · 방문 방 기억 | [`13`](13-information-design.md) §13.7 — **추리 성립 조건** |

**기사 문장 자체는 여기서 완성하지 않는다.** 구조만 만들고 최소 템플릿으로 둔다.
문장 쓰기는 코딩이 아니라 글쓰기라 **D 구간 자투리 시간에 채울 수 있는 유일한 항목**이다.

---

## 16.7 5단계 — 메타 루프 (60 ~ 70h) 〔M11, M12, M13, M8 확장, M9〕

3단계에서 만든 아웃게임 껍데기에 살을 붙인다.

| 순서 | 할 일 | 추정 | 비고 |
| --- | --- | --- | --- |
| 1 | **세계 갱신** | 2h | 정수 + 확률 판정. 기사 생성기 재사용 ([`15`](15-world.md) §15.3) |
| 2 | **관계도 + 영입** | 3h | [`05`](05-rules.md) §5.10, [`14`](14-squad.md) §14.5 |
| 3 | 스쿼드 편성 화면 | 3h | [`14`](14-squad.md) §14.4 |
| 4 | 주둔지 강화 3~4종 | 1h | |
| 5 | 던전 2개 (데이터) | 1h | [`07`](07-level-design.md) §7.3 |

**세계 갱신을 맨 앞에 둔 이유:** 가장 싸고, 뉴스 피드가 생기면
그 뒤 만드는 영입·편성 화면이 붙을 자리가 이미 마련된다.

**🔴 +70h — 기능 추가 중단.**

## 16.8 축소 순서 — 밀렸을 때 무엇부터 자르는가

**뒤에서부터 자른다.** 미리 정해 두지 않으면 마감 직전에 잘못된 것을 자른다.

| 순위 | 자르는 것 | 대체 |
| --- | --- | --- |
| 1 | 던전 2개 | 1개로 |
| 2 | 주둔지 강화 | 없앰 |
| 3 | 스쿼드 편성 | **정원 1명 고정** — 편성 화면 불필요 |
| 4 | 세계 갱신의 수치 변동 | 뉴스 기사만 (겉보기엔 세계가 도는 것처럼 보인다) |
| 5 | 영입 | 관계도만 남김 |

### 절대 자르지 않는 여섯 (핵심)

| # | 항목 | 없으면 |
| --- | --- | --- |
| M1 | 방 그래프 + 위험도 합 | 판이 없다 |
| M2 | 계획/행동 페이즈 | 이 게임이 아니다 |
| M4 | NPC 탐험가 | 흔한 턴제 로그라이크가 된다 |
| M5 | 조우 절차 | NPC 가 장애물로 전락한다 |
| M6 | 렉카 피드 | 개성이 사라지고 정보원도 하나 잃는다 |
| M7 | 사망 / 탈출 정산 | 익스트랙션이 성립하지 않는다 |

**이 여섯만 있으면 게임은 성립한다.** 나머지는 전부 협상 가능하다.

## 16.9 D 구간 (70 ~ 90h) — 마감

**축소 불가** ([`10`](10-content-scope.md) §10.0).

| 할 일 | 비고 |
| --- | --- |
| 웹 빌드 최종 검증 | 로컬에서 되던 것이 브라우저에서 안 될 수 있다 |
| 밸런스 조정 | 수치를 한 곳에 모아 뒀어야 가능 ([`06`](06-progression.md) §6.5) |
| **렉카 기사 문장 채우기** | 코딩이 아니므로 자투리 시간에 가능. 반복이 보이면 장치가 죽는다 |
| 온보딩 점검 | 채점자가 설명 없이 30초 안에 이해하는가 ([`06`](06-progression.md) §6.4) |
| 문서 갱신 · `docs/ai-usage.md` | 제출물 |

**✅ +85h — 최종 배포본 확인 완료.**
