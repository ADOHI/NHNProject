# 31. 소프트바디 — 물리를 먼저 세우고, 모핑은 그것을 그리는 층이다

> 사용자: *"레이맨 절차 애니메이션에 가슴 및 헤어 모핑을 합치고 해당 캐릭터에
> 물리력이 작용하는걸 시스템적으로 구현 한 뒤 모핑으로 통합하는 작업"*

**순서가 명령에 들어 있다.** ① 물리를 시스템으로 세우고 → ② 그 물리를 모핑으로 통합한다.
모핑을 먼저 만들고 물리를 나중에 끼우면, 모핑이 **자기 사인파를 갖게 되고**
그 순간 이 층은 물리가 아니라 **또 하나의 클립**이 된다. 그러면 타격 · 착지 · 방향 전환에
반응할 방법이 원천적으로 없다.

이 문서는 **쓰면서 고친다.** 판단이 바뀌면 그 자리에서 고치고, 왜 바뀌었는지를 남긴다
(`CLAUDE.md` 개발 원칙 1).

읽어야 하는 앞 문서: [`25-character-animation.md`](25-character-animation.md)
§25.1 · §25.2 · §25.3 · §25.13 · §25.22 · §25.27 · §25.29 · §25.32 · §25.40 · §25.41,
그리고 [`../integration-2026-08-18.md`](../integration-2026-08-18.md) §3.

## 31.0 정면으로 부딪히는 것 — **물리는 상태를 갖고, 이 구조는 상태가 없다**

§25.3 이 이 저장소의 뼈대다.

> 궤도가 시각의 함수이면, 지연 = `orbit(t − d)` 그것뿐이다.
> `func sample(t: float, f: AnimFeatures) -> CharPose` — **순수 함수다.**

그 대가로 얻은 것이 셋이고 **셋 다 지금 쓰고 있다.**

| 얻은 것 | 어디서 쓰나 |
| --- | --- |
| 링 버퍼가 없다 | 잔상 · 호가 `sample(t − Δ)` 로 그냥 나온다 (§25.23) |
| 프레임률이 튀어도 지연이 안 변한다 | 웹은 단일 스레드라 프레임이 튄다 (§25.8) |
| 임의의 `t` 를 바로 뽑는다 | GIF 캡처가 결정적이고 이음매가 정확히 맞는다 (§25.3.2) |

**그런데 물리는 정의상 상태다.** `v += a·dt; x += v·dt` 는 이전 프레임을 본다.
스프링을 순진하게 넣으면 위 셋이 **전부** 날아간다.

## 31.1 빠져나가는 길 — **감쇠진동에는 닫힌 해가 있다**

**적분기를 안 쓴다.** 우리가 쓸 두 경우 모두 해석해가 있다.

| 구동 | 해 | 쓰는 곳 |
| --- | --- | --- |
| **주기 구동** (idle · walk · run 은 §25.3.2 대로 한 바퀴당 정수 회다) | 정상상태 응답 — **같은 주파수, 진폭과 위상만 이동** | 서 있을 때 · 걸을 때 흔들림 |
| **충격** (타격 · 착지 · 방향 전환) | 충격 응답 `e^(−ζωt)·sin(ω_d t)` — **「사건 이후 흐른 시간」의 함수** | 맞을 때 흔들림 |

두 번째는 §25.3 이 **이미 쓰고 있는 형태 그대로**다. `char_reaction.gd` 가 그 절반이다.

### 31.1.1 어떤 방정식인가 — **바닥 가진(base excitation)이다**

「살이 몸을 늦게 따라온다」의 물리는 **질량이 스프링으로 몸에 매달려 있고, 몸이 흔들리는 것**이다.
몸의 변위를 `u(t)`, 살의 **상대 변위**를 `x(t)` 라 하면

```
x'' + 2ζω x' + ω² x = −u''(t)
```

`u = A sin(Ωt)` 이면 `−u'' = A Ω² sin(Ωt)` 이고, 정상상태는

```
x(t) = A · r² / sqrt((1 − r²)² + (2ζr)²) · sin(Ωt − ψ)
r = Ω / ω        ψ = atan2(2ζr, 1 − r²)
```

**이 모형을 고른 이유는 두 끝이 옳기 때문이다.**

| | 뜻 | 이 모형이 내는 값 |
| --- | --- | --- |
| `r → 0` (몸이 아주 천천히 움직인다) | 살이 몸에 딱 붙어 간다 | 상대 변위 **0** — 흔들림이 없다 |
| `r → ∞` (몸이 아주 빠르게 움직인다) | 살은 제자리에 남는다 | 상대 변위 **−u** — 몸만 지나간다 |

가속도로 안 쓰고 변위 전달률로 쓰면 저주파에서 흔들림이 안 죽어서, **가만히 서 있는데
가슴이 떠 있는** 그림이 된다. 실제로 그 함정이 있어서 여기에 적어 둔다.

### 31.1.2 그래서 응답이 **또 하나의 `wave()`** 다

클립이 쓰는 파형은 전부 이 꼴이다 (`CharClip.wave`).

```gdscript
wave(cycles, t, delay, f) = sin(TAU * cycles * (t − delay·f.delay) / loop_seconds)
```

정상상태 응답은 **같은 주파수에 진폭 배수와 시간 지연이 붙은 것**이므로

```
응답 = A · gain(cycles) · wave(cycles, t, delay + lag_seconds(cycles), f)
lag_seconds = ψ / Ω
```

**즉 응답이 클립과 같은 어휘로 표현된다.** 한 바퀴당 정수 회라는 성질이 그대로 남고,
**GIF 이음매가 물리를 얹은 뒤에도 정확히 맞는다.** 이것이 이 길을 고른 진짜 이유다.

### 31.1.3 구동을 어디서 얻나 — **클립에게 안 묻는다. 재서 뽑는다**

응답을 구하려면 구동 `u(t)` 의 **하모닉**이 필요하다. 두 길이 있었다.

| 길 | 대가 |
| --- | --- |
| 클립이 자기 스펙트럼을 내놓는다 (`drive_harmonics()`) | 클립 아홉을 전부 고쳐야 하고, **값이 두 곳에 적힌다** — §25.13.1 그 모양이다 |
| **한 바퀴를 표본해 이산 푸리에로 뽑는다** | **클립을 한 줄도 안 건드린다.** 셋업 때 한 번, 프레임마다는 안 돈다 |

**둘째를 골랐다.** 클립이 시각의 순수 함수이고 주기적이라 **그냥 된다** — §25.3 이 여기서
또 한 번 값을 한다. 그리고 이 길은 **자가 자기를 검사하지 않는다**(§25.13.2):
`SoftDrive` 는 `CharIdleClip` 의 상수를 **한 번도 안 읽는데**, 뽑아 보면 `breath 2 회`와
`sway 1 회`가 그 진폭으로 나온다. 그것이 테스트다.

### 31.1.4 안 되는 것 — **루프가 아닌 클립은 구동 응답을 안 받는다**

`jump` · `swing` · `hit` · `die` 는 루프가 아니다. 주기 분해가 성립하지 않으므로
**구동 응답을 안 건다.** 그 대신 **충격 응답**을 받는다 — 타격 · 착지 · 방향 전환이
정확히 충격이라 그쪽이 물리적으로도 맞는 이야기다.

> **남겨 두는 물음.** 스윙 중 몸이 크게 도는 것도 흔들림을 만들어야 한다면,
> 길은 「스윙의 시작 · 끝에 충격을 자동으로 심는 것」이지 「스윙을 주기로 보는 것」이 아니다.

## 31.2 모핑 — **머리카락과 가슴은 같은 장치다**

§25.1 이 **메시 변형과 `Polygon2D` 가중치를 금지**한다. 관절이 없는 것이 이 스타일이라서다.
그래서 모핑은 **렌더링에만 갇힌다** — 파츠 여섯의 트랜스폼은 그대로다.

### 31.2.1 머리카락을 일곱째 파츠로 떼지 않았다 — **판단이 한 번 바뀐 자리다**

[`../integration-2026-08-18.md`](../integration-2026-08-18.md) §3.3 은 **머리카락을 일곱째
파츠로 분리**한다고 적었다. §25.1.1 이 보류해 둔 후보이고, 「스프라이트가 오면 판단한다」는
조건이 §25.41.7 에서 풀렸기 때문이다.

**그 판단이 착수 직전에 뒤집혔다.** 통합자가 실물 파츠를 다시 보고 정했다.

| | 왜 |
| --- | --- |
| 실물에 `hair.png` 가 **없다** | 규약(§25.41.1)이 정한 파일 여섯에 머리카락이 없고, `head.png` 에 **그려져 들어 있다**. 뗄 그림이 없다 |
| 파츠 · 노드 수를 **안 늘린다** | §25.32 의 실측표가 「파츠 여섯 + 무기」에 대한 것이다. 일곱째를 늘리면 그 표가 낡는다 |

**그래서 머리카락도 가슴과 같은 장치를 쓴다 — 파츠 스프라이트의 UV 워프.**
셰이더 한 벌을 둘이 나눠 쓴다.

> **다만 추상을 남긴다.** `MorphAnchor` 는 「어느 파츠의 어디에 붙는가」를 자료로 들고 있어서,
> 나중에 `hair.png` 가 오면 **앵커의 `part` 를 새 파츠로 바꾸는 것만으로** 갈아탈 수 있다.
> 계수와 마스크는 그대로 남는다.

### 31.2.2 왜 프래그먼트 셰이더인가 — **버텍스로는 원천적으로 안 된다**

파츠 그림은 **사각형 하나**로 그려진다(`draw_texture_rect`). 버텍스 셰이더로는
**네 모서리밖에 못 움직인다** — 국소 부풀림이 안 나온다.
격자를 잘게 나눈 `MeshInstance2D` 로 바꾸면 되지만 §25.32 의 비용표를 전부 다시 재야 한다.

**UV 를 프래그먼트에서 휘면** 노드가 안 늘고, `gl_compatibility`(WebGL2)에서 그대로 돌고,
실측표가 안 낡는다.

### 31.2.3 ★ 얼굴을 뭉개지 마라 — **마스크가 자료여야 하는 이유**

머리 앵커의 감쇠 반경이 얼굴까지 닿으면 **이목구비가 녹는다.** 반경만으로는 못 막는다 —
머리카락은 정수리와 뒤통수에 있고 얼굴은 그 아래 앞쪽에 있어서, **거리로는 안 갈리고
방향으로 갈린다.**

그래서 앵커가 **영역 마스크**를 자료로 갖는다.

| 자료 | 무엇 |
| --- | --- |
| `centre` · `radius` | 타원 감쇠 (파츠 지역 좌표, `+y` 위) |
| `mask_normal` · `mask_offset` · `mask_feather` | **반평면 게이트.** `dot(p, n) ≥ offset` 인 쪽만 휜다 |

**이 둘이 곱해진다.** 머리는 「정수리 쪽 반평면」으로 얼굴을 통째로 잘라 낸다.
자료라서 **검사가 되고**(테스트가 얼굴 위치의 가중치가 0 임을 단언한다),
**그림이 바뀌어도 코드가 안 바뀐다** — §25.13.1 의 다섯 번째를 여기서 막는다.

## 31.3 배선

```
        AnimFeatures(t)
              │
     ┌────────┴──────────────┐
     │                       │
  CharPose                SoftDrive   ← 클립 한 바퀴를 표본해 하모닉으로 (셋업 때 한 번)
  (파츠 여섯 트랜스폼)          │
     │                    SoftBody    ← 해석적 감쇠진동 (ω, ζ)
     │                       │
     │                  MorphState    ← 앵커별 변위 · 눌림. **순수 자료. 셰이더 없이 테스트된다**
     │                       │
     └── CharPartsView ◄─────┘
              │
        CharPartSprite → char_morph.gdshader (uniform)
```

**자리표시자 도형과 진짜 그림이 갈리는 자리는 `CharPartsView._make_part()` 하나다.**
모핑은 **그림 쪽에만 붙는다** — 도형에는 UV 가 없다. 갈래를 새로 만들지 않는다.

| 파일 | 무엇 |
| --- | --- |
| `src/core/char_anim/soft_body.gd` | `SoftBody` — ω · ζ, 이득 · 위상지연 · 충격 응답. **해석해만 있다** |
| `src/core/char_anim/soft_drive.gd` | `SoftDrive` — 클립 한 바퀴의 하모닉. `from_clip()` 이 이산 푸리에로 뽑는다 |
| `src/core/char_anim/morph_anchor.gd` | `MorphAnchor` — 중심 · 반경 · 마스크 · 응답 계수. `weight_at()` |
| `src/core/char_anim/morph_rig.gd` | `MorphRig` — 인물 한 벌의 앵커 목록과 `strength`. **0 이면 완전히 꺼진다** |
| `src/core/char_anim/morph_state.gd` | `MorphState` — 앵커별 변위 · 눌림. 순수 자료 |
| `src/entities/character/char_morph.gdshader` | UV 워프. 앵커 최대 둘 |

## 31.4 미리 박힌 판단 (통합자가 정했다 — 이 레인이 안 뒤집는다)

| 물음 | 확정 | 근거 |
| --- | --- | --- |
| 적분기 | **안 쓴다. 해석해** | §25.3 의 셋을 잃는다 |
| 머리카락 일곱째 파츠 | **지금은 안 뗀다** (추상은 남긴다) | 실물에 `hair.png` 가 없다 |
| 가슴과 머리카락 | **같은 장치 — UV 워프** | 셰이더 한 벌을 둘이 쓴다 |
| 버텍스 셰이더 | **안 된다. 프래그먼트** | `Sprite2D` 는 네 점이다 |
| 파츠 · 노드 수 | **안 늘린다. 여섯 그대로** | §25.32 의 실측표가 낡으면 안 된다 |
| 진폭 상한 | 정지 시 최대 변위 ≤ 파츠 **반크기의 12 %** | §25.29 |
| 켜고 끄기 | **인물마다 자료값. 0 이면 지금 화면과 픽셀 단위로 같다** | §25.40 |
| 좌표계 | 코어는 `+y` 위. 변환은 `CharPose.canvas_transform()` 한 곳만 | §25.2.1 |
| 미학 판정 | **흔들림이 동작을 읽는 데 방해가 되면 진 것이다** | §25.22 |

## 31.5 검증 — **이 레인이 조용히 틀릴 수 있는 자리 셋**

§25.13 이 열거한 모양들이 이 작업에서 어떻게 나타나는지 미리 적는다.

### 31.5.1 ★ 해석해를 **수치 적분과 대조한다** — 이 작업의 정직성

닫힌 형태가 맞다는 것을 **자기가 쓴 값으로 검사하면 늘 통과한다**(§25.13.2).
그래서 테스트 안에서 **작은 RK4 적분기를 돌린다.**

```
x'' + 2ζω x' + ω² x = A Ω² sin(Ωt)      를 0 에서 여러 주기 돌려 정상상태에 들어간 뒤,
해석해가 낸 값과 같은가.
```

**적분기는 테스트 안에만 있다.** 제품 코드에 들어가는 순간 §25.3 의 셋을 잃는다.

### 31.5.2 GIF 이음매 — **물리를 얹은 뒤에도**

`sample(0)` 과 `sample(한 바퀴)` 가 같아야 한다(§25.3.2). 물리가 같은 주파수에
위상만 옮기므로 **수학적으로는 보장되지만**, 하모닉을 뽑을 때 정수가 아닌 성분이
섞이면 깨진다. **재서 단언한다.**

### 31.5.3 꺼짐이 **진짜 꺼짐**인가

`strength = 0` 이면

- `MorphState` 의 변위가 **정확히** `Vector2.ZERO` (근사가 아니라 등식)
- `CharPartSprite` 에 **셰이더 재질이 아예 안 붙는다** — 붙여 놓고 0 을 넣는 것과 다르다.
  안 붙어야 그리는 경로가 지금과 **같은 경로**이고, 그래야 픽셀이 같다
- 그리는 사각형에 **여백(pad)이 안 붙는다** (아래 §31.6.2)

## 31.6 실제로 밟은 함정

> 이 절은 작업하면서 채운다. **비어 있으면 아직 아무것도 안 만든 것이다.**

### 31.6.1 `paint_into()` 로 합쳐 그리면 모핑이 안 걸린다

`merged` 모드(§25.32)는 파츠 여섯을 **뷰의 캔버스에 직접 찍는다.** 재질은 그리는
`CanvasItem` 의 것이라 **파츠의 재질이 안 쓰인다.** 벤치 전용 경로이므로 지금은 막지 않고
문서에 적는다 — 벤치가 재는 것은 「노드를 합치면 빨라지나」이지 모핑이 아니다.

### 31.6.2 밀려난 살이 **사각형 밖으로 못 나간다**

파츠 그림은 **알파 경계상자로 딱 잘려 있다**(§25.41.2). 그 사각형 그대로 그리면
부풀린 살이 **변에서 잘린다.** 그래서 모핑이 켜진 파츠만 사각형을 `pad` 만큼 넓히고,
셰이더가 UV 를 **되돌려 매핑**해 그림이 원래 크기로 남게 한다.

**꺼져 있으면 여백도 없다** — 그래야 §31.5.3 의 「픽셀 단위로 같다」가 성립한다.

### 31.6.3 그림이 왼쪽을 보므로 **파츠 지역 좌표와 텍스처 좌표가 뒤집혀 있다**

§25.41.9 대로 뿌리가 자리를 뒤집고 파츠가 그림을 **되뒤집는다**(`CharPartSprite.mirror`).
그래서 `mirror` 인 파츠에서는 **파츠 지역 `+x` 가 텍스처의 `−u`** 다.
앵커를 파츠 지역 좌표로 적어 두었으므로 **UV 로 옮길 때 그것을 봐야 한다.**

빌려 쓴 손(`CharSkin.borrowed`)은 여기에 앵커가 없다 — 그래서 이 레인은 그 경우를 안 만난다.
