# 29. 효과음

> **상태: 배치 층 확정 · 합성 층 프로토타입.**

> 그래서 지금은 **엔진 합성 + CC0 재료**로 간다. 퀄리티를 올릴 때 아래층만 갈아 끼운다.

## 29.1 소리는 UI 와 정반대 성질이다

UI 는 열다섯 개를 한 장에 늘어놓으면 30초에 훑힌다.
**소리는 직렬이라 열다섯 개면 열다섯 번 들어야 한다.**

그래서 UI 레인이 쓴 "많이 만들고 고르게 한다" 가 여기서는 안 통한다.
판정 한 번의 단가가 열 배 이상 비싸다.

**해결: 판정이 필요한 것과 아닌 것을 가른다.**

| 층 | 무엇 | 취향인가 | 비용 |
| --- | --- | --- | --- |
| **어디서 나나** (배치) | 타격 시점 · 발 디딤 프레임 · 팝업 열림 | **아니다.** 코드가 이미 안다 | 일의 대부분 · **판정 0** |
| **무엇이 나나** (음색) | 금속인가 나무인가, 밝은가 둔한가 | **그렇다.** 사용자가 듣고 정한다 | 최소로 줄인다 |

**이 문서의 §29.2~§29.4 는 판정 0 이다.** 사용자가 들어 볼 것은 §29.8 한 파일뿐이다.

## 29.2 계약 — 세 층으로 가른다

교체가 진짜로 한 줄이 되려면 층이 갈려 있어야 한다.

```
사건        SfxEvent.HIT_LANDED / BREAK_STAGGER / PANEL_OPENED ...
             ↑ 배치 층. 나중에 안 바뀐다. 다른 레인 코드가 여기까지만 안다
             ↓
소리 요청    SfxRequest { material, weight, seed, kind }
             ↑ 계약. 나중에 안 바뀐다
             ↓
소리 원천    SfxSynth (지금)  /  CC0 샘플 (다음)  /  생성물 (나중)
             ↑ 여기만 갈아 끼운다
```

### 왜 가운데가 필요한가

**가운데 계약이 없으면 "교체" 가 재작성이 된다.**
사건마다 `res://assets/audio/hit_sword_02.ogg` 같은 경로가 박히면,
원천을 바꿀 때 사건 수만큼 손봐야 한다. 사건은 40개가 넘는다.

### 호출하는 쪽은 파일 이름을 모른다

전투 코드는 이렇게만 말한다.

```gdscript
Sfx.play(SfxEvent.Kind.HIT_LANDED, weapon.cells)
```

**인자가 둘이다.** 무슨 일이 일어났는가와, 얼마나 무거운가.
재질도 파일 이름도 전투 코드에 없다 — `hit_sword_02.ogg` 라는 문자열은 어디에도 없고,
"금속" 이라는 단어조차 없다. 그건 `SfxCatalog` 표가 정한다.

### 아래층은 무음이어도 배치는 끝난다

`Sfx.set_enabled(false)` 면 `play()` 가 `false` 를 돌려주고 아무 소리도 안 난다.
**배치 코드는 그대로 돌아간다.** 자리가 없어 못 낼 때도 조용히 버린다 —
**소리 때문에 게임 로직이 멈추는 일은 없어야 한다**는 것이 이 층의 유일한 책임이다.

그래서 **음색 판정을 기다리지 않고 배치를 먼저 끝낼 수 있다.**

## 29.4 무게 축 — 넷을 손으로 만들지 않는다

### 이 저장소에서 두 번 통한 수법

- 애니메이션 레인은 무기 넷을 손으로 안 만들고 **관성에서** 뽑았다
- 전투 레인은 한 방 무게를 **부피에서** 끌어냈다

소리도 같다. **무게 1~4 를 넣으면 기본 주파수 · 감쇠 길이 · 저역 차단이 같이 움직인다.**

### 축 하나 — 관성 시간

애니메이션 레인의 시간 법칙을 그대로 빌린다.

```
질량   m  ∝ c                        (c = 칸 수, 1..4)
길이   L  = 52 · c^0.30
관성   I  = ⅓ m L²  ∝ c^1.60
시간   T  ∝ √I      ∝ c^0.80
```

**빌린 것이 아니라 같은 함수다.** `src/core/char_anim/char_weapon.gd` 에
`time_scale()` 이 이미 있고, 값은 `1.000 / 1.741 / 2.408 / 3.031` 이다.
`test_sfx_voice.gd` 가 우리 `weight_scale()` 을 이 네 값과 직접 대조한다 —
애니메이션 레인이 지수를 바꾸면 소리 테스트가 깨진다.

**휘두르기 전체 길이는 1칸 0.710초 → 4칸 2.217초, 즉 3.12배다.**
`c^0.80` 의 3.03배와 3 % 차이가 나는데, **이건 오차가 아니라 설명이 된다** —
휘두르기 전체는 `예비 + 타격 + 멈춤 + 회복` 이고, 이 중 **멈춤(hitstop)만
`c^0.80` 이 아니라 칸 수에 선형**이다 (`hold_seconds() = 0.02 + 0.035*(c-1)`).
나머지 셋만 `pace` 로 곱해진다.

**소리는 멈춤이 없으므로 순수하게 `c^0.80` 을 쓴다.**

### 세 값이 한 축에서 나온다

```gdscript
scale(c) = pow(c, 0.80)          # 1.00 / 1.74 / 2.41 / 3.03

감쇠 시간   tau(c) = tau1 * scale(c)      # 무거우면 길게 운다
기본 주파수  f0(c)  = f1   / scale(c)      # 무거우면 낮다
저역 차단   fc(c)  = fc1  / scale(c)      # 무거우면 둔하다
```

### 왜 f0 와 tau 가 정확히 반비례인가 — 임의로 정한 것이 아니다

`f0(c) × tau(c) = f1 × tau1 = 상수` 다.
이건 **울림 안의 진동 횟수가 무게와 무관하게 같다**는 뜻이고,
물리에서 **감쇠비(damping ratio)가 크기가 아니라 재질의 성질**이라는 사실 그대로다.

큰 종과 작은 종은 **음높이와 울림 길이가 같이 변하지, 진동 횟수는 안 변한다.**
그래서 축이 하나로 충분하다. 넷을 따로 맞추면 이 관계가 깨지고,
**"같은 무기의 크고 작은 버전" 이 아니라 "서로 다른 네 물건" 으로 들린다.**

### 재질은 직교축이다

무게가 크기라면 재질은 **무엇으로 만들어졌나**다. 재질이 정하는 것은 넷이다.

| 파라미터 | 뜻 | 금속 | 나무 | 살 | 돌 | 천 |
| --- | --- | --- | --- | --- | --- | --- |
| `tone_ratio` | 음 대 잡음 비율 | 높다 | 중간 | 거의 0 | 낮다 | 0 |
| `partials` | 배음 개수 | 많다 | 적다 | — | 적다 | — |
| `inharmonicity` | 배음이 정수배에서 벗어난 정도 | 크다 | 작다 | — | 크다 | — |
| `damping` | 감쇠비 (울림 길이 배수) | 길다 | 짧다 | 아주 짧다 | 짧다 | 아주 짧다 |
| `brightness` | 기준 저역 차단 배수 | 밝다 | 중간 | 둔하다 | 중간 | 둔하다 |

**무게 축과 재질 축이 곱해진다.** 재질 5 × 무게 4 = 20 가지가 손으로 만든 값 없이 나온다.

## 29.5 합성 — `AudioStreamWAV`, `AudioStreamGenerator` 가 아니다

### 왜 미리 굽는가

| | `AudioStreamGenerator` | **`AudioStreamWAV` (채택)** |
| --- | --- | --- |
| 방식 | 매 프레임 버퍼를 밀어 넣는다 | 시작할 때 샘플을 계산해 둔다 |
| 웹 단일 스레드 | **버퍼가 굶으면 뚝뚝 끊긴다** | 런타임 비용 0 |
| 그 뒤 재생 | 특수 처리 필요 | 평범한 `AudioStreamPlayer` |

우리는 `gl_compatibility` · **단일 스레드**로 제출한다
([`09-art-sound.md`](09-art-sound.md) §9.3.3 에서 배포본이 single-threaded 로 뜨는 것을 확인했다).
**프레임 하나가 늦으면 소리가 끊기는 구조를 웹에 올리지 않는다.**

굽는 비용은 시작할 때 한 번이고, §29.6 에 실측이 있다.

### 신호 사슬 — 숫자 네댓 개다

```
잡음 한 줌  ──┐
             ├─→ 아주 빠른 어택 ─→ 지수 감쇠 ─→ 저역 통과 ─→ 소프트 클립
음 하나    ──┘     (1~3 ms)        (tau)       (1극, fc)
```

1. **잡음** — 씨(seed)로 고정된 흰 잡음. 부딪히는 순간의 "탁"
2. **음** — `f0` 기본음 + 재질이 정한 배음들. 물체의 울림
3. **어택** — 1~3 ms 선형 상승. 이보다 길면 타격이 아니라 "왔다" 로 들린다
4. **감쇠** — `exp(-t/tau)`. 무게가 정한다
5. **저역 통과** — 1극 IIR, `fc`. 무거울수록 둔해진다
6. **피치 하강** — sfxr 의 slide 에 해당. 무거울수록 크게 떨어뜨린다

### sfxr 계보를 참고한다

파라미터 20개짜리 작은 신디사이저이고 퍼블릭 도메인 재구현이 여럿 있다.
**파라미터 셋이 2007년부터 검증돼 있으므로 처음부터 설계하지 않는다.**
자세한 계보와 라이선스는 §29.9.6.

우리가 sfxr 과 다른 점은 하나다. **sfxr 은 20개 노브를 손으로 돌린다.
우리는 노브를 `(재질, 무게)` 둘로 줄이고 나머지를 §29.4 축에서 계산한다.**

## 29.6 변주 — 합성이라 공짜다

**5타가 1.4초 안에 나간다** (전투 레인 실측). 같은 소리 다섯 번이면 기계로 들린다.

| --- | --- |
| 파일 | 변주 파일을 여러 개 만들어야 한다. 용량 × N |

```
감쇠     ± 12%
잡음 파형   완전히 다른 난수열
```

### 29.7.1 축이 실제로 세 값을 같이 미는가 — **민다**

| 무게 | 배수 `c^0.80` | 기본 Hz | 감쇠 ms | 차단 Hz | 길이 ms | **진동 횟수** |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1.000 | 620.0 | 57.0 | 6000 | 228.0 | **35.34** |
| 2 | 1.741 | 356.1 | 99.2 | 3446 | 397.0 | **35.34** |
| 3 | 2.408 | 257.5 | 137.3 | 2492 | 549.1 | **35.34** |
| 4 | 3.031 | 204.5 | 172.8 | 1979 | 691.2 | **35.34** |

**진동 횟수가 소수점 둘째 자리까지 같다.** §29.4 의 `f0 × tau = 상수` 가 성립한다는 뜻이고,
넷이 "서로 다른 네 물건" 이 아니라 "같은 물건의 네 크기" 로 들린다는 근거다.
`test_sfx_voice.gd` 가 이 불변량을 회귀 테스트로 잡아 둔다.

### 29.7.2 소리 길이가 동작 길이와 맞는가 — **맞는다**

| 칸 | 휘두르기 전체 | 타격음 꼬리 | 비율 |
| --- | --- | --- | --- |
| 1 | 0.710 s | 0.228 s | 32.1 % |
| 2 | 1.256 s | 0.397 s | 31.6 % |
| 3 | 1.752 s | 0.549 s | 31.3 % |
| 4 | 2.217 s | 0.691 s | **31.2 %** |

**비율이 1 % 안에서 일정하다.** 4칸 휘두르기 2.22초에 0.69초짜리 소리가 붙는다.
둘 다 `c^0.80` 을 쓰기 때문에 자동으로 맞는다 — 맞춘 것이 아니다.

### 29.7.3 겹침 — **금속 4칸만 넘친다**

체인 타 간격은 **0.35초**다 (`break_tuning.gd` 의 `seconds_per_hit`).
5타 1.40초 · 10타 3.15초 · 12타 3.85초가 전부 이 값에서 나온다.

| 재질 | 무게 | 꼬리 | 간격 대비 | 판정 |
| --- | --- | --- | --- | --- |
| 금속 | 1 | 228 ms | -122 ms | 안 겹침 |
| **금속** | **4** | **691 ms** | **+341 ms** | **겹침** |
| 살 | 4 | 255 ms | -95 ms | 안 겹침 |
| 나무 | 4 | 309 ms | -41 ms | 안 겹침 |

**4칸 금속만 다음 타를 341 ms 물고 들어간다.** 실제로 5타를 섞어 보면:

| 무게 | 단타 피크 | 5타 합 피크 | 증가 |
| --- | --- | --- | --- |
| 1 | 0.399 | 0.399 | 1.00배 |
| 4 | 0.500 | 0.524 | **1.05배** |

**5 % 만 올라간다.** 꼬리가 이미 지수적으로 죽은 뒤에 다음 타가 들어오기 때문이다.
**겹치기는 하지만 뭉개지지는 않는다** — 이건 오히려 무거운 무기의 두께로 들릴 여지가 있다.
**들어 보고 정할 문제이므로 §29.8.1 데모 파일의 두 번째 구간에 넣었다.**

### 29.7.4 동시 발음 — **네 개부터 넘친다. 리미터로 받는다**

| 겹친 수 | 피크 | 판정 |
| --- | --- | --- |
| 1 | 0.469 | 여유 |
| 2 | 0.657 | 여유 |
| 3 | — | 여유 |
| **4** | **1.100** | **넘침** |
| 8 | 1.459 | 넘침 |

**처음에 `PEAK_TARGET` 을 0.80 으로 두었더니 둘만 겹쳐도 1.30 이었다.**
0.50 으로 내려 셋까지 확보하고, 그 위는 `Sfx` 버스의 `AudioEffectLimiter`
(천장 -1 dB)가 받는다. 리미터는 엔진 C++ 이라 웹 단일 스레드에서도 싸다.

보이스는 12개로 잡았다. 넘치면 **조용히 버린다** — 소리 때문에 게임이 멈추면 안 된다.

### 29.7.5 반복이 기계처럼 들리나 — **변주가 실제로 다른 파형이다**

| 씨 | 기본 Hz | 길이 ms | 기준과의 파형 차이 |
| --- | --- | --- | --- |
| 없음 | 257.5 | 549.1 | **0 % (다섯 번 모두 같은 배열)** |
| 1 | 252.2 | 519.6 | 139.9 % |
| 2 | 263.7 | 551.6 | 149.5 % |
| 3 | 257.4 | 577.4 | 38.9 % |
| 4 | 269.8 | 520.5 | 154.9 % |
| 5 | 259.3 | 593.2 | 125.3 % |

**변주끼리도 최소 113.6 % 다르다.** 기준과만 다르고 서로 같으면 소용없으므로
쌍끼리도 잰다. 피치는 ±6 % 안, 길이는 520~593 ms 안에서 흔들린다.

**드는 비용은 씨 하나다.** 파일 방식이면 변주 파일을 다섯 벌 만들어야 한다.

### 29.7.6 UI 가 전투에 묻히나 — **자리를 나눠서 안 묻힌다**

| 사건 | 길이 | 중심 Hz | RMS |
| --- | --- | --- | --- |
| 타격 | 397 ms | 489 | 0.068 |
| 쓰러짐 | 309 ms | **183** | 0.090 |
| 눌림 | 31 ms | **756** | 0.062 |
| 확인 | 157 ms | **957** | 0.075 |
| 커서 올림 | 28 ms | 840 | 0.028 |

**음량이 아니라 주파수 자리로 나눴다.** 전투는 183~489 Hz, UI 는 756~957 Hz 다.
UI 는 `SfxVoice` 가 한 옥타브 올리고 길이를 30분의 1 로 줄인다.
음량 차이는 -3.2 dB 뿐인데도 안 묻히는 이유가 이것이다 — **음량을 더 깎으면
조용한 장면에서 UI 가 안 들리게 되므로, 자리로 나누는 쪽이 옳다.**

### 29.7.7 웹에서 시작할 때 내는 값 — **113 ms, 내려받는 용량 0**

| 항목 | 값 |
| --- | --- |
| 사건 50개 전수 굽기 | **113 ms** (시작할 때 한 번) |
| 사건당 평균 | 2.26 ms |
| 가장 비싼 사건 하나 | 8.67 ms (타격, 4칸 금속) |
| 실행 중 메모리 (PCM) | 287 KB |
| 변주까지 포함한 실제 warm | **184 ms · 53벌 · 297 KB** |
| **웹 빌드에 추가되는 다운로드 용량** | **0 KB** |

**다운로드가 0인 것이 합성의 가장 큰 실익이다.**
`09-art-sound.md` §9.3.3 기준 `index.pck` 는 1.13 MB 이고 그 대부분이 폰트다.
CC0 샘플로 가면 여기에 2~4 MB 가 붙는다 (§29.9).

**샘플레이트를 44100 에서 22050 으로 내려 굽는 시간을 535 ms → 113 ms 로 줄였다.**
근거는 취향이 아니다 — 우리 저역 차단은 가장 밝을 때도 6000 Hz 고 최고 배음은
5538 Hz 라 둘 다 나이퀴스트(11025 Hz) 아래다. **들리지 않는 대역을 계산하고 있었다.**

### 29.7.8 아직 못 잰 것 — 정직하게

| 못 잰 것 | 왜 | 어떻게 재야 하나 |
| --- | --- | --- |
| **브라우저 실제 동시 발음** | 헤드리스는 Dummy 오디오 드라이버라 믹싱을 안 한다 | 웹 빌드를 올리고 브라우저에서 재야 한다 |
| **실제 오디오 지연** | 같은 이유 | 브라우저 필요 |
| 굽는 시간의 웹 실측 | 위 113 ms 는 **데스크톱 GDScript** 값이다 | wasm 은 대개 더 느리다. 실측 전에는 이 값을 웹 값으로 쓰지 않는다 |

**위 113 ms 를 "웹에서도 113 ms" 라고 읽으면 안 된다.**
필요하면 로딩 화면에서 `SfxBank.warm()` 을 부르고 그 반환값을 그대로 보고하게 해 두었다.

## 29.8 사용자에게 들려줄 것

### 29.8.1 파일 하나

**소리는 직렬이라 여러 파일을 보내면 판정이 비싸진다.** 열다섯 개를 보내면
열다섯 번 들어야 한다. 그래서 **한 파일에 다 넣었다.**

```bash
godot --headless --path . -s res://tools/render_sfx_demo.gd
```

| | |
| --- | --- |
| 경로 | `docs/design/samples/sfx/sfx_demo.wav` |
| 길이 | **14.38 초** (15초 안쪽) |
| 형식 | 22050 Hz 모노 16비트 · 619 KB |

| 시각 | 구간 | 무엇을 판정하나 |
| --- | --- | --- |
| 0.00 s | 무게 1 부터 4 (금속 타격) | **축이 귀에도 계단으로 들리나** |
| 3.68 s | 5타 체인 (무게 3, 간격 0.35초) | **§29.7.3 의 겹침이 실제로 뭉개지나** |
| 6.23 s | 대조 A — 변주 **없음** | 다섯 번이 기계로 들리나 |
| 8.78 s | 대조 B — 변주 **있음** | 씨 하나로 충분한가 |
| 11.33 s | 재질 다섯 (무게 2 고정) | **음색 판정 — 여기가 취향이다** |

**A 와 B 를 붙여 둔 것이 핵심이다.** 변주는 따로 들으면 차이를 못 느끼고
**바로 이어서 들어야 드러난다.**

파일은 **전체를 한 배수로** 0.90 까지 올렸다. 무게 사이 · 재질 사이의 음량 관계는
그대로 보존된다. 게임 안에서는 이렇게 하지 않는다 — 거기선 동시 발음 여유를 남긴다 (§29.7.4).

### 29.8.2 만져 보는 화면

파일은 한 번 듣는 것이고, **화면은 만져 보는 것이다.**

```bash
godot --path . res://src/proto/sfx/sfx_lab.tscn
```

| 무엇 | 어디 |
| --- | --- |
| 무게 슬라이더 1~4 | 숫자 키 `1`~`4` 로도 바뀐다 |
| 재질 · 종류 · 음정 방향 | 표를 벗어나 축을 직접 만진다 |
| 사건 50개 목록 | 묶음별로 접혀 있다. 누르면 그 소리가 난다 |
| **파형 그림** | **체인 간격 0.35초에 세로선.** 꼬리가 선을 넘는지 눈으로 보인다 |
| 숫자 표시 | 기본 Hz · 감쇠 · 차단 · 길이 · **진동 횟수** |
| 5타 체인 (변주 있이 / 없이) | 대조를 그 자리에서 |

**파형을 그린 이유:** 소리는 직렬이라 판정이 비싼데, **길이와 봉우리는 보면 안다.**
들어야만 아는 것(음색)과 보면 아는 것을 갈라 두면 귀를 쓰는 횟수가 준다.

Kenney 지원 페이지 원문: 에셋은 퍼블릭 도메인(CC0)이고 표시는 필수가 아니며 로고 사용만 금지된다 `[확인]`.

### 29.9.3 배제한 것 — **"무료" 와 "CC0" 는 다르다**

| 소스 | 실제 라이선스 | 왜 배제 |
| --- | --- | --- |
| **Sonniss GDC 번들** | **독자 상용 라이선스** `[확인]` | **CC0 가 아니다.** 무료·무표시지만 저작권 미양도. **27.5 GB 전부 WAV** |
| **BBC Sound Effects** | RemArc — 연구·교육·개인 한정 `[부분확인]` | **웹 공개 배포는 회색지대.** 제출물에 리스크 |
| CC-BY-SA 계열 (`Punches, hits, swords...`) | CC-BY-SA 3.0 `[확인]` | **카피레프트 감염** |
| `Fleshy Fight Sounds` | **OGA-BY 3.0** `[확인]` | CC0 로 자주 오인됨. 표시 필수 |
| Pixabay | Pixabay Content License `[확인]` | 2019년 CC0 폐지. **CC0 로 적으면 오기** |
| Mixkit · ZapSplat CC0 | `[미확인]` | 약관 본문 접근 실패. 검증 못 한 것은 안 쓴다 |

**"무표시 무료" 와 "CC0" 를 같은 칸에 적지 않는다.** 제출물이라 표기가 틀리면 그 자체가 감점이다.

### 29.9.4 최소 구성안

```
Kenney Impact Sounds   0.76 MB   금속 · 나무 · 살
Kenney RPG Audio       0.92 MB   천 · 가죽
OGA 100 CC0 SFX #2     2.4  MB   흙 · 돌 · 발소리
─────────────────────────────
합계 약 4.1 MB / 280여 개 .ogg / 전부 CC0 무표시
```

**지금 합성이 0 KB 라는 것과 비교해야 한다.** `index.pck` 가 1.13 MB 인 프로젝트에
4.1 MB 를 얹는 결정이다 (`09-art-sound.md` §9.1 용량 예산 미정).
**웹 로딩이 이탈 지점이므로** (`01-constraints.md` §1.2) 전량이 아니라
**재질당 두세 개만 추리는 편이 낫다** — 무게와 변주는 어차피 엔진이 만든다.

### 29.9.5 증빙 관리

각 zip 의 `License.txt` 를 지우지 말고 보관하고, `CREDITS.md` 에
**소스명 · URL · 라이선스명 · 접근일자**를 남긴다. OGA 는 컬렉션 페이지에서
CREDITS.TXT 를 자동 생성해 준다. **Freesound 는 사운드별 URL 을 전부 남겨야 해서 가장 번거롭다.**

### 29.9.6 sfxr 계보 — 파라미터를 처음부터 설계하지 않는다

| 프로젝트 | 라이선스 | 파라미터 재사용 |
| --- | --- | --- |
| **jsfxr** | **Unlicense (퍼블릭 도메인)** `[확인]` | **의무 0. 주 참조로 삼기 좋다** |
| sfxr (DrPetter, 2007) | **MIT** `[확인]` | 22노브 원본. 고지만 남기면 된다 |
| rFXGen | zlib `[확인]` | ⚠ RNG 매크로 버그로 Hit/Hurt 가 square 를 못 만든다 |
| Bfxr | Apache-2.0 `[확인]` | 32노브. `overtones` · `bitCrush` 참고 가치 |
| **LMMS Sfxr 플러그인** | **GPL-2.0+** `[확인]` | **절대 베끼지 말 것 (감염)** |

**"sfxr SDL 포트가 GPL" 이라는 통설은 사실이 아니다** — 실제로 GPL 인 것은
LMMS 내장 플러그인뿐이고, 그건 MIT 가 허용하는 다운스트림 재라이선스다.

**우리가 sfxr 에서 실제로 가져온 것:** 신호 사슬의 순서(잡음/음 → 엔벨로프 →
슬라이드 → 저역 통과)와 **`p_freq_ramp` 가 항상 강하게 음수여야 타격으로 들린다**는
HIT/HURT 프리셋의 핵심. 이것이 우리 `pitch_drop` 이다.

**가져오지 않은 것:** 20개 노브를 손으로 돌리는 방식.
**우리는 노브를 `(재질, 무게)` 둘로 줄이고 나머지를 §29.4 축에서 계산한다.**

### 29.9.7 기성 Godot 애드온 — 참고만

`gdfxr` (MIT) · `GodotSfxr` (MIT) 둘 다 Godot 4 대응 `[확인]`.
`gdfxr` 은 **`.sfxr` 파일 하나가 약 100바이트**라 다운로드 용량이 사실상 0 이다.

**지금 도입하지 않는다.** 우리 요구는 sfxr 의 20노브 UI 가 아니라
**무기 칸 수 하나로 20가지가 나오는 축**이고, 그건 애드온이 안 해 준다.
다만 나중에 UI 소리를 늘릴 때는 재검토할 가치가 있다.

## 29.10 정직하게 알아 둘 것 — 합성은 사실적이지 않다

**합성은 사실적인 소리가 안 난다.** 숨기지 않고 적는다.

| 안 되는 것 | 이유 |
| --- | --- |
| 자갈 밟는 소리 | 수십 개 알갱이가 제각기 부딪히는 것 — 잡음 한 줌으로 안 된다 |
| 천 스치는 소리 | 시간에 따라 스펙트럼이 계속 변한다 — 지수 감쇠 하나로 안 된다 |
| 진짜 검의 배음 두께 | 실제 금속은 배음이 수십 개고 각각 다른 속도로 죽는다 |

**나오는 것은 양식화된, 아케이드 쪽으로 읽히는 소리다.**

**프로토타입에서는 그게 오히려 낫다.**
프로토가 필요한 전부는 **"지금 타격이 들어갔다" 가 애매하지 않은 것**이고,
양식화된 소리는 그걸 오히려 더 또렷하게 한다.
다만 이건 **제출 단계의 최종 음색이 아니다** — 사용자가 알고 판정해야 한다.

**교체 지점은 §29.2 의 아래층 한 곳이다.** 위 두 층은 그대로 둔다.
