# 29. 효과음

> **상태: 배치 층 확정 · 원천은 CC0 녹음물.**
> 프로토타입 단계에서는 **유료 서비스를 쓰지 않는다** (사용자 결정).
>
> **1판은 엔진 합성이었고 사용자가 물렸다** ("효과음 완전이상하다").
> 2판은 **CC0 녹음물 65개**로 간다. 합성은 지우지 않고 대비책으로 남겼다.
> 경위와 교훈은 §29.12.
>
> 상위 문서 [`09-art-sound.md`](09-art-sound.md) §9.5 의 "미정" 을 이 문서가 대체한다.

## 29.1 소리는 UI 와 정반대 성질이다

UI 는 열다섯 개를 한 장에 늘어놓으면 30초에 훑힌다.
**소리는 직렬이라 열다섯 개면 열다섯 번 들어야 한다.**

그래서 UI 레인이 쓴 "많이 만들고 고르게 한다" 가 여기서는 안 통한다.
판정 한 번의 단가가 열 배 이상 비싸다.

**해결: 판정이 필요한 것과 아닌 것을 가른다.**

| 층 | 무엇 | 취향인가 | 비용 |
| --- | --- | --- | --- |
| **어디서 나나** (배치) | 타격 시점 · 발 디딤 프레임 · 팝업 열림 | **아니다.** 코드가 이미 안다 | 일의 대부분 · **판정 0** |
| **무엇이 나나** (음색) | 금속인가 나무인가, 밝은가 둔한가 | **그렇다.** 사용자가 듣고 정한다 | 최소로 줄인다 |

**이 문서의 §29.2~§29.4 는 판정 0 이다.** 사용자가 들어 볼 것은 §29.8 한 파일뿐이다.

## 29.2 계약 — 세 층으로 가른다

교체가 진짜로 한 줄이 되려면 층이 갈려 있어야 한다.

```
사건        SfxEvent.HIT_LANDED / BREAK_STAGGER / PANEL_OPENED ...
             ↑ 배치 층. 나중에 안 바뀐다. 다른 레인 코드가 여기까지만 안다
             ↓
소리 요청    SfxRequest { material, weight, seed, kind }
             ↑ 계약. 나중에 안 바뀐다
             ↓
소리 원천    SfxSynth (지금)  /  CC0 샘플 (다음)  /  생성물 (나중)
             ↑ 여기만 갈아 끼운다
```

### 왜 가운데가 필요한가

**가운데 계약이 없으면 "교체" 가 재작성이 된다.**
사건마다 `res://assets/audio/hit_sword_02.ogg` 같은 경로가 박히면,
원천을 바꿀 때 사건 수만큼 손봐야 한다. 사건은 40개가 넘는다.

### 이 설계는 하루 만에 값을 했다

사용자가 합성을 물리고 CC0 파일로 가기로 했을 때, **바뀐 것은 아래층뿐이었다.**
사건 50개도 계약도 표도 한 줄 안 고쳤다 (§29.5 의 비교표).

**가운데 계약이 없었으면 "교체" 가 재작성이었다.**

### 호출하는 쪽은 파일 이름을 모른다

전투 코드는 이렇게만 말한다.

```gdscript
Sfx.play(SfxEvent.Kind.HIT_LANDED, weapon.cells)
```

**인자가 둘이다.** 무슨 일이 일어났는가와, 얼마나 무거운가.
재질도 파일 이름도 전투 코드에 없다 — `hit_sword_02.ogg` 라는 문자열은 어디에도 없고,
"금속" 이라는 단어조차 없다. 그건 `SfxCatalog` 표가 정한다.

### 아래층은 무음이어도 배치는 끝난다

`Sfx.set_enabled(false)` 면 `play()` 가 `false` 를 돌려주고 아무 소리도 안 난다.
**배치 코드는 그대로 돌아간다.** 자리가 없어 못 낼 때도 조용히 버린다 —
**소리 때문에 게임 로직이 멈추는 일은 없어야 한다**는 것이 이 층의 유일한 책임이다.

그래서 **음색 판정을 기다리지 않고 배치를 먼저 끝낼 수 있다.**

### 29.3.9 배치 층이 열어야 할 신호 둘

읽어 보니 **아직 없는 훅이 둘** 있다. 지금 만들지 않는다 — 전투 레인이
"쓰지도 않는 신호를 미리 굳히지 않는다" 고 명시했다 (`28-combat.md` §28.20.23).

1. **무너짐 상태가 바뀌는 순간.** 지금은 화면이 `SparringBout.state()` 를 매 프레임
   폴링한다. 문턱을 넘는 순간을 알려면 프레임 간 차이를 보거나
   `ChainBreakOutcome.first_step_reaching(kind)` 로 **몇 번째 타에서 넘을지 미리** 계산해야 한다
2. **단추 눌림.** `ActionButton` 에 커스텀 신호가 없다. Godot 내장 `button_down` 을 쓰면 된다

**둘 다 소리 층이 여는 것이 아니라 해당 레인이 필요할 때 연다.** 이 문서는 자리만 표시해 둔다.

## 29.4 무게 축 — 넷을 손으로 만들지 않는다

### 이 저장소에서 두 번 통한 수법

- 애니메이션 레인은 무기 넷을 손으로 안 만들고 **관성에서** 뽑았다
- 전투 레인은 한 방 무게를 **부피에서** 끌어냈다

소리도 같다. **무게 1~4 를 넣으면 길이 · 주파수 · 저역 차단이 같이 움직인다.**

### 축 하나 — 관성 시간

애니메이션 레인의 시간 법칙을 그대로 빌린다.

```
질량   m  ∝ c                        (c = 칸 수, 1..4)
길이   L  = 52 · c^0.30
관성   I  = ⅓ m L²  ∝ c^1.60
시간   T  ∝ √I      ∝ c^0.80
```

**빌린 것이 아니라 같은 함수다.** `src/core/char_anim/char_weapon.gd` 에
`time_scale()` 이 이미 있고, 값은 `1.000 / 1.741 / 2.408 / 3.031` 이다.
`test_sfx_voice.gd` 가 우리 `weight_scale()` 을 이 네 값과 직접 대조한다 —
애니메이션 레인이 지수를 바꾸면 소리 테스트가 깨진다.

**휘두르기 전체 길이는 1칸 0.710초 → 4칸 2.217초, 즉 3.12배다.**
`c^0.80` 의 3.03배와 3 % 차이가 나는데, **이건 오차가 아니라 설명이 된다** —
휘두르기 전체는 `예비 + 타격 + 멈춤 + 회복` 이고, 이 중 **멈춤(hitstop)만
`c^0.80` 이 아니라 칸 수에 선형**이다 (`hold_seconds() = 0.02 + 0.035*(c-1)`).

### 녹음물에서는 리샘플 하나가 축 전체다

**합성일 때는 주파수와 감쇠를 따로 계산해서 `f0 × tau = 상수` 를 손으로 맞췄다.**
녹음물에서는 그게 필요 없다. **테이프를 느리게 돌리면 된다.**

```
리샘플 비율 = scale(c) = c^0.80
   길이   → scale 배
   주파수 → 1/scale 배
```

**`f0 × tau` 가 저절로 보존된다.** 큰 물체와 작은 물체의 관계가 원래 그렇기 때문이다 —
큰 종은 낮고 길게 울리고, 진동 횟수는 같다. 손으로 맞췄던 불변량이 공짜로 나온다.

여기에 두 가지를 더 얹는다.

| 무엇 | 왜 |
| --- | --- |
| **저역 통과** `BASE_CUTOFF × brightness / scale` | 무거울수록 둔하게. 리샘플만으로는 부족하다 |
| **꼬리 정형** 목표 길이까지 | 녹음의 어택과 몸통(앞 35 %)은 안 건드린다 |

**꼬리 정형에서 앞 35 % 를 남기는 것이 중요하다.** 거기까지 합성 엔벨로프로 덮으면
녹음을 쓰는 의미가 없어진다 — 다시 합성처럼 들린다.

### 물리인 것과 기호인 것을 가른다

**타격과 바람은 물리다.** 4칸 무기는 실제로 더 큰 물체이므로 리샘플로 늘이는 것이 맞다.

**UI 딸깍과 확인음은 물리가 아니라 기호다.** 사람이 그 높이로 들으라고 만든 소리다.
무게를 핑계로 피치를 내리면 설계된 신호가 망가진다.

**실제로 이걸로 사고가 났다** — §29.12.2 에 기록해 두었다.

### 재질은 직교축이다

무게가 크기라면 재질은 **무엇으로 만들어졌나**다. 재질은 **어느 폴더에서 재료를 꺼낼지**를
정하고, 저역 차단 배수(`brightness`)와 꼬리 길이 배수(`damping`)를 민다.

**재질 6 × 무게 4 = 24 가지가 손으로 맞춘 값 없이 나온다.**

## 29.5 원천 — CC0 녹음물

> **1판은 엔진 합성이었고 사용자가 물렸다.** 경위는 §29.12.1.
> 합성 코드는 지우지 않고 **대비책으로 남겨 두었다** (§29.10).

### 층이 갈려 있어서 아래만 바꿨다

§29.2 의 계약이 값을 한 지점이다. 원천을 통째로 갈아 끼웠는데
**전투 코드도 UI 코드도 사건 목록도 한 줄 안 바뀌었다.**

| 층 | 1판 (합성) | 2판 (CC0 파일) | 바뀌었나 |
| --- | --- | --- | --- |
| 사건 `SfxEvent` | 50개 | 50개 | **그대로** |
| 계약 `SfxRequest` | 재질+무게+씨 | 재질+무게+씨 | **그대로** |
| 표 `SfxCatalog` | 사건→요청 | 사건→요청 | **그대로** |
| 축 `SfxVoice` | 주파수·감쇠 계산 | 리샘플 비율·차단 계산 | 조금 (고역 통과 추가) |
| **원천** | **`SfxSynth`** | **`SfxLibrary`+`SfxSample`** | **전부** |

### 파이프라인

굽는 시점은 **개발 도구**와 **실행 시점** 둘로 나뉜다.

```
[개발 도구 · tools/build_sfx_library.py — 파이썬, 게임에 안 들어감]
  CC0 원본 .ogg
    → 모노 변환
    → 선행 무음 제거      ← 천은 앞에 64.7 ms 가 붙어 있었다
    → 22050 (천·바람은 44100) 로 리샘플
    → 피크 1.0 정규화     ← 원본 음량이 27.7 dB 벌어져 있었다
    → 1.5초로 자름
    → assets/audio/sfx/<재질>/<재질>_NN.wav  (커밋됨)

[실행 시점 · SfxRender — GDScript]
  .wav 읽기 (16비트 PCM)
    → 필요한 만큼만 자르기   ← 늘인 뒤 버리면 안 들릴 부분까지 계산하게 된다
    → 리샘플 (무게 축)       ← 물리인 것만. UI 는 건너뛴다
    → 저역 통과 (무게 축)
    → 고역 통과 (UI 만)      ← 전투 위로 밀어 올린다
    → 꼬리 정형
    → 피크 정규화 · 페이드
    → AudioStreamWAV
```

**왜 원본을 그대로 안 쓰고 다시 굽는가** — 이유 셋이 전부 실측이다 (§29.7.9).

### `AudioStreamGenerator` 가 아닌 것은 그대로다

미리 구워 두는 이유는 1판과 같다. 웹은 **단일 스레드**라 매 프레임 버퍼를 채우다
한 번 굶으면 소리가 뚝뚝 끊긴다. `AudioStreamWAV` 는 재생 시점 비용이 0 이다.

### wav 임포트를 PCM 으로 고정한다

Godot 4.7 의 wav 기본 임포트는 **QOA**(`compress/mode=2`)다.
그러면 `AudioStreamWAV.data` 에서 샘플을 못 꺼내 축을 못 먹인다.

```
[importer_defaults]
wav={ "compress/mode": 0 }
```

`project.godot` 에 박아 두었다. **이걸 지우면 다음 임포트부터 소리가 조용히 합성으로 떨어진다** —
실제로 그렇게 당했다 (§29.12.2). `test_sfx_library.gd` 가 이 설정을 직접 검사한다.

### 29.7.1 축이 녹음물에도 먹히는가 — **먹힌다**

| 무게 | 배수 `c^0.80` | 저역 차단 | 길이 | 휘두르기 대비 |
| --- | --- | --- | --- | --- |
| 1 | 1.000 | 6000 Hz | 89.9 ms | 12.7 % |
| 2 | 1.741 | 3446 Hz | 156.5 ms | 12.5 % |
| 3 | 2.408 | 2492 Hz | 216.5 ms | 12.4 % |
| 4 | 3.031 | 1979 Hz | 272.5 ms | **12.3 %** |

**휘두르기 대비 비율이 0.4 %p 안에서 일정하다.** 소리와 동작이 같은 지수를 쓰기 때문에

**이건 손해가 아니다** — 겹침이 사라졌다 (§29.7.3).

**피크가 전부 같다.** 파일이 음량을 정하지 않는다는 뜻이다 (§29.7.9).

### 29.7.3 겹침 — **이제 하나도 안 겹친다**

체인 타 간격은 **0.35초**다 (`break_tuning.gd` 의 `seconds_per_hit`).

**1판에서는 4칸 금속이 341 ms 물고 들어갔다. 지금은 78 ms 남는다.**
5타를 실제로 섞어도 합 피크가 **단타와 완전히 같다**(1.00배, 무게 1~4 전부).

| 겹친 수 | 피크 | 판정 |

| 1 | 0.469 | 여유 |

보이스는 12개, 넘치면 **조용히 버린다**.

### 29.7.6 UI 가 전투에 묻히나 — **아래를 깎아서 자리를 만든다**

**1판에서는 합성이라 기본 주파수를 두 배로 올려 자리를 나눴다.
녹음물은 스펙트럼을 우리가 못 정한다.** 그래서 방법을 바꿨다 — **아래를 깎는다.**

| 사건 | 길이 | 중심 Hz | RMS |
| --- | --- | --- | --- |
| 쓰러짐 | 309 ms | **40** | 0.100 |
| 게이트 입장 | 218 ms | **41** | 0.142 |
| 타격 | 157 ms | **374** | 0.062 |
| 확인 | 157 ms | **536** | 0.115 |
| 취소 | 157 ms | **3268** | 0.041 |
| 눌림 | 31 ms | **3299** | 0.048 |
| 커서 올림 | 28 ms | **3467** | 0.021 |

**전투 40~374 Hz / UI 536~3467 Hz 로 갈렸다.**
`TICK` 은 900 Hz, `TONE` 은 550 Hz 에서 아래를 깎는다 (`SfxVoice.highpass_hz`).
`TONE` 을 덜 깎는 이유는 몸통을 남겨야 음정으로 들리기 때문이다.

### 29.7.7 웹에서 시작할 때 내는 값

| 항목 | 값 |
| --- | --- |
| 사건 50개 전수 (첫 읽기 포함) | **75.9 ms** |
| 두 번째 (파일 캐시 후) | 43.3 ms |
| 사건당 평균 | 1.52 ms |
| 가장 비싼 사건 하나 | 10.39 ms (휘두르기) |
| 변주까지 포함한 실제 `warm()` | **81.7 ms · 63벌 · 388 KB** |
| 실행 중 메모리 (PCM) | 336 KB |
| **웹 빌드에 추가되는 재료 용량** | **956 KB** (wav 65개) |

**1판은 다운로드 0 KB 였다. 이번엔 956 KB 를 낸다.**
`09-art-sound.md` §9.3.3 기준 `index.pck` 가 1.13 MB 이므로 대략 두 배가 된다.
**용량 예산(§9.1)이 아직 미정이라, 줄여야 하면 재질당 개수를 깎는 것이 첫 수단이다** —
무게와 변주는 어차피 엔진이 만들므로 재료 개수와 표현력이 비례하지 않는다.

### 29.7.8 22050 으로 줄여도 되나 — **재질마다 다르다. 실측했다**

원본 281개의 11 kHz 위 에너지 비율:

| 재질 | 11 kHz 위 에너지 | 판정 |
| --- | --- | --- |
| 나무 · 살 · 돌 | 0.03~0.04 % | 22050 으로 충분 |
| 발소리 | 0.12 % | 충분 |
| 금속 | 0.77 % | 충분 |
| 바람 | 1.07 % | 충분 |
| **천** | **9.65 %** | **44100 필요** |

**천만 다르다.** 천 소리의 정체가 바로 그 고역이라 거기만 두 배를 준다.
`AudioStreamWAV` 가 스트림마다 `mix_rate` 를 들고 있어서 섞어 써도 공짜다.

### 29.7.9 원본을 다시 굽는 이유 셋 — 전부 실측

| 문제 | 실측 | 안 고치면 |

### 29.7.10 아직 못 잰 것 — 정직하게

| 못 잰 것 | 왜 |
| --- | --- |
| **브라우저 실제 동시 발음** | 헤드리스는 Dummy 오디오 드라이버라 믹싱을 안 한다 |

받은 파일 안의 문서를 직접 읽었다. OGA 넷은 작품 페이지의 `License(s)` 필드를 직접 조회했다.

원본 총 500여 개 중 **65개만 골랐다.** 무게와 변주는 엔진이 만들므로
**재료 개수와 표현력이 비례하지 않는다** (§29.4).

## 29.10 합성은 지우지 않았다 — 대비책으로 남긴다

`SfxSynth` 와 그 테스트는 그대로 있다. `SfxRender.mode` 를 `SYNTH` 로 두면 전부 합성으로 난다.

**왜 남기나.**

1. **재료에 구멍이 생기면 그때 메운다.** 지금은 0 이지만 사건이 늘면 생길 수 있다
2. **다운로드 0 KB 라는 선택지를 버리지 않는다.** 용량 예산(§9.1)이 아직 미정이다
3. **프로토 화면의 원천 토글이 1판과 2판을 나란히 듣게 해 준다** — 판정의 근거가 된다

**합성의 한계는 1판에서 확인된 그대로다.** 자갈 밟는 소리 · 천 스치는 소리 ·
진짜 검의 배음 두께는 안 나오고, 양식화된 아케이드 쪽 소리가 나온다.
**사용자가 그걸 듣고 물렸다.** 그 판단이 이 문서에 기록되어 있다 (§29.12.1).

### 이번 판의 한계도 정직하게

## 29.12 판을 두 번 뒤집으며 배운 것

> 레인은 언제든 끊긴다. **같은 함정을 다시 밟지 않도록 남긴다.**

### 29.12.1 1판 — 합성, 사용자 불합격

1판은 엔진 합성이었다. 문서에 **"합성은 사실적이지 않다. 양식화된 아케이드 쪽 소리가 난다.
프로토타입에서는 그게 오히려 낫다"** 고 정직하게 적어 두었다.

**앞부분은 맞았고 뒷부분은 틀렸다.** 사용자 판정은 한 줄이었다 —
*"효과음 완전이상하다 안되겠다. 그냥 저작권 없는 무료 효과음 다 긁어모아서 해야할듯"*

**교훈: "프로토에는 이 정도면 낫다" 는 것은 만든 쪽의 판단이지 듣는 쪽의 판단이 아니다.**
정직하게 적어 둔 것은 값을 했다 — 무엇이 문제였는지 다시 조사할 필요가 없었다.

**그리고 층을 갈라 둔 것이 값을 했다.** 원천을 통째로 갈아 끼웠는데
사건 50개 · 계약 · 표가 한 줄도 안 바뀌었다 (§29.5).

### 29.12.2 2판에서 새로 밟은 함정 셋

**(1) QOA 임포트 — 조용한 대체가 가장 위험하다**

Godot 4.7 의 wav 기본 임포트가 QOA 라 `AudioStreamWAV.data` 에서 샘플이 안 나왔다.
`SfxRender` 는 그걸 "재료 없음" 으로 보고 **합성으로 조용히 떨어졌다.**
실측 도구는 "사건 50개 전부 파일에서 옴 / 구멍 0" 이라고 **정상 보고했다.**
변주 RMS 가 소수점 넷째 자리까지 똑같은 것을 보고서야 알았다.

**교훈: 대비책은 조용하면 안 된다.** 지금은 `test_sfx_library.gd` 가
파일을 실제로 열어 보고, 임포트 설정 자체도 검사한다.

**(2) UI 를 무게로 리샘플 — 물리와 기호를 안 가름**

확인음(원본 791 Hz)에 무게 2.0 을 먹여 1.74배 늘였더니 **255 Hz** 가 되어
전투음(374 Hz)보다 **낮게** 깔렸다. UI 를 위로 올리려고 고역 통과를 넣는 동안
정작 리샘플이 아래로 끌어내리고 있었다.

**교훈: 축을 전부에 똑같이 먹이면 안 된다.** 타격은 물리라 늘이는 것이 맞고,
UI 는 기호라 설계된 높이를 지켜야 한다 (`SfxVoice.scales_with_size`).

**(3) 선행 무음 — 파일은 시간축도 들고 온다**

천 소리는 앞에 평균 64.7 ms(최대 76 ms)의 무음이 붙어 있었다.
그대로 쓰면 타격 순간보다 65 ms 늦게 난다 — 체인 간격 350 ms 의 19 % 다.

**교훈: 합성은 항상 t=0 에서 시작하지만 녹음은 아니다.**

**(4) 출처 표기 — 부분 문자열로 맞추면 틀린 사람 이름이 남는다**

굽는 도구가 원본 경로에서 출처를 알아내는데, `"rpg" in "oga_80rpg"` 가 참이라
**OpenGameArt 파일 셋이 Kenney RPG Audio 로 표기됐다.** 라이선스는 둘 다 CC0 라
법적으로는 문제가 없지만, **제출물에서 만든 사람 이름이 틀리는 것은 그 자체가 사고다.**

지금은 압축을 푼 **최상위 폴더 이름과 정확히 일치**할 때만 인정한다.

**교훈: 증빙은 자동 생성해도 되지만, 자동 생성기가 틀리면 조용히 틀린다.**
`CREDITS.md` 의 출처 분포를 눈으로 세어 보고서야 알았다.

### 29.12.3 1판에서 실측으로 고쳤던 것 셋 — 지금도 유효하다

| 고친 것 | 계기 | 지금 |
| --- | --- | --- |
| **44100 → 22050** | 굽는 시간 535 ms → 113 ms | 유지. 다만 **천만 44100** 으로 예외 (§29.7.8) |
| **`PEAK_TARGET` 0.80 → 0.50** | 두 소리만 겹쳐도 피크 1.30 | 유지. 파일에도 같은 정규화를 건다 |
| **캐시 열쇠에 `gain`·벌 수 누락** | "대기"와 "재개"가 같은 열쇠로 묶여 **한쪽이 다른 쪽 음량으로 재생됨** | 유지 + **원천(파일/합성)까지 열쇠에 추가** |

**캐시 열쇠 버그는 원천이 바뀌어도 같은 종류가 난다.**
파형을 결정하는 값이 열쇠에 빠지면 조용히 남의 소리가 나온다.
