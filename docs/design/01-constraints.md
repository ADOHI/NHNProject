## 1.2 제약이 기획에 주는 영향

웹 빌드라는 조건은 단순한 배포 방식이 아니라 **기획 제약**이다.

- **초기 로딩이 곧 이탈 지점이다.** 브라우저에서 여는 순간 다운로드가 시작된다.
  에셋 용량이 커질수록 플레이 전에 이탈한다. 고해상도 텍스처와 긴 BGM 은 비용이 크다.
- **소리는 첫 입력 전까지 재생되지 않는다.** 브라우저 정책이다.
  타이틀 화면에서 바로 BGM 이 나오는 연출은 성립하지 않는다.
- **단일 스레드다.** 무거운 연산을 별도 스레드로 넘길 수 없다.
  한 프레임에서 오래 걸리는 처리는 화면 전체를 멈춘다.
- **입력 환경을 가정할 수 없다.** 채점자가 어떤 기기·화면으로 열지 모른다.
  키보드 전용 조작은 위험하고, UI 는 화면 비율 변화를 견뎌야 한다.

## 1.3 일정 · 인력 제약

> **상태: 확정.** (2026-08-07 기준)

| 항목 | 값 |
| --- | --- |
| 마감까지 남은 시간 | **90시간** (실시간 기준, 2026-08-11 경) |
| 인원 | **1인** (기획·개발·아트·사운드 전부) |
| 하루 투입 가능 시간 | 미정 |

### 이 조건이 기획에 주는 영향

90시간은 **달력 시간**이지 작업 시간이 아니다. 수면·식사·이동을 빼면
실제 작업 가능 시간은 **40~55시간** 수준이고, 그중 상당 부분이
빌드·배포·문서 작업으로 나간다. 순수 게임 제작 시간은 **30~40시간**으로 잡아야 한다.

1인이라는 조건은 **병렬 작업이 불가능**하다는 뜻이다.
아트를 만드는 동안 코드는 멈춘다. 따라서:

- **에셋 제작량이 곧 개발 시간**이다. 아트 스타일 선택이 일정에 직접 붙는다.
  → [`09-art-sound.md`](09-art-sound.md)
- **콘텐츠 양보다 시스템 하나의 완성도**로 승부하는 편이 성립 확률이 높다.
  스테이지 10개를 얕게 만드는 것보다, 잘 굴러가는 루프 하나를 만드는 쪽이다.
- **처음 보는 기술을 쓰지 않는다.** 학습 시간을 낼 여유가 없다.
- **마감 전 마지막 구간은 통합·검증에 비운다.** 웹 빌드는 로컬에서 되던 것이
  브라우저에서 안 되는 경우가 있고, 그 디버깅에 시간이 걸린다.
  → [`10-content-scope.md`](10-content-scope.md) §10.4
