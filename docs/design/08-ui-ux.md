## 8.1 화면 흐름

```
타이틀
  ↓ (클릭 — 브라우저 오디오 정책상 첫 입력 필요, §8.6)
주둔지  ←──────────────────────┐
  ├→ 강화                       │
  ├→ 장비 세팅                  │
  └→ 던전 선택                  │
        ↓ 입장                  │
     던전 (인게임)              │
        · 계획 페이즈 ← 렉카 피드 갱신
        · 행동 페이즈 → 사건 발생
        ↓ 탈출 / 사망           │
     결과 정산 ─────────────────┘
```

## 8.2 인게임 화면 구성

인게임은 한 화면에서 **판 · 피드 · 상태**를 동시에 본다.
플레이어의 매 턴 판단이 이 셋의 대조에서 나오기 때문에, 탭으로 나누면 안 된다.

```
┌──────────────────────────────────┬───────────────────┐
│                                  │  📰 렉카 피드      │
│      방 그래프 (위험도 숫자)      │                   │
│         전체가 한 화면에          │  이번 턴 기사     │
│                                  │  지난 턴 기사     │
│                                  │  ...              │
├──────────────────────────────────┤  (스크롤)         │
│  소지품 · 체력 · 턴 · 페이즈      │                   │
└──────────────────────────────────┴───────────────────┘
```

**세로 화면(모바일)에서는 판 ↕ 피드로 쌓는다.** 비율 제약 대응.

## 8.3 렉카 피드 (핵심)

### 8.3.1 무엇인가

던전에서 벌어지는 일을 **악동 스트리머가 SNS 렉카 채널로 중계**한다.
플레이어는 계획 페이즈에 이 기사를 읽고 다른 방의 상황을 짐작한다.

> 🔴 **속보** ㅋㅋㅋ 서쪽 회랑에서 방금 뭔 일 났는데요<br>
> "칼날의 요한" 그 형 있잖아요. 보스방 앞까지 갔다가 그냥 튐 ㅋㅋ<br>
> 아니 거기까지 가서 왜 도네 개많이 박힘

### 8.3.2 왜 이 장치가 결정적인가

이것 하나가 네 가지를 동시에 해결한다.

| 해결하는 문제 | 방식 |
| --- | --- |
| **시야 문제** | 안 보이는 방의 사건을 전달한다. 시야 시스템·미니맵·정찰 UI 가 전부 불필요 |
| **NPC 존재감** | NPC 가 이름으로 불리고 행적이 서술된다. 화면에 안 나와도 **살아 있는 경쟁자**가 된다 |
| **톤** | 던전 침입이 목숨 건 사투이면서 동시에 **남들에겐 구경거리**라는 세계관이 공짜로 선다 |
| **개발 비용** | **텍스트다.** 애니메이션·이펙트·스프라이트 없이 사건을 전달한다. 웹 용량도 거의 0 |

**1인 90시간에서 "사건을 전달하는 가장 싼 수단"이 동시에 가장 개성 있는 수단이다.**
이건 타협이 아니라 이 프로젝트가 낼 수 있는 최선의 수다.

### 8.3.3 신뢰도 — 과장한다 (확정)

렉카는 조회수를 먹고 산다. **기사는 부풀린다. 단, 축소하지 않는다.**

| 요소 | 신뢰도 |
| --- | --- |
| 사건의 존재 · 장소 · 종류 | **사실** |
| 규모 · 수치 | **과장** (부풀리기만) |
| 스트리머의 논평 | 주관 |

플레이어는 기사에서 **하한선을 읽는다** — "3명 죽었대"는 못 믿어도
"최소 1명은 죽었다"는 믿는다. 규칙적으로 과장하기 때문에 역보정이 학습 가능하고,
그게 숙련이 된다.

상세 — [`13-information-design.md`](13-information-design.md) §13.3

### 8.3.4 플레이어도 중계된다 (확정)

**플레이어의 행동도 기사에 실린다.** 정보는 양방향이다.

- NPC 들이 플레이어의 위치·전리품을 알게 된다 → 플레이어가 **표적**이 된다
- 많이 챙길수록 유명해지고 위험해진다 → **주목도** 시스템
- 자기 기사를 읽는 것 = 자신이 얼마나 노출됐는지 확인하는 수단

**익스트랙션의 "많이 챙길수록 위험해진다"를 수치 페널티가 아니라 서사로 구현한다.**

상세 — [`13-information-design.md`](13-information-design.md) §13.4

### 8.3.4.1 아웃게임에서도 쓴다

렉카 피드는 던전 전용이 아니다. **주둔지 화면의 뉴스 피드**로 그대로 재사용된다.
세계가 판마다 갱신되므로([`15-world.md`](15-world.md)) 매번 새 소식이 있다.

> 📰 이번 주 대박 났다는 그 스쿼드 ㅋㅋ 결국 전멸했답니다<br>
> 📰 "칼날의 요한" 드디어 은퇴각? 요즘 조용하네요

**생성기 하나를 두 화면에서 쓴다.** 인게임에서는 정보원이고,
아웃게임에서는 **누구를 영입할지 · 누구를 조심할지**의 근거가 된다.

### 8.3.5 기사 생성 — 구현 방향

**미정.** 매 행동 페이즈 후 사건 로그에서 1~3건을 골라 기사화한다.

| 방식 | 비용 | 결과 |
| --- | --- | --- |
| 템플릿 + 슬롯 치환 | 낮음 | 반복이 금방 눈에 띈다 |
| 템플릿 다층화 (문체·감정·군더더기 분리 조합) | 중간 | 같은 사건도 매번 다르게 읽힌다 |
| 사전 생성 텍스트 대량 준비 | 중간 | 용량 부담, 상황 대응 불가 |

**반복되는 문장이 보이는 순간 이 장치는 죽는다.** 여기에 시간을 얼마나 쓸지가
[`10-content-scope.md`](10-content-scope.md) 의 핵심 판단이다.

### 8.3.6 기사에 담기는 정보

| 요소 | 예 | 필수 |
| --- | --- | --- |
| 누가 | NPC 이름 | 필수 — 이름이 있어야 경쟁자가 된다 |
| 어디서 | 방 이름 | 필수 — 판 위 위치와 연결되어야 정보다 |
| 무엇을 | 전투 · 획득 · 사망 · 탈출 · 조우 | 필수 |
| 얼마나 | 수량·가치 (과장 대상) | §8.3.3 |
| 스트리머의 논평 | 조롱 · 편들기 · 부추김 | 톤 |

**"어디서"가 빠지면 기사는 분위기용 장식이 된다.** 반드시 판 위의 방과 연결한다.

## 8.4 화면 목록

| 화면 | 역할 | 필수 요소 | 우선순위 |
| --- | --- | --- | --- |
| 타이틀 | 진입 · 첫 입력 확보 | 시작, 조작 안내 | 필수 |
| 주둔지 | 아웃게임 허브 | 보유 자원, 메뉴 진입 | 필수 |
| 강화 | 영구 성장 | 목록, 비용, 효과 | 필수 |
| 장비 세팅 | 잠입 준비 | 소지품 선택, **잃는다는 경고** | 필수 |
| 던전 선택 | 난이도·보상 선택 | 던전별 성격 비교 | 필수 |
| 던전 (인게임) | 본편 | §8.2 | 필수 |
| 조우 · 협상 | NPC 상호작용 | 선택지, 상대 단서 | 필수 |
| 결과 정산 | 손익 확인 | 가져온 것 / 잃은 것 | 필수 |

**8개다.** 화면 수는 그대로 개발 시간이다.
주둔지·강화·장비·던전선택을 **한 화면 안의 탭**으로 묶으면 4개가 1개가 된다.
→ [`10-content-scope.md`](10-content-scope.md)

## 8.5 인게임 HUD

**"더 벌까 나갈까"를 매 턴 묻는 게임이라면, 그 판단에 필요한 숫자가 항상 화면에 있어야 한다.**

| 정보 | 항상 표시 | 이유 |
| --- | --- | --- |
| 현재 페이즈 (계획/행동) | **예** | 페이즈 구분이 게임의 정체성 |
| 인접 방 위험도 합 | **예** | 판 위에 직접 표기 |
| 소지품 가치 | **예** | "지금 나갈까" 판단의 근거 |
| 체력 | **예** | |
| 탈출 지점 방향 | **예** | 탈출이 판단이려면 필요 |
| 렉카 피드 | **예** | §8.2 |
| 현재 턴 수 | 미정 | 턴 압박이 있다면 필수 → [`06`](06-progression.md) §6.3 |

## 8.6 피드백

동시 해결([`03`](03-core-loop.md) §3.6)에서는 한 번에 여러 일이 벌어진다.
**플레이어가 무슨 일이 일어났는지 놓치면 다음 계획을 세울 수 없다.**

- 행동 페이즈 결과를 **순차적으로** 보여 준다 (내 행동 → 조우 → 타 방 사건)
- 그 뒤 렉카 피드가 갱신되며 **못 본 것을 메운다** — 피드가 곧 리플레이다

## 8.7 첫 화면 규칙

브라우저 정책상 첫 입력 전에는 소리가 나지 않는다.
타이틀 화면이 **클릭을 유도**하는 구조여야 한다.
