# 18. 시각 정체성 — 지하 실황 호외

> **상태: 방향 확정(코드까지) / 선택 열림.**
> 방향 후보 넷을 각각 실제 화면으로 만들어 두고, 그중 하나(B)를 끝까지 구현했다.
> **최종 채택은 아직 하지 않았다.** 나머지 셋은 `src/ui/style/sketch/` 에 실행 가능한
> 스케치로 남아 있고, 캡처로 나란히 비교할 수 있다.
>
> 이 문서는 [`09-art-sound.md`](09-art-sound.md) §9.2·§9.4 의 "미정"을 채운다.

---

## 18.1 앞선 판본이 왜 실패했는가

첫 시도는 **어두운 배경 + 얇은 인광 청록 선 + 작은 글씨**였다.
기능은 맞았지만 평가는 한 줄이었다 — *"여전히 AI 틱하다."*

원인은 셋이고, 셋 다 같은 데서 나온다.

| 실패 | 무엇을 했나 |
| --- | --- |
| **절제를 미덕으로 삼았다** | "반듯하고 조용하다", "상시 움직임은 둘뿐" — 정보 설계로는 옳지만 화려함의 반대다 |
| **가장 흔한 기본값에 안착했다** | 어두운 바탕에 형광 선은 "이 게임"이 아니라 "SF 게임 일반"의 모습이다 |
| **세계관에서 심심한 쪽을 골랐다** | 시설의 관제 화면(태생적으로 절제됨)만 보고, **악동의 방송 채널**(태생적으로 시끄러움)을 안 썼다 |

그리고 두 번째 시도에서 한 번 더 지적당했다. 판본은 인쇄물로 바뀌었지만
**셰이더는 여전히 필터였고, 모션은 여전히 기본값이었다.**

| 두 번째 실패 | 무엇을 했나 |
| --- | --- |
| **기성품 셰이더 묶음** | 주사선 · 격자 · 비네트 · 그레인 · 훑는 조명. 아무리 겹쳐도 필터는 필터다 |
| **기본값 모션** | 페이드 · 슬라이드 · 이즈인아웃 · scale pop. 애니메이션이 아니라 엔진 기본값이다 |
| **웹 버튼 반응** | 올리면 밝아지고 누르면 작아진다 |

§18.5 와 §18.6 은 그 셋을 각각 어떻게 뒤집었는지를 적는다.

## 18.2 컨셉 — 플레이어는 **이번 턴의 호외 한 장**을 본다

### 18.2.1 근거는 화자에 있다

화자는 시설 연출부 소속이면서 그 방송을 자기 채널로 유출해 먹고사는 렉카다
([`19`](19-rekka-voice.md) §19.2). 그렇다면 **유출한 자가 내놓는 물건은 무엇인가.**

방송 장비가 아니다. 장비는 시설의 것이다.
유출한 자가 내놓는 것은 **간행물**이다 — 급하게 찍어 뿌리는 호외.

이 한 줄에서 화면의 모든 것이 따라 나온다.

| 화면의 요소 | 지면에서의 정체 |
| --- | --- |
| 방 = 망점으로 찍힌 칸 | 그 방 카메라의 **사진**. 원판이 나쁘면 뭉개 찍힌다 |
| 통로 = 괘선과 점선 | 이어진 굵은 괘선만 지금 지나갈 수 있는 길이다 |
| 위험도 숫자 = 먹판 | 시설이 잰 값. **사실**이므로 정합이 맞는다 |
| 송출 표시 = 별색 붉은 깃발 | 렉카가 붙인 것. 칸의 틀을 뚫고 나간다 |
| 배경 = 종이 | 판은 그림이 아니라 **책상 위의 큰 신문지**다 |
| 개발 패널 = 교정쇄 | **아직 인쇄기에 안 걸린 지면.** 별색이 하나도 없다 |

### 18.2.2 왜 이 방향이 이 게임에서만 말이 되는가

**인쇄에는 신뢰도를 말하는 장치가 이미 두 개 있다.**

| 인쇄의 사실 | 이 게임의 규칙 |
| --- | --- |
| **정합(register)** — 두 번째 판은 어긋난다 | 어긋난 크기 = 부풀린 크기 ([`13`](13-information-design.md) §13.3) |
| **선수(screen)** — 원판이 없으면 굵게 찍는다 | 망점의 굵기 = 모르는 정도 ([`13`](13-information-design.md) §13.6) |

색이 장식이 아니라 **"이 정보를 믿어도 되는가"의 표시**라는 원칙은 앞선 판본에서
그대로 가져왔다. 표현만 갈아엎었다.

| 레이어 | 앞선 판본 | 지금 |
| --- | --- | --- |
| **계측** (정확하지만 모호) | 인광 청록 | **먹판.** 정합이 맞고 괘선에 갇힌다 |
| **송출** (구체적이지만 못 믿음) | 방송 주홍 | **별색 붉은판.** 늦게, 어긋나서, 찢긴 조각으로 |

그리고 **폰트가 SongMyung 하나뿐이라는 제약이 여기서 무기가 된다.**
SongMyung 은 명조이고, 명조는 **신문 제목의 얼굴**이다.
게임 UI 에서 명조는 드물다. 제약이 정체성이 됐다.

### 18.2.3 잉크는 둘뿐이다

세 번째 색을 쓰지 않는다. 판이 둘뿐이어야 "먹=사실 / 별색=과장"이 흔들리지 않는다.
못 오르는 길은 **사실**이므로 먹으로 찍고, 색 대신 **사선 겹쳐찍기**라는 무늬로 가른다
(색약자에게도 남는다).

---

## 18.3 서명 — **모든 것은 두 번 찍힌다**

> **먹판이 먼저 사실을 찍고, 별색판이 늦게, 어긋나서 찍힌다.
> 어긋난 크기가 곧 부풀린 크기다. 어긋남이 0 이면 그것은 사실이다.**

이 한 몸짓이 화면 전체에서 반복된다.

| 어디에 | 어떻게 |
| --- | --- |
| 제호 · 판 번호 | `PressPage._strike()` — 별색이 어긋난 자리에 먼저, 먹이 제자리에 |
| 인접 위험도 합 | `PlateLabel` (`slip_amount`) |
| 방 칸의 숫자 | `RoomNode._ghost_home()` |
| 별색 조각의 괘선 | `PressPanel._draw_story_rules()` |
| 판 맞춤표 | `PressPage._draw_register()` — 별색 표적만 떠다닌다 |
| 인쇄판 전체 | `ink_plate.gdshader` 의 `slip` — 화면의 모든 별색 망점이 같은 방향으로 어긋난다 |
| 값이 바뀌는 순간 | `UiMotion.misprint()` — 3.4배로 튀어 나갔다 되튄다 |

`UiTokens.slip(amount)` 하나가 화면의 모든 어긋남을 만든다.
방향이 요소마다 다르면 한 대의 인쇄기로 찍은 지면이 아니다 (테스트로 고정).

## 18.4 형태 — 굴리지도 자르지도 않는다

**둥근 모서리도 잘린 모서리도 없다.** 인쇄물의 형태는 굴리는 것이 아니라
**괘선에 갇히거나 찢겨 나오는 것**이다.

| 역할 | 형태 | 왜 |
| --- | --- | --- |
| 먹판 패널 | 위 굵은 괘선 + 아래 가는 괘선 + 귀퉁이 판 맞춤표. **옅은 망을 깐다** | 지면 위에 더 흰 종이를 얹어 봐야 인쇄판을 통과하면 바탕과 같아진다 |
| 별색 조각 | **찢긴 가장자리** + 1.8도 기울기 | 사실은 축에 반듯하고 이야기는 기운다 |
| 교정쇄 | 왼쪽 굵은 괘선 + 여백 눈금. 별색 없음 | 아직 안 나간 지면이다 |
| 방 칸 | **윤곽을 셰이더가 만든다** (§18.5.2) | 모르는 칸은 도형이 다 생기지 않았다 |
| 송출 깃발 | 오른쪽이 파인 조각. 칸의 틀을 **뚫고 나간다** | 축에 정렬된 사각형만 있으면 화면이 표가 된다 |
| 버튼 | 아래 굵은 괘선 + 왼쪽 가는 괘선의 'L'. 누르면 통째로 먹이 먹는다 | 활자 한 조각이다 |

사방 테두리를 두르지 않는다. 대신 **판 맞춤표**를 귀퉁이에 둔다 —
얇은 테두리를 두른 사각형은 어느 게임에나 있지만, 맞춤표는
**이 화면이 인쇄 중인 판이라는 사실 자체**다.

형태는 전부 `src/ui/style/shape.gd` 의 순수 함수가 만든다 (씬 없이 테스트된다).

## 18.5 셰이더 — **효과가 아니라 형태를 만든다**

**에셋 파일을 하나도 늘리지 않는다.** 그림·아이콘·패턴은 전부 코드가 만든다.

그리고 여기서 **하지 않는 것을 먼저 적는다.** 주사선, 발광, 격자, 색수차, 비네트,
필름 그레인, 홀로그램 깜빡임, 화면을 훑는 조명 — 전부 뺐다.
이 장르에서 수천 번 쓰인 묶음이고, 화면에 얇게 덧씌우는 필터는 아무리 겹쳐도 필터다.

### 18.5.1 인쇄판 — 이 화면의 렌더링 모델

`src/ui/style/press_plate.gd` + `shaders/ink_plate.gdshader`

**이 화면은 그려지는 것이 아니라 찍힌다.**
화면 맨 위에 늘 깔려 있는 판 한 장이 그 아래 그려진 모든 것을 `hint_screen_texture` 로
되읽어서 **두 장의 인쇄판으로 분해하고 다시 구성한다.** 꺼지지 않는다.

| 하는 일 | 형태를 어떻게 만드나 |
| --- | --- |
| **접힘** | 접힌 자리를 지나는 그림을 실제로 **밀어 버린다** (UV 변위). 선을 긋는 것이 아니다 |
| **찢김** | 새 판을 찍을 때 지면이 갈라져 두 쪽이 서로 다른 쪽으로 벌어졌다 맞물린다 |
| **망점** | 계조를 점 크기로 뭉갠다. **부드러운 그라디언트가 화면에 존재할 수 없다** |
| **충격** | 누른 자리에서 고리가 퍼지며 종이를 밀고 지나간다 |

> **중간톤만 점으로 뭉갠다.** 실제 신문이 그렇다 — 활자와 괘선은 통짜(선화)로 앉히고
> 사진만 선수를 걸어 찍는다. 전부 점으로 바꾸면 11px 본문이 통째로 뭉개진다(한 번 그랬다).
> 덕분에 위계가 하나 더 생긴다: **사진은 점으로 이루어져 있고 글자와 괘선은 통짜다.**

`gl_compatibility` 에서 화면 되읽기는 `hint_screen_texture` 로 동작한다(엔진이
백버퍼 복사를 넣어 준다). 캡처로 실제 확인했다.

### 18.5.2 방 칸 — 윤곽이 망점에서 나온다

`shaders/halftone_cell.gdshader`

사각형을 그려 놓고 그 안에 무늬를 넣는 것이 아니라, **사각형의 윤곽이 망점에서 나온다.**

| 상태 | 화면 |
| --- | --- |
| 지금 있는 방 | 가는 선수로 곱게 찍힌다. 가장자리가 또렷하다 |
| 갈 수 있는 방 | 중간 선수 |
| 못 오르는 방 | 중간 선수 + 먹 사선 겹쳐찍기 |
| 먼 방 | 굵은 선수. **가장자리가 점으로 부서져 있다** — 도형이 다 인쇄되지 못했다 |

그래서 "모른다"는 색이 흐린 것도 글자가 없는 것도 아니고
**형태가 아직 다 생기지 않은 것**이 된다.
개발 모드에서 실제 값이 드러나면 **선수가 실제로 고와진다.**

### 18.5.3 종이

`shaders/press_sheet.gdshader` — 잉크가 고르게 먹지 않는 것 하나뿐이다.
질감은 인쇄판이 만들므로 여기서 더 얹을 이유가 없다.
판의 이동·배율을 따라가므로 끌면 얼룩과 접힌 자리가 함께 흐른다 — 판은 장소다.

## 18.6 모션 — **인쇄기는 멈추지 않는다**

앞선 판본의 규칙은 "움직이는 것은 변한 것이다"였다. 정보 설계로는 옳았지만 화면이 죽었다.

**여기서 쓰지 않는 것을 먼저 적는다.** 페이드, 슬라이드, 이즈인아웃,
크기를 살짝 키웠다 줄이기 — 어느 UI 에나 있는 기본값이라 이 게임의 것이 아니다.
무엇이 일어났는지는 **형태가 바뀌어서** 보여야 한다.

### 18.6.1 두 박자

| 이름 | 무엇 | 곡선 |
| --- | --- | --- |
| `UiMotion.slam()` | **활자가 조판대에 떨어진다.** 비뚤게 들어와 튕기며 자리를 잡는다 | ELASTIC |
| `UiMotion.misprint()` | **별색판이 크게 어긋났다 되튄다** | ELASTIC |
| `UiMotion.chase()` | 별색판이 늦게 따라붙어 지나쳤다 앉는다 | BACK |
| `RoomNode._resolve_plate()` | **면이 반응한다** — 굵은 점에서 제 선수로 자라난다 | EXPO |

각도를 쓰는 이유: 이 화면에서 배율은 카메라의 것이라 손댈 수 없고,
무엇보다 납활자를 손으로 집어 판에 앉히면 반듯하게 들어가지 않는다.

### 18.6.2 전환이 곧 인쇄 공정이다

한 턴이 넘어가면 `PressPlate.print_edition()` 이 돈다.

1. 지면 전체가 **굵은 점 덩어리**가 된다 (`swell` 1 → 0)
2. 앞머리가 **왼쪽부터** 지나가며 자리를 잡는다 (`swell_lead`)
3. 방 칸들은 자기 자리가 화면에서 얼마나 왼쪽인가에 따라 **차례로** 다시 찍힌다
   (`DungeonBoard.reprint()` 의 `TIME_STAGGER`)
4. 판을 새로 짠 것이면 종이를 한 번 **찢고** 시작한다

한꺼번에 나타나면 덩어리가 되고, **시차가 있어야 박자가 된다.**
곡선은 EASE_IN_OUT 이다 — EASE_OUT + EXPO 를 쓰면 첫 5% 만에 다 풀려서
굵은 점이 눈에 보이지 않는다(한 번 그랬다).

**화면이 뜨는 것 자체가 첫 판을 찍는 것이다.** 켜자마자 인쇄기가 한 번 지나간다.

### 18.6.3 늘 도는 것

전부 정보를 지고 있다.

| 무엇 | 무슨 뜻 |
| --- | --- |
| 별색 맞춤표가 미세하게 떠다닌다 | 이 지면은 지금 인쇄되고 있다 |
| 모르는 칸의 선수가 아주 느리게 흔들린다 | 인쇄기가 그 칸에서 자리를 못 잡고 있다 |
| 송출 중인 칸의 별색 띠가 맥동한다 | 여기가 지금 그림으로 나가고 있다 |

### 18.6.4 변화 표시

값이 바뀌면 별색판이 3.4배로 튀어 나갔다 되튀고, 그 옆에 `+2` / `-2` 가 떠올랐다 사라진다.
플레이어에게 이전 값을 외우게 하면 노동이 된다
([`13`](13-information-design.md) §13.7). **화면이 대신 기억한다.**

## 18.7 반응 — 요소마다 다르게 저항한다

올리면 밝아지는 것은 웹 버튼이지 이 게임이 아니다.
**갈 수 있는 칸과 못 가는 칸은 다르게 저항해야 한다.** (`RoomNode._on_hover()`)

| 상태 | 커서를 올리면 |
| --- | --- |
| 갈 수 있는 칸 | **원판이 또렷해진다.** 들여다보면 선수가 고와지고 괘선이 굵어진다 |
| 못 오르는 칸 | **더 뭉개진다.** 몸을 틀어 밀어내고(`_shrug()`), 겹쳐찍기가 두꺼워진다 |
| 먼 칸 | 아무 반응도 없다. 내 것이 아니다 |
| 지금 있는 칸 | 별색이 조금 더 또렷해진다 |

버튼은 누르면 통째로 먹이 먹고, **누른 자리에서 파문이 퍼져 지면을 밀고 지나간다**
(`PressPlate.strike_at()`). 조작이 지면에 자국을 남긴다.

## 18.8 정보 위계

### 18.8.1 글자 — 명조 하나로 버티려면 크게 벌린다

| 크기 | 이름 | 무엇 |
| --- | --- | --- |
| **108** | `Banner` | **인접 위험도 합.** 1면 톱 |
| 54 | `Deck` | 제호 |
| 34 | `Head` / `SpotHead` | 기사 제목 |
| 22 | `Sub` | 지금 어디인가 |
| 16 | 본문 | |
| 13 | `Caption` | 사진 설명 |
| 11 | `Micro` | 안 읽어도 되는 말 |

가장 큰 것과 가장 작은 것의 비가 **9.8:1** 이다. 앞선 판본은 3.5:1 이었다.

먹 세 단계를 전부 어둡게 잡았다. 화면의 모든 것이 인쇄판을 통과하는데
**옅은 먹은 그 판에서 점으로 부서져 읽히지 않는다.**

### 18.8.2 배율에 따른 밀도

| 배율 | 보이는 것 |
| --- | --- |
| 낮음 (< 62%) | 숫자만. 숫자가 칸 가운데로 온다 |
| 중간 | 이름 + 숫자 |
| 높음 (> 92%) | 이름 + 숫자 + 고도 |

숫자가 앉을 자리는 **하얗게 뚫는다**(knockout). 사진 위에 숫자를 그냥 얹으면
선수가 굵은 칸에서 묻히는데, **원판이 나쁜 것과 값이 없는 것은 다른 뜻**이라
그 둘이 구분되지 않으면 안 된다. 신문도 사진 위 숫자는 흰 박스로 뚫어 앉힌다.

### 18.8.3 통로가 상태를 함께 말한다

**지금 실제로 지나갈 수 있는 길만 굵은 괘선 다발로 찍힌다.** 나머지는 점선이다.
그래서 판 위에서 **내 선택지가 저절로 도드라진다.**
고도로 막힌 길은 사라지지 않고 굵은 점선으로 남는다
([`07`](07-level-design.md) §7.2.7).

## 18.9 배격 목록

| 하지 않는다 | 왜 |
| --- | --- |
| 어두운 배경 + 얇은 형광 선 + 작은 글씨 | 앞선 판본이 실패한 자리다 |
| 둥근 모서리 · 잘린 모서리 | 인쇄물의 형태가 아니다 |
| 주사선 · 격자 · 비네트 · 그레인 · 훑는 조명 | 이 장르의 기성품. 겹쳐 봐야 필터다 |
| 페이드 · 슬라이드 · scale pop | 애니메이션이 아니라 엔진 기본값이다 |
| 올리면 밝아지는 반응 | 웹 버튼이다 |
| 근거 없는 그라디언트 | 인쇄판을 통과하면 존재할 수도 없다 |
| 세 번째 잉크 | 판이 둘이어야 신뢰도 표시가 흔들리지 않는다 |
| 이모지 · 특수기호 | 폰트에 없다. 웹에서 두부가 된다 (§18.11.4) |
| 먹으로 적은 논평 / 별색으로 적은 숫자 | 신뢰도 표시가 무너진다 |

├── ui_motion.gd            # 두 박자의 프리셋

├── style_showcase.tscn/gd  # 견본쇄
├── shaders/
│   ├── press.gdshaderinc       # 해시 · 얼룩 · 망점 · 맥동 (공용)

## 18.11 제약과 비용

### 18.11.1 렌더러

`gl_compatibility` 고정([`01`](01-constraints.md))이라 컴퓨트 셰이더가 없다.
전부 `canvas_item` 셰이더이고 **미분(`fwidth`)을 쓰지 않는다.**
화면 되읽기(`hint_screen_texture`)만 텍스처를 쓰고, 그것도 엔진이 넣는 백버퍼 복사다.
캡처로 실제 동작을 확인했다.

### 18.11.2 실측 (1920×1080, 400프레임)

| 항목 | 값 |
| --- | --- |
| 평균 | **3.15 ms (317 fps)** |
| 최악 | **3.70 ms (270 fps)** |

60fps 예산 16.7ms 대비 **4.5배 여유.** 인쇄판(화면 전체 1패스 + 되읽기)을
넣고도 이 정도다.

```bash
godot --path . --resolution 1920x1080 -s res://tools/capture_scene.gd -- perf.png perf
```

### 18.11.3 모션은 정지 화면으로 증명되지 않는다

`tools/capture_scene.gd` 에 **연속 캡처**를 넣었다.

```bash
godot --path . -s res://tools/capture_scene.gd -- in.png   film boot   # 등장
godot --path . -s res://tools/capture_scene.gd -- cut.png  film <방id> # 전환
godot --path . -s res://tools/capture_scene.gd -- acc.png  film debug  # 강조
```

프레임이 아니라 **시간**으로 띄운다. 창이 60Hz 인지 165Hz 인지에 따라
같은 프레임 수가 전혀 다른 길이가 되기 때문이다.

### 18.11.4 폰트

SongMyung 하나뿐이고 한자·특수기호 글리프가 없다.
`號外`·`見本` 은 두부가 되어 **`호외`·`견본`** 으로 바꿨고,
가운뎃점 `·` 는 `•` 로 바꿨다. 커밋 전 `tools/check_glyphs.gd` 로 확인한다.

## 18.12 아직 화면이 없는 것들

| 화면 | 판 | 형태 |
| --- | --- | --- |
| 렉카 피드 ([`08`](08-ui-ux.md) §8.3) | **별색** | 찢긴 조각. 기사 본문은 먹, 논평은 별색 |
| 조우 · 협상 | 먹 + 별색 | 상대 정보는 먹, 렉카의 부추김은 별색 |
| 결과 정산 | 먹 | 가져온 것/잃은 것은 사실이다 |
| 주둔지 · 강화 · 장비 | 먹 | 방송 밖이다 |
| 아웃게임 뉴스 피드 | **별색** | 인게임 조각을 재사용한다 |
| 타이틀 | 별색 | 첫 화면부터 "이건 유출본이다"를 말해야 한다 |

**주목도([`13`](13-information-design.md) §13.4)는 별색판의 값이다.**
화제성은 렉카가 매기는 것이지 시설이 재는 것이 아니다.

## 18.13 방향 넷 — 고르지 않고 남겨 둔다

머릿속으로 비교하면 첫 아이디어가 이긴다. 그래서 넷을 각각 **실제로 렌더**했다.
넷은 같은 방·같은 숫자·같은 문장을 쓴다 (`sketch/sketch_stage.gd`).

| 방향 | 무엇 | 서명 | 띄우는 법 |
| --- | --- | --- | --- |
| **A** 지하 실황 | 예능 자막의 방송 그래픽 패키지 | 12도 기울기 | `-- a.png sketch_a` |
| **B** 호외 | **인쇄된 판** (구현 완료) | **오정합** | 메인 씬 |
| **C** 썸네일 | 화면에 직접 그은 빨간 낙서 | 손으로 그은 획 | `-- c.png sketch_c` |
| **D** 검열 | 지면을 먹으로 덮는다 (**일부러 과한 쪽**) | 먹칠 막대 | `-- d.png sketch_d` |

D 를 만든 이유 — **쓸 만한 것 셋을 늘어놓고 고르면 결국 가장 안전한 것이 뽑힌다.**
끝이 어디인지 봐야 가운데가 어디인지 알 수 있다.
D 는 실제로 쓰기 어렵다(판의 절반을 덮으면 정보 설계와 정면으로 부딪힌다).
그 사실이 화면에 같이 적혀 있다.

**B 를 추천한 근거**

1. 인쇄가 **신뢰도 장치를 두 개 이미 갖고 있다** (§18.2.2). 색이 장식이 아니게 된다
2. 명조 하나뿐이라는 제약이 **무기**가 된다
3. 셋 중 유일하게 **밝은 바탕**이다. 앞선 판본의 반대편이다
4. A·C 는 여전히 어두운 화면 위의 그래픽이라, 실패한 판본과 거리가 가깝다
