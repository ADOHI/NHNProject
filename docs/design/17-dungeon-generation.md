# 17. 던전 절차 생성

> **상태: 설계 확정 / 수치 미정.**
> 던전은 **모두 절차적으로 생성**한다. 수제작 던전은 두지 않는다.
> 공간 규칙(고도 · 방 종류)은 [`07-level-design.md`](07-level-design.md) §7.2.6~7.2.9 참고.

---

## 17.1 생성기의 진짜 요구사항

**"재미있는 판"이 아니라 "추리가 성립하는 판"을 만드는 것이다.**

이 게임에서 던전은 이동 경로가 아니라 추리판이다([`07`](07-level-design.md) §7.2).
따라서 생성기의 난이도는 만드는 쪽이 아니라 **못 쓸 판을 걸러내는 쪽**에 있다.

| 실패한 판 | 왜 못 쓰나 |
| --- | --- |
| 탈출구에 도달할 수 없다 | 시작하자마자 진 판이다 |
| 숫자만으로 정답이 나온다 | 추리가 아니라 계산이 된다 |
| 단서가 전혀 없다 | 추리가 아니라 도박이 된다 |
| 입구 옆이 즉사급 | 판단할 기회 자체가 없다 |

---

## 17.2 연결 차수가 곧 정보량

인접 위험도 합은 **내가 선 방의 연결 차수**에 따라 정보량이 달라진다.
지뢰찾기에서 인접 칸 수가 정보량을 정하는 것과 같다.

| 내 방의 차수 | 보이는 것 |
| --- | --- |
| 1 (막다른 방) | 합 = **그 한 방의 정확한 위험도.** 모호함 없음 |
| 2 | 두 방이 뭉친다 |
| 4+ | 거의 읽을 수 없다 |

**연결을 촘촘하게 짜면 어려워지고 성기게 짜면 쉬워진다.**
몬스터 수치를 건드리지 않고 난이도를 조절하는 손잡이다.

### 막다른 방은 정찰 지점이다

차수 1인 방에 들어가면 앞방의 위험도를 **정확히** 알 수 있다.
대신 퇴로가 하나뿐이다.

> **정보가 정확한 대신 도망칠 길이 없다.**

위험 대 정보의 트레이드오프가 그래프 모양에서 저절로 나온다.
따라서 생성기는 막다른 방을 **없애지 않는다.** 비율만 관리한다.

## 17.3 생성 절차

```
1. 고도 층(layer) 구성      — 층 수와 층별 방 개수를 정한다
2. 방 배치                  — 층마다 방을 놓는다
3. 척추 연결                — 입구에서 최심부까지 이어지는 경로를 먼저 보장한다
4. 곁가지 연결              — 차수 분포 목표에 맞춰 간선을 추가한다
5. 필요 민첩 계산           — 방마다 bottleneck 값을 구한다 (§17.4)
6. 방 종류 배치             — 필요 민첩 등급에 따라 귀중품·보스·탈출구를 놓는다
7. 존재 배치                — 몬스터·NPC 를 놓는다
8. 검증                     — §17.5 를 통과하지 못하면 폐기하고 다시 만든다
```

**3번(척추)을 먼저 보장하는 것이 핵심이다.**
무작위로 잇고 나서 도달 가능한지 검사하면 대부분 실패해 재시도가 폭증한다.
먼저 성립하는 뼈대를 놓고 살을 붙이면 검증은 거의 통과한다.

---

## 17.4 필요 민첩 (bottleneck)

```
필요 민첩(방) = min over 경로 ( max over 간선 ( 상승폭 ) )
```

내려가는 간선의 상승폭은 0 이다([`07`](07-level-design.md) §7.2.6).
Dijkstra 와 같은 구조에 "합" 대신 "최댓값"을 쓰면 그대로 구해진다.

이 값의 쓰임:

| 용도 | 내용 |
| --- | --- |
| 방 등급 | 배치의 기준 (§17.3-6) |
| 탈출구 보장 | 필요 민첩 0 인 탈출구가 최소 하나 |
| 고가치 배치 | 가치와 필요 민첩을 비례시킨다 |
| (추후) UI | "저기 가려면 민첩이 얼마나 더 필요한가" |

## 17.5 검증 규칙

생성 결과가 아래를 **전부** 만족해야 채택한다.

| # | 규칙 | 이유 |
| --- | --- | --- |
| V1 | 모든 방이 입구에서 도달 가능 (민첩 무한 가정) | 고립된 방은 존재하지 않는 것과 같다 |
| V2 | **필요 민첩 0 인 탈출구가 최소 하나** | 없으면 시작하자마자 진 판이다 |
| V3 | 고가치 방의 필요 민첩 > 기본 탈출구의 필요 민첩 | 보상은 대가를 요구해야 한다 |
| V4 | 입구의 인접 위험도가 상한 이하 | 즉사 배치 금지 ([`07`](07-level-design.md) §7.6) |
| V5 | 막다른 방 비율이 목표 범위 안 | 너무 많으면 정보가 다 새고, 없으면 다 뭉친다 |
| V6 | 같은 위험도 합을 만드는 서로 다른 구성이 판에 존재 | **모호함이 실제로 발생하는지** 확인한다 |

**V6 이 이 게임 고유의 검증이다.**
다른 게임의 생성기에는 없는 조건이고, 이게 없으면
"위험도 6 = 늘 보스 하나" 같은 판이 나와 추리가 규칙 암기로 바뀐다.

### 재시도

검증 실패 시 **판을 통째로 버리고 다시 만든다.** 부분 수정하지 않는다.
부분 수정은 다른 규칙을 깨뜨리고, 그 연쇄를 추적하는 비용이 재생성보다 크다.

재시도 상한을 두고, 상한을 넘기면 **파라미터를 완화**한 뒤 다시 시도한다.
무한 루프로 프레임이 멈추면 웹 단일 스레드에서 화면이 굳는다
([`01`](01-constraints.md) §1.2).

## 17.6 자동 레이아웃

| 축 | 값 |
| --- | --- |
| Y | **고도.** 높을수록 위 |
| X | 같은 고도 안에서 분산. 연결된 방과 가깝게 |

판 전체가 한 화면에 들어가야 하므로([`07`](07-level-design.md) §7.8)
생성된 좌표를 화면 크기에 맞춰 정규화한다.

**선이 방을 관통하지 않는 것**이 최소 품질 기준이다.
완벽한 교차 제거는 하지 않는다 — 비용에 비해 얻는 게 적다.

---

## 17.7 재현성

생성은 **시드**를 받는다. 같은 시드는 같은 판을 만든다.

| 이유 | 내용 |
| --- | --- |
| 테스트 | 판을 고정해야 생성 규칙을 검증할 수 있다 |
| 버그 재현 | "이상한 판이 나왔다"를 다시 볼 수 있다 |
| 밸런싱 | 같은 판에서 수치만 바꿔 비교한다 |

Godot 의 `RandomNumberGenerator` 를 인스턴스로 들고 다닌다.
전역 난수(`randi()`)를 쓰면 시드 고정이 깨진다.
