## 9.1.1 이 게임은 아트 부담이 낮다

기획 구조상 **그림으로 전달해야 하는 것이 거의 없다.**

| 요소 | 표현 수단 | 아트 필요량 |
| --- | --- | --- |
| 던전 공간 | 방 노드 + 연결선 + 숫자 ([`07`](07-level-design.md) §7.1) | 도형·UI |
| 다른 방의 사건 | **렉카 기사 텍스트** ([`08`](08-ui-ux.md) §8.3) | **없음** |
| NPC 탐험가 | 이름 + 초상 1장 | 캐릭터당 1장 |
| 전투 | 결과 표시 (연출 아님) | 거의 없음 |
| 몬스터 | 아이콘 · 숫자 | 아이콘 |

**애니메이션·스프라이트 시트·타일맵이 전부 불필요하다.**
1인 90시간([`01-constraints.md`](01-constraints.md) §1.3)에서 아트가 코드를 멈추지 않는다는 뜻이고,
웹 초기 로딩 문제도 거의 사라진다.

**대신 UI·타이포그래피가 곧 아트다.** 플레이어가 보는 시간의 대부분이
숫자판과 텍스트 피드이므로, 여기서 인상이 결정된다.

## 9.2 비주얼 스타일

**미정.** 방향 후보:

- **SNS / 방송 UI 를 그대로 차용** — 렉카 피드가 실제 SNS 타임라인처럼 보인다.
  톤([`02`](02-overview.md) §2.5)과 직결되고, 도형·폰트만으로 완성된다. 아트 비용 최소.
- 보드게임 판 — 방 노드를 물리적 말·카드처럼.
- 지도 · 문서 — 탐험가의 수기 지도처럼.

## 9.3 폰트 · 가독성

이 게임에서 **폰트가 스프라이트보다 중요하다.**

| 항목 | 값 |
| --- | --- |
| 한글 폰트 | **임시 조치 중 — §9.3.1** |
| 위험도 숫자 | 미정 — 판 위에서 즉시 읽혀야 한다 |
| 기사 본문 | 미정 — 긴 텍스트를 읽는 화면이므로 가독성 우선 |

**한글 폰트 파일이 이 게임 최대의 용량 항목이 될 수 있다.** §9.1 예산에 반영한다.

### 9.3.1 현재 상태 — 웹 빌드에서 깨진다 ⚠

Godot 기본 폰트에는 **한글 글리프가 없다.** 그대로 두면 UI 가 전부 두부(□)로 나온다.

현재는 `assets/fonts/ui_font.tres` 가 `SystemFont` 으로 시스템에 설치된 한글 폰트를
빌려 쓰고 있다. 데스크톱에서는 정상이지만 **웹에서는 빌려 올 시스템 폰트가 없다.**

| 환경 | 현재 |
| --- | --- |
| 데스크톱 (개발) | ✅ 정상 |
| **웹 (제출물)** | **❌ 두부로 나올 가능성 높음** |

**제출 전에 반드시 해결해야 한다.** 선택지:

| 안 | 내용 | 비용 |
| --- | --- | --- |
| 재배포 가능 폰트 임베드 | Noto Sans KR 등(SIL OFL)을 받아 서브셋해 넣는다 | 다운로드 필요 · 용량 수백 KB~ |
| 사용 글자만 서브셋 | UI 문구가 확정된 뒤 필요한 글자만 추출 | 가장 가볍지만 **렉카 기사 텍스트가 유동적이라 위험** |
| UI 문구를 영문/숫자로 | 폰트 문제 자체가 사라진다 | 게임의 톤을 버린다 |

**두 번째 안은 렉카 기사와 충돌한다.** 기사 문장은 마감 직전까지 늘어나므로
(docs/design/16-build-order.md §16.6) 서브셋을 미리 고정하면 나중에 넣은 글자가 깨진다.
