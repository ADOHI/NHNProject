# UI 키트 — 등고선 장(場)

이 문서는 **UI 원자 단위**(버튼 · 팝업)의 조형을 정한다.
구현은 `src/ui/kit/`, 확인용 화면은 `src/ui/kit/kit_showcase.tscn` 이다.

기존 `src/ui/style/`(호외 신문 컨셉)과 **아무 관계가 없다.** 참고하지도 이어 붙이지도 않았다.
게임 화면이 그쪽을 아직 쓰고 있으므로 둘은 당분간 공존한다.

> **작성 시점의 상태: 미완.** 버튼은 3차 심사까지 왔고 팝업은 아직 심사 전이다.
> 아직 정하지 못한 것은 §7 에 따로 적었다.

---

## 1. 무엇을 만드는가 — 그리고 무엇을 만들지 않는가

앞선 두 번의 시도가 같은 이유로 실패했다. **아직 없는 게임 화면에 UI 를 맞춰 재단했다.**
던전 판을 성립시키느라 위험도·신뢰도·고도 같은 정보 설계가 조형을 잡아먹었다.

그래서 이번에는 화면을 만들지 않는다. 만드는 것은 둘뿐이다.

| 만드는 것 | 상태 |
| --- | --- |
| 버튼 | 평상 · 호버 · 눌림 · 포커스 · 비활성 |
| 팝업 | 떠 있는 상태 |

방도 위험도도 던전도 나오지 않는다. **이 둘만으로 스타일이 판정된다**는 것이 이번 전제다.

### 컨셉은 서사가 아니라 조형이다

"관제 화면", "호외 신문" 같은 이야기를 짓지 않는다. 그것이 앞선 실패의 원인이었다.
여기서 정하는 것은 **그림체 · 규격 · 간격 · 애니메이션 · 셰이더** 다섯 가지뿐이다.

### 애니메이션의 뜻도 좁혔다

**리빌·하이드 연출이 아니다.** 등장·퇴장은 한 번 보고 끝난다.
여기서 애니메이션은 둘을 뜻한다.

- **idle** — 아무도 건드리지 않아도 화면이 죽어 있지 않은 것
- **포커스** — 포커스가 갔을 때 그 요소의 **성격**이 드러나는 것

## 2. 잡은 컨셉 — 한 문장

> **UI 는 화면 위에 놓인 물건이 아니라, 화면 전체에 깔린 고도장(場)을 밀어 올린 자리다.
> 테두리는 그은 것이 아니라 비탈에 등고선이 몰려서 생긴 것이다.**

따라오는 규칙은 전부 이 한 문장에서 나온다.

- 화면에 **칠해진 면이 하나도 없다.** 등고선만 있다. 명암은 선의 밀도로만 만든다.
- 버튼은 자기 몸을 그리지 않는다. **자기 사각형과 고도만 장에 신고한다.**
- 그래서 요소끼리의 관계(붙었는가 떨어졌는가, 무엇이 무엇 위인가)가
  규칙이 아니라 **지형의 계산 결과**로 나온다.

### 셰이더가 하나뿐인 이유

요소마다 재료를 따로 두면 두 버튼의 비탈이 만나는 일이 일어나지 않는다.
흉내는 낼 수 있어도 계산되지는 않는다. 그래서 화면 전체를 덮는 `KitField` 하나가
모든 요소의 사각형·고도를 uniform 배열로 받아 **한 번에** 그린다.

## 3. 조형 다섯 가지

### 3.1 그림체 — 등고선뿐

| 항목 | 값 |
| --- | --- |
| 선 굵기 | 반폭 0.62px (해석적 안티에일리어싱) |
| 굵기 위계 | **다섯 줄마다 하나를 2.6배로** 굵게 (지형도의 계곡선 index contour) |
| 면 | 없음. 단 하나도 없음 |
| 색 | 꺼진 곳 청회색 → 지반 회갈색 → 솟은 곳 뼈색. **기복의 함수** |
| 강세색 | 주홍 하나. **포커스 물결의 마루에만** 얹힌다 |

굵기 위계는 3차 심사에서 추가했다. 굵기가 하나뿐이면 화면 전체가 같은 무게로 깔려
경사를 읽을 수 없고, 그때 등고선은 지형이 아니라 **벽지 무늬**가 된다.

색은 절대 고도가 아니라 **요소가 만든 기복**의 함수다. 바탕에는 전체 경사가 있어서
절대 고도로 색을 정하면 화면 아래쪽 바탕이 통째로 밝아진다.

### 3.2 규격 — 고도가 크기를 정한다

크기 단계는 셋이고, **임의로 고른 셋이 아니라 고도 1·2·3 단에서 유도된 셋**이다.
높은 것이 큰 것이다.

| 급 | 고도 | 높이 | 글자 |
| --- | --- | --- | --- |
| 보조 | 1 단 | 40px | 15 |
| 주 행동 | 2 단 | 48px | 17 |
| 결단 | 3 단 | 56px | 19 |
| 팝업 | 6 단 | — | 24 (제목) |

`높이 = 32 + 8 × 고도`. 폭은 글자가 정하되 **8px 의 정수배로 올림**한다.
자동 크기에 맡기면 화면에 이미 깔린 등고선 간격과 아무 관계 없는 치수가 생긴다.
규격이 보이려면 셀 수 있어야 한다.

길이의 원자는 **8px**(`UNIT`)이다. 바탕 등고선 평균 간격의 대략 절반으로 잡았다.

### 3.3 간격 — 비탈이 겹치는가로 드러난다

비탈 폭이 30px 이므로 두 비탈이 만나는 거리는 60px 다. 간격의 세 급은 그 수에서 나온다.

| 급 | 값 | 지형에서 보이는 것 |
| --- | --- | --- |
| 붙음 | 16px (2U) | 비탈이 깊이 겹쳐 **하나의 능선**이 된다. 이음매는 등고선 한 칸도 안 되게 얕다 |
| 묶임 | 32px (4U) | 비탈이 절반쯤 겹쳐 사이에 **안장(saddle)** 이 생긴다 |
| 분리 | 64px (8U) | 비탈이 거의 닿지 않아 **각자 닫힌 고리**를 갖는다 |

여백 수치는 눈에 보이지 않지만 지형의 위상(연결성)은 보인다.
**"두 행동이 한 몸이되 같은 것은 아니다"** 를 8px/16px 같은 숫자는 절대 말하지 못한다.

### 3.4 애니메이션 — idle 과 포커스

**idle (아무도 안 건드릴 때)**

- 바탕의 결이 늘 흐른다. 초당 20px 안팎
- 핵심은 **곱한 항**이다. 더한 항만 쓰면 결은 모양을 유지한 채 통째로 미끄러지고,
  그건 등고선 타일을 `translateY` 로 무한 스크롤하는 랜딩페이지와 구별되지 않는다.
  두 물결을 곱하면 마디마다 진폭이 달라져 줄이 **좁아졌다 넓어지고 갈라졌다 붙는다**
- 요소마다 고도가 **숨**을 쉰다. 진폭은 등고선 한 칸보다 크게(0.30단) 잡았다.
  그보다 작으면 줄이 한 개도 넘나들지 않아 화면상 아무 일도 일어나지 않는다
- 위상은 요소마다 어긋나 있다. 그래서 이웃한 둘의 바깥 고리가 **붙었다 떨어진다.**
  이 위상 변화가 이 키트의 idle 이다

**포커스**

- 봉우리에서 물결이 **끊임없이** 바깥으로 밀려 나간다. 시작도 끝도 없다
- 물결에 **회전**을 함께 건다. 반지름만의 함수로 두면 마루가 요소를 두른 닫힌 고리가 되고,
  그건 어느 프레임에서 잘라도 Tailwind `ring-2 ring-offset-2` 다.
  세 갈래 마루가 돌면서 동시에 퍼지므로 고리가 닫히지 않는다
- 강세색은 그 **마루에만** 얹혀 함께 흘러간다

**상태가 붙고 떨어지는 시간** — 붙는 것이 떨어지는 것보다 빠르다.

| | 붙음 | 떨어짐 |
| --- | --- | --- |
| 호버 | 0.10s | 0.22s |
| 눌림 | 0.045s | 0.16s |
| 포커스 | 0.18s | 0.18s |

### 3.5 셰이더 — `kit_terrain.gdshader` 하나

`gl_compatibility`(WebGL2) 이므로 컴퓨트 셰이더가 없다. 전부 `canvas_item` 프래그먼트다.

지켜야 하는 **불변식 하나**가 있다.

> **고도장은 어디서도 끊기지 않는다.**
> 등고선은 서로 교차할 수 없고 허공에서 끝날 수 없다.
> 그 둘이 화면에 보이면 그것은 조형의 문제가 아니라 장에 불연속을 넣었다는 증거다.

한동안 요소 안쪽에서 바탕값을 다른 값으로 바꿔치기해 정상을 평평하게 만들었는데,
그 바꿔치기가 정확히 그 사고를 냈다. 지금은 **장을 건드리지 않고 잉크만 지운다**(`clear`).

## 4. 상태 — 다섯 가지를 지형으로 말한다

밝기나 관습적 꼬리표(빨강=위험, 파선=비활성)에 기대지 않는다.

| 상태 | 지형 |
| --- | --- |
| **평상** | 봉우리. 정상은 평평하고 비탈에 고리가 깔린다 |
| **호버** | 봉우리가 솟는다. 정상에서 **새 고리가 밀려 나온다** |
| **눌림** | 0 아래로 꺼져 **구덩이**가 된다. 등고선이 사각형 **안으로** 말려 들어가고, 지도의 **해칭**(안쪽을 향한 짧은 갈고리)이 붙는다. 색은 자동으로 차가워진다 — 낮은 곳은 차갑다는 규칙에서 따라온다 |
| **포커스** | 회전하는 물결이 계속 퍼져 나간다. 강세색이 마루를 탄다 |
| **비활성** | 지면까지 주저앉는다. 고리가 한 줄도 없고 정상을 다듬는 일도 일어나지 않아, **바탕의 결이 글자 위를 휘지 않고 그대로 지나간다.** 흐리게 칠한 버튼이 아니라 **애초에 밀어 올려지지 않은 자리**다 |

### 비탈 곡선이 "테두리를 긋지 않았다"의 전부다

비탈 단면은 `a / (a + d)` 다. `d = 0` 에서 기울기가 최대이므로
고리가 가장자리에 **1.4 / 3.5 / 6.9 / 13.3 / 30px** 로 벌어지며 놓인다. 등간격이 아니다.

지수 감쇠나 거듭제곱 곡선은 `d = 0` 에서 기울기가 0 이어서 맨 안쪽 고리가 일정 간격으로
떨어졌고, 그래서 **획을 여러 겹 두른 것**(Illustrator Offset Path)처럼 보였다. 심사에서 두 번 지적당했다.

### 고도는 더하지 않고 겹친다

더하면 비탈이 겹치는 자리(붙어 있는 두 버튼 사이)가 양쪽 봉우리보다 높아져,
이음매에 있지도 않은 첨탑이 솟는다. 겹치기(max)로 합치므로 **요소는 절대 고도를 신고한다** —
팝업(6단) 위의 버튼(2단)은 8단이다.

낮추는 것(눌림·웅덩이)은 겹치기가 아니라 **따로 모았다가 마지막에 더한다.**
`min` 으로 합치면 구덩이 밖에서도 `min(relief, 0)` 이 걸려 그 요소의 영향권 안에 있는
**다른 모든 봉우리가 지면까지 깎인다.**

## 5. 팝업 — 덮지 않고 눌러 내린다

화면을 어둡게 덮는 반투명 판이 없다. 대신 **주변 지반을 눌러 내린다.**
팝업 둘레의 등고선은 웅덩이 쪽으로 끌려 내려가고 색이 차가워지므로,
뒤가 물러났다는 사실이 밝기가 아니라 **지형**으로 읽힌다.

- 고도 6 단, 비탈 72px, 웅덩이 깊이 1.7 단
- 안에 놓인 버튼은 이 고원 위에서 다시 솟는다. 고도가 겹쳐지는 값이라 층을 따로 관리하지 않는다
- **더 높은 지형에 묻힌 요소는 글자까지 사라진다.** 안 그러면 팝업이 떴을 때
  고원 아래 깔린 버튼의 글자만 허공에 떠 있다 (`KitField.is_buried`)

## 6. 심사 기록

작업을 쪼개고 단계마다 **심사 에이전트 둘**에게 받는다.
하나는 정지 화면의 조형(그림체·규격·간격), 하나는 움직임(idle·포커스·전환)을 본다.
**"괜찮다" 는 실패다.** 통과는 "이건 처음 본다" 일 때만.

### 1차 — 버튼 다섯 상태 · 둘 다 불합격

**정지 심사자**

| 지적 | 고친 것 |
| --- | --- |
| 링 간격이 4~5px 등간격 → Photoshop 획 5겹 / Illustrator Offset Path | 비탈 단면을 `a/(a+d)` 로 바꿔 가장자리에서 몰리고 바깥에서 벌어지게 함 |
| 바깥 링까지 모서리 반지름 유지 — 물리적으로 불가능 | 거리장 자체를 흔들어 두 번째 고리부터 네모를 잊게 함 |
| 배경 등고선이 버튼을 무시하고 평행 통과 — 벽지 위 스티커 | 넓고 낮은 부풀음을 더해 255px 밖까지 휘게 함 |
| 눌림이 빨강 → `btn-danger`. 게다가 봉우리와 그림이 같음 | 구덩이(안쪽으로 말려드는 등고선) + 해칭 + 차가운 색으로 바꿈 |
| 비활성이 파선 → Figma 드롭 타겟 | 파선 삭제. 지면까지 내려앉히고 결이 글자 위를 지나가게 함 |
| 3행 나열 + 회색 소제목 = 디자인 시스템 명세서 | 소제목 삭제, 세 무리를 흩어 놓고 무리 안에서도 높이를 어긋냄 |
| 간격 대조군 없음(붙은 예만 둘) | 붙인 쌍과 뗀 쌍을 함께 둠 |

**모션 심사자**

| 지적 | 고친 것 |
| --- | --- |
| 배경이 무변형 평행이동(−19px/s) = Hero Patterns 무한 스크롤 | 곱한 항 둘을 넣어 결이 **변형**되게 함 |
| 포커스 물결이 0.72초마다 삭제되고 리셋 = `animate-ping` | 감쇠를 길게(95px) 잡아 마루가 항상 서넛 떠 있게 함 |
| 버튼 내부 12프레임 표준편차 **0.00** | 숨 진폭을 0.07 → 0.30 단(등고선 한 칸 이상)으로 올림 |
| 눌림 7프레임 연속 동일 픽셀 | 숨을 눌림 계수 **앞**에 얹어 구덩이 깊이가 함께 오르내리게 함 |
| 도입부 과도기 잔상(f01~f04) | 캡처 준비 프레임 10 → 60 |

### 2차 — 정지 심사자 불합격 (모션 심사자는 앱이 죽어 미실시)

| 지적 | 고친 것 |
| --- | --- |
| 등고선이 **교차**하고 **허공에서 끝난다** | 원인은 정상 평탄화가 장에 넣은 불연속. 장을 건드리지 않고 **잉크만 지우는** 방식으로 교체 |
| 고원 안쪽 균일 2px 테두리 = `border: 2px solid` | 비탈 곡선 교체로 가장자리가 톤 띠가 되게 함 |
| 굵기 위계가 0 → 등간격 평행선은 곧 평지, 평지는 죽어 보인다 | **계곡선** 도입(다섯 줄마다 2.6배 굵게, 사이 줄은 66% 밝기) |
| 화면 왼쪽 절반이 등간격 평행선 | 바탕 흔들림 진폭을 전체 경사에 맞먹게 올려 간격이 40~150px 로 달라지게 함 |
| 겨눔 = Tailwind `ring-offset` 그대로 | 물결에 **회전**을 걸어 마루가 닫힌 고리가 되지 않게 함 |
| 눌림의 균일 축정렬 틱 = DIP IC 칩 다리 | 갈고리를 가늘게(피치 10px, 듀티 0.16) 하고 길이를 자리마다 다르게 함 |
| 잠김의 삼각형+대각선 = 깨진 이미지 글리프 | 고도를 지면까지 낮춰 결이 **휘지 않고** 지나가게 함 |

### 3차 — 진행 중

렌더 완료, 심사 대기. 3차에서 추가로 고친 것:

- 팝업 고원이 제 안쪽을 통째로 지워 **그 위에 얹힌 버튼의 고리까지 사라지던 것** —
  잉크 지우기를 "그 자리에서 가장 높은 요소"에게만 맡기도록 고침
- 팝업 아래 묻힌 버튼의 글자만 떠 있던 것 — `is_buried` 도입

## 7. 아직 정하지 못한 것

- **팝업이 심사를 받지 않았다.** 버튼과 같은 언어로 서 있는지 확인 전이다
- **글자와 지형의 관계.** 지금 글자는 지형 위에 얹혀만 있고 지형에 참여하지 않는다.
  글자 자체가 봉우리의 정점이 되어야 하는가는 미결이다
- **비활성이 지나치게 없다.** "밀어 올려지지 않은 자리"는 규칙상 옳지만
  버튼이 거기 있다는 것조차 보이지 않는다. 절충안이 필요한지 미결
- **평상과 호버의 거리.** 지금은 고리 개수와 밝기 차이뿐이라, 라벨을 가리면
  어느 쪽이 쉬는 상태인지 알기 어렵다는 지적이 두 번 나왔다
- **에셋 없이 폰트가 SongMyung 하나뿐**이라 글자에서 위계를 만들 수단이 크기밖에 없다.
  굵기 대비가 필요하면 폰트 추가를 **제안**해야 한다 (임의 추가 금지)
- **타이틀 화면은 다른 레인**이 맡는다. 그쪽이 "갈라짐"을 서명으로 잡을 가능성이 있고
  언젠가 이 조형과 만나야 하지만, 지금 맞추려 하지 않는다

## 8. 견본 화면을 직접 띄워 보는 법

세 방향은 **같은 배치 위에서 갈아 끼워 봐야** 견줄 수 있다. 그래서 방향 전환은
캡처 도구 안이 아니라 화면 안에 있다.

```
& "C:\Users\adohi\Godot\Godot_v4.7.1-stable_win64_console.exe" --path . res://src/ui/kit/kit_showcase.tscn
```

| 키 | 하는 일 |
| --- | --- |
| `1` `2` `3` | 조형 방향을 등고선 / 파편 / 알갱이로 바꾼다 |
| `P` | 팝업을 열고 닫는다 |
| `Tab` | 포커스를 옮긴다 (포커스 물결을 다른 요소에서 본다) |
| `H` | 왼쪽 아래 조작 안내를 숨긴다 |

왼쪽 위에 **지금 보고 있는 방향의 이름**이, 왼쪽 아래에 조작 안내가 뜬다.
방향 이름을 화면에 박아 두는 이유는 셋의 차이가 미묘해서, 이름이 없으면
몇 번째를 보고 있는지 금방 잃어버리기 때문이다.

`Tab` 을 방향 순환에 쓰지 않았다. `ui_focus_next` 를 빼앗으면 포커스 상태를
눈으로 확인할 수단이 함께 사라진다.

안내 글자는 **지형에 등록하지 않는다.** 장에 신고하면 그것도 봉우리가 되어
견주려는 조형을 밀어 올린다. 어느 방향 위에서도 읽히도록 어두운 외곽선만 준다.
캡처 도구는 `set_guide_visible(false)` 로 이 글자를 끄므로 **심사에 나가는
그림은 예전과 똑같다.**

### 캡처를 한 번에 몰아 뽑는 이유

이 프로젝트는 `gl_compatibility`(OpenGL)를 쓰고 창을 띄울 때마다 GL 컨텍스트를 새로 만든다.
그 반복이 NVIDIA 드라이버를 흔들어 **실제로 프로세스가 통째로 죽은 적이 있다.**
테스트·임포트·린트·글리프 검사는 전부 `--headless` 로 돌리고,
창은 적게 띄우고 많이 뽑는다.
