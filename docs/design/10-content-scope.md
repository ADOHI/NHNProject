# 10. 콘텐츠 범위 · 우선순위

> **상태: 일정 확정 / 내용 미정.**
> 마감 **90시간**, **1인** 개발 ([`01-constraints.md`](01-constraints.md) §1.3).
> 실작업 가능 시간은 40~55시간, 순수 게임 제작은 30~40시간으로 본다.

---

## 10.0 시간 예산

전체를 4구간으로 나눈다. 각 구간 끝에서 **다음으로 넘어갈지 범위를 줄일지** 판단한다.

| 구간 | 실시간 | 작업 | 끝났을 때의 상태 |
| --- | --- | --- | --- |
| A. 기획·기반 | ~0-15h | 기획 확정, 프로젝트 뼈대, 조작 구현 | 캐릭터가 화면에서 의도대로 움직인다 |
| B. 코어 루프 | ~15-45h | 핵심 재미 한 가지를 끝까지 구현 | **재미없어도 게임이 한 판 돌아간다** |
| C. 살 붙이기 | ~45-70h | 콘텐츠, 난이도, 연출, 사운드 | 남에게 보여줄 수 있다 |
| D. 마감 | ~70-90h | 웹 빌드 검증, 버그, 문서, 제출 | 배포본이 브라우저에서 돌아간다 |

**D 구간은 줄이지 않는다.** 웹 빌드는 로컬에서 되던 것이 브라우저에서 안 되는 일이 있고,
그 시점에 고칠 시간이 없으면 제출물이 없는 것과 같다.

**구간 B 가 끝날 때 게임이 안 돌아가면 범위를 줄인다.** C 를 희생하지 A 로 돌아가지 않는다.

## 10.0.1 범위 재평가 (2026-08-07 갱신)

**초기 경고를 하향한다.** 방 노드 + 위험도 숫자 + 렉카 텍스트로 확정되면서
가장 비쌌던 항목들이 대부분 사라졌다.

| 원래 걱정 | 현재 |
| --- | --- |
| 던전 공간 (타일맵·경로탐색·시야) | **해소** — 그래프 + 정수 합산 |
| 전투 연출 · 애니메이션 | **해소** — 결과 표시만 |
| 아트 에셋 물량 | **대폭 감소** — UI·타이포가 곧 아트 ([`09`](09-art-sound.md) §9.1.1) |
| NPC 존재감 | **해소** — 렉카 기사가 대신한다 |

남은 진짜 비용은 셋이다.

| 항목 | 왜 비싼가 |
| --- | --- |
| **NPC 탐험가 AI** | 목표 추구 · 경쟁 · 탈출 판단. 동시 해결과 맞물려 설계 난도 높음 |
| **동시 해결 경계 처리** | [`05`](05-rules.md) §5.6 의 E1~E9. **기획을 안 하면 코딩이 멈춘다** |
| **렉카 기사 생성기** | 반복되는 문장이 보이면 장치 자체가 죽는다 ([`08`](08-ui-ux.md) §8.3.5) |

**이 셋에 시간을 쓰기 위해 나머지를 전부 깎는다.** 구체적으로:

- 주둔지 강화는 **3~4종만**
- 던전은 **2개** (성격이 다른)
- 직업은 **2~3개** (정보 스킬이 서로 다른)
- 아웃게임 화면 4개를 **한 화면 탭**으로 통합 ([`08`](08-ui-ux.md) §8.4)
- 사운드는 최소 (효과음 몇 개)

## 10.0.2 설계 기조 — 잼 규모다

**이 프로젝트는 90시간짜리 게임잼 규모다.** 상용 라이브 게임이 아니다.
설계 판단이 갈릴 때 이 기조가 기준이 된다.

| 기조 | 결과 |
| --- | --- |
| **좌절보다 회전** | 한 판 망해도 바로 다음 판을 시작할 수 있어야 한다 |
| 영구 손실 배제 | 대원 영구 사망 없음 ([`14`](14-squad.md) §14.6) |
| 구제 시스템 불필요 | 잃는 것이 작으면 보험·재기 시스템이 필요 없다 |
| 깊이는 **폭이 아니라 조합**에서 | 콘텐츠 양을 늘리지 않고 편성·정보 조합으로 깊이를 낸다 |

**손실을 키우면 그 손실을 흡수할 시스템이 줄줄이 따라붙는다.**
잼 규모에서는 그 연쇄를 감당할 수 없다. 손실을 작게 두는 것이 곧 범위 관리다.

향후 확장 시 재검토할 항목은 그때 [`11-decisions.md`](11-decisions.md) 에 남긴다.

## 10.0.3 초기 범위 경고 (기록용)

[`02`](02-overview.md)~[`08`](08-ui-ux.md) 에 적힌 컨셉은 **상용 인디게임 규모**다.
90시간 1인으로 전부 만들 수 없다. 이건 기획이 나빠서가 아니라 **양이 많아서**다.

현재 컨셉에 들어 있는 시스템을 세면:

| 시스템 | 대체 가능? |
| --- | --- |
| 아웃게임 허브 · 주둔지 강화 | 축소 가능 (강화 3종만) |
| 장비 세팅 · 인벤토리 | 축소 가능 |
| 던전 선택 (복수 던전) | 축소 가능 (2개) |
| 던전 공간 · 이동 | **방식 선택에 따라 비용 급변** → Q8 |
| 계획/행동 페이즈 턴 시스템 | **핵심. 축소 불가** |
| 몬스터 AI | 단순화 가능 |
| **NPC 탐험가 AI** (목표 추구 · 경쟁 · 탈출) | **가장 비싸다** |
| **성향 · 협상 · 협력 · 배신** | **가장 비싸다** |
| 손실/보존 규칙 | 싸다 (규칙만) |
| UI 화면 7종 | 통합해서 축소 |

**"가장 비싸다"로 표시된 둘이 동시에 이 게임의 차별점이다.**
그래서 선택은 "무엇을 뺄까"가 아니라 **"무엇을 이번 90시간의 주인공으로 삼을까"** 다.

### 권장 — 하나를 주인공으로 삼는다

- **주인공: NPC 탐험가와 성향/협상.** 던전 공간은 노드/방으로 최대한 싸게 (Q8),
  몬스터는 단순 장애물, 주둔지 강화는 3종. → 컨셉의 독창성이 그대로 남는다.
- 반대로 공간·전투를 제대로 만들면 NPC 는 "움직이는 상자"가 되고,
  이 게임은 흔한 턴제 로그라이크와 구분되지 않는다.

이 판단은 Q2·Q8·Q9 의 답에 따라 확정한다.

## 10.1 최소 제출 범위 (MVP)

이것만 있으면 제출 가능한 최소 집합. **여기 있는 항목은 협상 대상이 아니다.**

> **상태는 2026-08-19 에 실제 코드를 재서 갱신했다.** ✅ 선 것 · ◐ 반만 선 것 · ☐ 없는 것.
> 「반만」은 **코어는 있는데 화면이나 호출부가 없다**는 뜻이다 — 그 구분이 남은 일을 정한다.

| # | 항목 | 근거 | 상태 |
| --- | --- | --- | --- |
| M1 | 방 그래프 + 인접 위험도 합 표시 | 게임의 판 자체 | ✅ |
| M2 | 계획 → 행동 페이즈 턴 진행 (동시 해결) | 정체성 | ✅ [33](33-turn-loop.md) |
| M3 | 이동 · 탐색 · 전투 · 탈출 | 최소 행동 집합 | ✅ |
| M4 | NPC 탐험가 (이동 · 획득 · 탈출) | **이게 없으면 다른 게임이다** | ✅ [33](33-turn-loop.md) |
| M5 | 조우 시 전투 / 협상 / 회피 선택 | 핵심 재미 B | ✅ [35](35-encounter.md) |
| M6 | 렉카 피드 (사건 → 기사) | 핵심 재미 B 의 정보원 | ✅ [32](32-rekka-feed.md) |
| M7 | 사망 / 탈출에 따른 손실·획득 정산 | 익스트랙션 성립 조건 | ✅ [36](36-settlement.md) |
| M8 | 아웃게임 1화면 (강화 + 스쿼드 편성 + 장비 + 던전선택) | 이중 루프 성립 조건 | ◐ 아지트·게이트는 서고 **편성·장비가 없다** |
| M9 | 던전 2개 | 선택이 존재해야 함 | ✅ 성격 다섯 (`DungeonCatalog`) |
| M10 | 타이틀 · 결과 화면 | 제출물 최소 요건 | ✅ [36](36-settlement.md) |
| M11 | **스쿼드 편성** (인게임에서는 말 1개) | 조작 단위 ([`14`](14-squad.md)) | ◐ 코어(`Squad`)는 있고 **화면이 없다** |
| M12 | **관계도 + 영입** | 관계도의 보상이 없으면 협상할 이유가 없다 | ✅ [37](37-meta-loop.md) |
| M13 | **세계 갱신** (판마다 NPC 상태 갱신 + 뉴스) | NPC 가 인물이 되는 유일한 장치 ([`15`](15-world.md)) | ✅ [37](37-meta-loop.md) — **저장도 건넌다** |

### 여기서 읽히는 것 — **남은 것은 전부 「잇는 일」이다**

**2026-08-21 갱신.** M13 · M12 가 서면서 남은 것은 **M11 의 전용 편성 화면과 M8 의 장비**뿐이다.
M11 은 아지트 기둥(`BaseMemberPanel`)으로 **이미 돌아간다** — 전용 화면이 없을 뿐이다.

> **그래서 남은 일은 새로 만드는 것이 아니라 잇는 것이다.**
> `NpcWorld.tick()` 은 써 놓고 아무도 안 부르고, `GuildSettlement` 는 정산할 줄 아는데
> 결과를 보여 줄 화면이 없다. **이 상태가 가장 흔한 실패 지점이다** —
> 부품이 다 있어서 다 된 것처럼 보이는데 플레이하면 아무것도 안 이어진다.

**M4·M5·M6·M12 가 이 게임의 정체성이다.** 시간이 부족하면 M8·M9 를 깎지 이 셋은 건드리지 않는다.

### 10.1.1 스쿼드·세계 갱신 추가에 따른 비용 재평가 (2026-08-07)

MVP 가 10 → 13 항목으로 늘었다. 항목별 실제 비용은 아래와 같다.

| 추가 | 비용 | 이유 |
| --- | --- | --- |
| M13 세계 갱신 | **낮음** | NPC 당 정수 몇 개 + 확률 판정. 기사 생성기 재사용 ([`15`](15-world.md) §15.3) |
| M12 관계도 · 영입 | **낮~중** | 친밀도 수치 + 영입 조건 + 화면 하나 |
| M11 스쿼드 편성 | **중** | 인게임에서 말 1개로 운용하면 인게임 복잡도는 거의 안 는다. 비용은 편성 UI 와 스킬 합산 |

**셋 다 인게임 턴 처리를 건드리지 않는다는 점이 핵심이다.**
가장 비싼 부분(동시 해결·조우 절차)에 손대지 않으므로 위험이 낮다.

**단, M11 이 §14.2(스쿼드를 개별 조작)로 뒤집히면 계산이 완전히 달라진다.**
그 경우 계획 페이즈 UI 와 동시 해결 경계 처리가 인원 수만큼 늘어나
90시간 안에서 성립하지 않는다. → [`12-open-questions.md`](12-open-questions.md) Q26

| P1 | 위험도 구성을 밝히는 아이템 · 직업 스킬 ([`07`](07-level-design.md) §7.2.3) | 높음 — 정보 자원화의 핵심 |

| P4 | 플레이어도 기사에 실림 → 표적화 ([`08`](08-ui-ux.md) §8.3.4) | 중간 |
| P5 | 협력 · 배신 | 중간 |
| P6 | 보스 몬스터 | 중간 |
| P7 | 던전 추가 · 배치 무작위화 | 낮음 |
| P8 | 사운드 · BGM | 낮음 |

## 10.3 이번엔 하지 않는 것

명시적으로 버린 것. 적어 두지 않으면 다시 논의하게 된다.

| 버린 것 | 이유 |
| --- | --- |
| 실제 멀티플레이 | 1인 90시간 · 웹 단일 스레드 ([`02`](02-overview.md) §2.6) |
| 타일 그리드 · 경로탐색 · 시야 | 방 노드로 대체 ([`07`](07-level-design.md) §7.1) |
| 전투 애니메이션 · 스프라이트 시트 | 결과 표시로 충분 ([`09`](09-art-sound.md) §9.1.1) |
| 절차적 던전 생성기 | 배치 무작위화로 대체 ([`07`](07-level-design.md) §7.5) |
| 별도 튜토리얼 화면 | 첫 던전 레벨 디자인에 흡수 ([`06`](06-progression.md) §6.4) |
| 스토리 · 컷신 | 톤은 렉카 기사가 전달한다 |

## 10.4 마일스톤 · 구현 순서

**→ [`16-build-order.md`](16-build-order.md) 로 이관.**

MVP 13항목을 의존 관계와 위험도에 따라 재배열한 구현 계획, 구간별 마일스톤,
그리고 **밀렸을 때의 축소 순서**가 그 문서에 있다.

핵심만 옮기면:

| 시점 | 도달 상태 |
| --- | --- |
| +15h | 조작 가능한 말이 판 위에 있다 |
| +25h | 배포본을 브라우저에서 확인 (배포 자체는 push 마다 자동) |
| +45h | 한 판이 시작되고 끝나고 다시 시작된다 |
| +60h | 조우와 렉카 피드 작동 — **여기서 게임이 된다** |
| +70h | MVP 완료, 기능 추가 중단 |
| +85h | 최종 배포본 확인, 문서 갱신 완료 |
