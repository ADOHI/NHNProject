# 던전 생성 레인 인수인계 (2026-08-10)

**맡는 것:** 절차적 던전 생성 — 구조·성격·등급·화면(F1 교정쇄 / F2 두 길) · 계측 도구.

**먼저 읽어라:** `design/17-dungeon-generation.md` §17.39(판정 다섯을 붙인 결과) ->
§17.13.4(어느 표를 어느 자가 내는가) -> `conventions.md` §6.3~6.5(표·도구·중복 판정 규칙).
**§17.33 은 판정 전의 근거 기록이다** — 지금 값이 아니다.

**열린 물음**

- ★ **얕은 갱도만 60% 다** (§17.41). 나머지 넷은 95~100%. 25% 에서 올린 것이지만
  §17.35.3 이 건 「다섯이 다 95%+」에는 못 미친다. **더 밀 손잡이가 없다** —
  곁가지는 안 듣고 단차는 이미 0 이다. **축을 바꾸는 것이 남은 길**
- ★ **민첩 1 스쿼드가 갈 게이트가 목록에 뜨는가** (§17.40.4). `GateBoard.create` 가
  스쿼드를 안 보므로 **넷이 다 막히는 목록이 원리적으로 가능하다. 재 본 적 없다**
- ★ **먼 출구 4/40 · 벌집 5/40 의 V5 하한 미달** (§17.39.4) — 채우려면 P3(보스 차수 4)이
  깨진다. **받아들이는 것으로 적어 뒀다.** 뒤집으려면 P3 을 먼저 손봐야 한다
- 웹 재측정 (§17.21.7) — **사람이 브라우저 창을 띄워 주는 것만 남았다.**
  띄우면 장면이 §17.21.6 의 확인 셋을 스스로 찍는다

**다음 할 일:** §17.40.4 의 「목록이 스쿼드를 안 본다」를 재라 — 그 다음이 §17.19.2 의
「미확인」 두 줄(방 50 개에서 추리가 성립하는가, 낮은 배율에서 방 종류 구분)이다.

**함정 (반드시 읽어라)**

- ★ **웹 벤치는 브라우저 pane 이 화면에 떠 있어야 `rAF` 가 돈다.** 안 뜨면 부팅 로그만
  찍히고 **0 프레임에서 얼어 있는데 성공한 것처럼 보인다** (§17.21.6).
  **이제 장면이 스스로 알려 준다** — 「확인 대기」 다음 줄이 안 뜨면 0 프레임이고,
  결과 줄이 `★ 버려라` 로 시작하면 중간에 숨겨진 것이다. **그 줄들부터 읽어라.**
  그리고 **지금 `build/web/` 에 든 것은 게임이 아니라 벤치다** (`build/` 는 커밋 안 된다 —
  다른 워크트리에서는 §17.21.7 의 1 번부터 해야 한다).
- ★ **성격 축을 건드리면 세 곳이 같이 움직인다** (§17.39): 복잡 경계 · 다른 성격의 식별율 ·
  V5 하한 미달. **흔든 성격의 줄만 보면 나머지 둘을 놓친다.** 붙인 뒤에는
  `survey_size_ladder` · `survey_character_overlap` · `survey_dead_end_floor` 셋을 돌린다.
- **표에 적힌 실측은 코드가 바뀌면 낡는다.** 인용 전에 §17.13.4 의 명령으로 다시 뽑아라 —
  §17.22.3 이 두 번 낡았고 한 번은 낡은 줄도 몰랐다. `gdlint` 는 간헐 크래시하니 재시도.
- **`reach_pct` 를 인용할 때는 `reach_agility` 를 같이 봐라.** 자가 이제 인자를 받으므로
  **같은 이름의 값이 다른 민첩에서 나올 수 있다** (§17.38.3).
- ★ **민첩이 모자라면 `Expedition.enter()` 가 `null` 을 낸다** (§17.40.3). 판정은
  `Gate.can_enter()` 한 곳이고, 화면은 그것을 **미리 불러 버튼을 잠근다** —
  화면을 새로 만들면 그 호출을 빠뜨리지 마라. 안 그러면 **눌리는데 아무 일도 안 일어난다.**
- **입장을 막는 기준은 「보스 방」이지 「모든 방」이 아니다** (§17.40.2). 「다 보려면」
  값(`full_agility`)으로 막으면 민첩 2 가 판의 55% 에서 거절당하고 수직 회랑이 사라진다.
