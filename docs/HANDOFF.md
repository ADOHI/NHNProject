# 던전 생성 레인 인수인계 (2026-08-10)

**맡는 것:** 절차적 던전 생성 — 구조·성격·등급·화면(F1 교정쇄 / F2 두 길) · 계측 도구.

**먼저 읽어라:** `design/17-dungeon-generation.md` §17.33(판정 대기 한 장) ->
§17.13.4(어느 표를 어느 자가 내는가) -> `conventions.md` §6.3~6.5(표·도구·중복 판정 규칙).

**열린 물음**

- ★ Q1~Q5 (§17.33) — **전부 「회신 오면 바로 붙는다」 상태.** Q3 의 고칠 자리는 §17.35.3 에 넷
- ★ 민첩 1 짜리 스쿼드가 성립하는가 (§17.38.3) — 성립하면 판이 3분의 1만 열린다.
  **자는 고쳤으니 코드로는 더 좁힐 것이 없다** — 남은 것은 기획 판단뿐이다
- 웹 재측정 (§17.21.7) — 절차 준비 끝. **사람이 브라우저 창을 띄워 주는 것만 남았다.**
  띄우면 장면이 §17.21.6 의 확인 셋을 스스로 찍는다

**다음 할 일:** §17.19.2 의 「미확인」 두 줄 — 방 50 개에서 추리가 성립하는가(굴려 봐야
안다), 낮은 배율에서 방 종류 구분(UI 킷 규격은 나왔고 아직 적용 안 했다).

**함정 (반드시 읽어라)**

- ★ **웹 벤치는 브라우저 pane 이 화면에 떠 있어야 `rAF` 가 돈다.** 안 뜨면 부팅 로그만
  찍히고 **0 프레임에서 얼어 있는데 성공한 것처럼 보인다** (§17.21.6).
  **이제 장면이 스스로 알려 준다** — 「확인 대기」 다음 줄이 안 뜨면 0 프레임이고,
  결과 줄이 `★ 버려라` 로 시작하면 중간에 숨겨진 것이다. **그 줄들부터 읽어라.**
  그리고 **지금 `build/web/` 에 든 것은 게임이 아니라 벤치다** (`build/` 는 커밋 안 된다 —
  다른 워크트리에서는 §17.21.7 의 1 번부터 해야 한다).
- **표에 적힌 실측은 코드가 바뀌면 낡는다.** 인용 전에 §17.13.4 의 명령으로 다시 뽑아라 —
  §17.22.3 이 두 번 낡았고 한 번은 낡은 줄도 몰랐다. `gdlint` 는 간헐 크래시하니 재시도.
- **`reach_pct` 를 인용할 때는 `reach_agility` 를 같이 봐라.** 자가 이제 인자를 받으므로
  **같은 이름의 값이 다른 민첩에서 나올 수 있다** (§17.38.3).
