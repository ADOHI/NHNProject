# 구조 정리 2026-08-19 — 재고 나서 고친다

> **이 문서는 작업 중에 쓴다.** 끝나고 쓰는 것이 아니다 ([`../CLAUDE.md`](../CLAUDE.md) 개발 원칙 1).
>
> 사용자 지시: *"무엇보다 계획적으로, 코드 모듈화 커플링 분리, 리팩토링도 같이 가면서 진행해"*

---

## 1. 먼저 쟀다 — **추측으로 리팩토링하지 않는다**

레인 열넷이 접히면서 `src/` 가 커졌다(테스트 623 → 1986). **커진 것이 곧 썩은 것은 아니므로**
고칠 곳을 정하기 전에 재기부터 했다.

### 1.1 지켜지고 있는 것 — **손대지 마라**

| 검사 | 결과 |
| --- | --- |
| `src/core/` 가 노드를 아는가 (`extends Node` · `get_node` · `@onready` · `add_child`) | **0건** |
| `src/core/` 가 `src/ui/` · `src/entities/` 를 아는가 | **0건** |
| 화면이 게임 난수를 굴리는가 | 1건 — **개발용 열람기의 「무작위 인물」 버튼**이라 규칙이 아니다 |

> **이 저장소의 핵심 규율은 지켜지고 있다.** `개발 원칙 2`(코어는 노드 비의존 순수 클래스)와
> `conventions.md §3.1`(게임 규칙은 전부 `src/core/`)이 열넷의 레인을 거치고도 안 뚫렸다.
>
> **그러므로 이 정리는 「썩은 것을 도려내는 일」이 아니다.** 아래 셋만 고친다.

### 1.2 진짜 위반 하나 — **출시 코드가 프로토타입에 기댄다**

```gdscript
# src/core/combat/sparring_field.gd:114
var approach_speed: float = ProtoMoveTuning.new().default_of("max_speed")
```

`src/core/` 가 **`src/proto/` 를 부른다.** 방향이 거꾸로다 —
프로토타입은 **버리려고 만든 것**인데 출시되는 전투가 그것에 매달려 있다.

**의도는 좋았다.** 주석이 이렇게 적고 있다.

> **수를 지어내지 않는다.** 값은 이동 레인의 실제 유닛 속도다.
> 계단의 평평한 쪽이라 어느 수를 골라도 결과가 같은데,
> **그러면 고를 이유가 있는 수를 고른다.**

**그 원칙은 옳고 유지한다.** 틀린 것은 **의존의 방향**이다 —
*"고를 이유가 있는 수"* 를 얻으려고 *"버릴 코드"* 에 링크를 걸었다.
값을 **옮겨 오고 출처를 주석으로 남기면** 둘 다 지켜진다.

### 1.3 없는 것 둘 — **`conventions.md` 가 자리를 비워 뒀는데 아직 안 찼다**

`conventions.md §1` 은 `src/systems/` 를 **"씬 전환, 저장, 오디오"** 라고 정의했다.
셋 중 **오디오만** 있다.

| 없는 것 | 지금 어떻게 되고 있나 | 없으면 |
| --- | --- | --- |
| **씬 전환** | `main.tscn` 하나가 전부다. `change_scene` 호출 **0건** | [08](design/08-ui-ux.md) §8.1 의 화면 흐름(타이틀 → 주둔지 → 던전 → 정산)이 **성립하지 않는다** |
| **저장** | `user://` 를 쓰는 게임 코드 **0건** | PC 출시인데 **껐다 켜면 다 사라진다** |

**둘 다 「나중에 필요할 것」이 아니라 「지금 없어서 화면이 안 이어지는 것」이다.**
타이틀도 아지트도 던전도 각자 씬으로 서 있는데 **서로 갈 길이 없다.**

### 1.4 쌓이고 있는 것 — `main.gd`

310줄 · 함수 20개 · 협력자 11개(`DungeonBoard` · `PressPage` · `PressPlate` ·
`RekkaFeedView` · `DebugOverlay` · `RekkaFeed` · `DungeonRun` · `SampleDungeons` ·
`DungeonCatalog` · `DungeonGrade` · `UiTheme`).

**아직 신전(god object)은 아니다.** 다만 [`architecture.md`](architecture.md) 가 스스로 이렇게 적어 뒀다.

> 콘텐츠가 생기면 이 씬은 **진입점 역할만** 남긴다.
> (어떤 씬을 띄울지 결정 → 해당 씬으로 전환) **플레이 로직을 여기에 쌓지 않는다.**

**콘텐츠가 생겼다.** 그런데 진입점이 아니라 **던전 화면 그 자체**가 되어 있다.
씬 전환 체계(§1.3)가 생기면 이 문제가 저절로 풀린다 — **`main` 은 고르는 자가 되고
던전은 제 씬으로 내려간다.** 그래서 §1.3 과 §1.4 는 **같은 작업이다.**

### 1.5 출시 빌드가 프로토타입을 싣는다

`export_filter="all_resources"` 라 `src/proto/` 넷(이동 · 애니 조절판 · 조명 · 효과음 데모)이
**PC 빌드와 웹 빌드에 다 들어간다.** 조명 실험실 하나가 705줄이다.

**빼는 것이 옳다** — 다만 §1.2 를 먼저 끊어야 뺄 수 있다. **지금 빼면 전투가 죽는다.**
그래서 순서가 정해진다.

## 2. 무엇을 하는가 — 셋

**순서가 있다.** ①이 ②의 전제이고, ③은 둘과 안 겹친다.

```
① 결합 끊기 (core → proto)  ──→ ② 프로토를 빌드에서 뺀다
                                         ↕ 안 겹침
③ 씬 흐름 + 저장 (src/systems/) ──→ main.gd 가 진입점으로 돌아간다
```

| # | 작업 | 건드리는 곳 | 왜 지금 |
| --- | --- | --- | --- |
| **①** | `core/combat` → `proto` 의존 끊기 | `src/core/combat/` | 유일한 진짜 방향 위반 |
| **②** | 프로토를 출시 빌드에서 제외 | `export_presets.cfg` | ① 뒤에만 가능 |
| **③** | **씬 흐름 + 저장** (`src/systems/`) | `src/systems/` · `src/main/` | 화면들이 서로 갈 길이 없다 |

### 2.1 안 하는 것 — **크기는 죄가 아니다**

1000줄짜리 파일이 셋 있다(`slash_sheet` · `backpack_board` · `radial_stage`).
**안 쪼갠다.** 셋 다 **한 가지 일**을 하고 있고, 줄 수가 많은 이유는
이 저장소가 **주석에 근거를 적기 때문**이다. 근거를 지우는 리팩토링은 손해다.

> **리팩토링의 기준은 줄 수가 아니라 「이유가 몇 개인가」다.**
> 이유가 하나면 길어도 둔다. 이유가 둘이면 짧아도 가른다.

`src/core/ui/` 의 30 파일도 안 건드린다 — **전부 순수 함수**이고 이미 파일 단위로 갈려 있다.

## 3. 검증 — 리팩토링은 「고쳤는데 안 돌아간다」가 허용되지 않는다

`CLAUDE.md` 개발 원칙 4. **리팩토링 커밋은 반드시 실행 검증을 거친다.**

```bash
godot --headless --path . --import
godot --headless --path . --quit-after 120
python tools/run_gut_retry.py --expect-tests 1986
python tools/run_lint_retry.py
```

**기준선 1986/1986 · 스크립트 174.** 리팩토링이므로 **이 수가 줄지도 늘지도 않는 것이 정상**이다
(②는 빌드 설정이라 테스트가 안 변한다). 늘어나면 새 기능이 섞여 들어간 것이고,
줄어들면 무언가를 잃은 것이다.

구조를 옮기는 변경은 **`.godot/` 캐시를 지우고** 검증한다 — 캐시가 깨진 경로를 가려 준다.

**그리고 PC 빌드를 실제로 뽑아 돌린다.** ②는 빌드 설정을 바꾸므로 테스트로는 안 잡힌다.
