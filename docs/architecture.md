# 구조와 코드 배치 규칙

현재는 부트 씬 하나뿐인 골격 상태다. 콘텐츠가 붙기 시작할 때
어디에 무엇을 두는지를 먼저 못 박아 둔다.

## 폴더

```
NHNProject/
├── project.godot            # 엔진 설정 (렌더러, 해상도, 오토로드)
├── export_presets.cfg       # Web 익스포트 프리셋 (CI 가 이 이름을 참조)
├── icon.svg
├── scenes/                  # .tscn — 화면/오브젝트 단위
│   └── main.tscn            # 부트 씬 (project.godot 의 main_scene)
├── scripts/                 # .gd — 씬 스크립트
│   ├── main.gd
│   └── autoload/            # 자동 로드 싱글톤
│       └── game_config.gd
├── docs/
└── .github/workflows/
    └── deploy-web.yml
```

## 배치 규칙

**한 파일에 다 넣지 않는다.** 씬이 늘어나면 `scenes/<기능>/`,
스크립트는 같은 이름으로 `scripts/<기능>/` 아래에 둔다.
씬과 스크립트가 경로상 대칭이면 "이 씬을 움직이는 코드가 어디 있나"를 찾을 필요가 없다.

- **씬 스크립트** (`scripts/*.gd`) — 그 씬의 노드를 조작하는 코드만.
  다른 씬에서 재사용할 로직이 생기면 씬 스크립트에서 빼낸다.
- **재사용 로직** — `RefCounted` / `Resource` 를 상속한 순수 클래스로 만들고
  `class_name` 을 붙인다. 노드 트리에 의존하지 않으므로 테스트하기도 쉽다.
- **오토로드** (`scripts/autoload/*.gd`) — 게임 전체에서 하나뿐이어야 하고,
  씬이 바뀌어도 살아남아야 하는 것만. 지금은 `GameConfig` 하나다.
  **오토로드는 늘리기 쉽고 줄이기 어렵다.** 추가 전에 재사용 클래스로 될 일인지 먼저 본다.
- **에셋** — 이미지/사운드는 `assets/<종류>/` 를 새로 만들어 둔다.
  씬 폴더 안에 에셋을 섞어 두면 나중에 공유할 때 경로가 꼬인다.

## 현재 있는 것

### `GameConfig` (오토로드)

`project.godot` 에 적힌 이름/버전과 실행 플랫폼(`is_web`)만 노출한다.
게임 상태(점수, 진행도 등)는 여기 넣지 않는다 — 그건 별도 오토로드나
씬 소유 상태로 분리한다.

### `main.tscn` / `main.gd`

지금은 "빌드가 실제로 구동되는지" 확인하는 화면이다.
브라우저에서 제목 + 버전 + 렌더러 정보가 보이면 웹 빌드가 정상이라는 뜻이다.

콘텐츠가 생기면 이 씬은 **진입점 역할만** 남긴다.
(어떤 씬을 띄울지 결정 → 해당 씬으로 전환) 플레이 로직을 여기에 쌓지 않는다.

## 렌더러 선택

`gl_compatibility` (OpenGL ES 3.0 / WebGL 2) 로 고정돼 있다.

Forward+ / Mobile 렌더러는 Vulkan 기반이라 브라우저에서 동작하지 않는다.
웹 제출이 목표인 이상 이 설정은 바꾸지 않는다. 바꾸면 웹 빌드가 검은 화면이 된다.
